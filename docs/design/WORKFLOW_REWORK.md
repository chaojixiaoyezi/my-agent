# 工作流有界重新规划

## 2026-11-19 · M42 条件、投递与私聊面板回执

工作流正则在配置的字符预算内求值。截断时，没有结束或边界断言的匹配可确认成立，其余结果记录为未知。
条件组合按三值规则判断。顺序、DAG 和调试入口都会为未决条件记录错误码与未开始的步骤效果，随后沿现有失败路径收口。
配置项 workflow_condition_max_subject_chars 由部署方在启动时设置，默认 4096 字符。

自定义通知发送端须返回明确的投递或排队状态。无法识别的回执保留未知和原去重键，等待核对后再处置。
飞书私聊面板沿用消息受理的会话锁判断。锁服务不可用时返回可重试错误，操作保留在原卡片。

回归覆盖顺序与 DAG 的未派发步骤、调试分支、三值组合、配置实际生效、通知原认领去重及私聊锁不可用。

当前为本地候选实现，部署版本及集成验收由交付回执记录。

## 2026-11-19 · M57 子工作流义务

正式子工作流把父运行、步骤、尝试和子运行绑定到原步骤回执。恢复沿冻结定义读取原子运行，
子运行未结清时继续等待，结清后沿原输出映射或失败路径推进。旧等待步骤从原子运行引用恢复绑定；
缺失引用或运行记录时记未知，保留原义务以待核对。

父取消沿原子运行的控制账请求取消，整个链条以子运行的耐久终态为准。回归覆盖等待与完成、旧回执、
缺失记录、并发取消和重复控制请求。

## 2026-11-19 · M58 步骤准入与归档责任

DAG 调度先在原运行账本保存当前尝试的 `reserved`。工作线程通过原步骤授权后，
在原运行目录排他创建本次尝试的 `.admitted` 标记并同步目录，再进入外部执行。
同一步的 foreach 批复用这次发表。协调线程用 C11 裁决中断回执。没有标记证明未启动，
已有标记且完成证明缺失时保留未知。排空异常写结构化诊断并保留已发表的同伴结果。

归档和退休共用未结义务口径。终态记录的未结引用和未知副作用继续阻止状态变更。
空间逐页核对规范来源，预算用完后用原幂等键从同版本续点继续，真正提交前在原空间锁内复核来源版本。
回归覆盖准入前后中断、同波次排空错误、终态引用、跨五个预算窗口的 165 条历史与提交窗口的来源变更。

## 显式元数据合同

工作流通过 `descriptor.metadata.workflow_rework_policy` 选择启用。原 ORCH 审核的结构化 `changes_requested` 触发此能力。

```json
{
  "workflow_rework_policy": {
    "replan_step_id": "architecture",
    "max_rounds": 3,
    "max_no_progress_rounds": 2
  }
}
```

原 `WorkflowDefinition` 在构造和恢复时校验策略。

- `replan_step_id` 引用同一冻结定义中的无状态 `llm_skill_analysis` 步骤，显式设置 `analysis_isolation` 为 `stateless_skill`。该步骤须独立于强制审核步骤，且只包含分析能力。
- 两项轮数均为 1～100 的整数，缺省分别为 3 和 2。非法类型、数值及未知字段返回具体校验错误。
- 策略随原运行快照冻结。内置开发阶段草案选择该策略，简单分析模板沿原分析流程执行。

## 原恢复链中的行为

恢复时先核验取消、当前权限及未知副作用。审核反馈为 `changes_requested` 且失败步骤尚未启动副作用时，才进入重新规划。选定分析步骤继续通过原启用状态和 Skill 权限检查。

每次显式恢复最多执行一轮原无状态分析 handler，使用原 core 执行轮、全局模型准入和输入预算。分析上下文来自原运行输入及已成功步骤输出。结果保存于失败步骤的 `escalation_result.rework_state`，随后暂停并要求修订真实候选、取得新审核。

调用分析器前持久化轮数和准确 attempt。原控制操作的幂等重放复用已保存结果。已成功步骤的输出与执行回执继续有效。

无进展计数使用候选 hash、冻结范围及业务上下文的结构化摘要。首次建立基线，随后每次相同摘要累计一轮。达到上限时，返回 `WORKFLOW_REWORK_LIMIT_REACHED` 或 `WORKFLOW_REWORK_NO_PROGRESS`，保持暂停并给出修订候选的下一步动作。

模型失败以 `WORKFLOW_REPLAN_FAILED` 保留脱敏原因、具体错误码和已消耗轮数。规划成功以 `WORKFLOW_REPLAN_READY` 表示计划已保存，业务执行仍须通过原审核与工具授权。

## 原审核与执行证据

`patched_step_output` 用于原修复流程。对待审且尚未执行的步骤使用它时，返回 `WORKFLOW_REVIEW_PATCH_FORBIDDEN`。可信操作的已提交结果继续沿原核验路径恢复。

审核候选和最低要求取自冻结定义。候选、范围或 attempt 变化后须重新审核。工具权限和生产凭证沿原授权入口核验。程序修改、DAG 编排和发布通过各自已有资产与工具入口执行。

独立审核员在派给自己的 `requirement_id` 上调用 `query_provenance`，可省略 `root`。返回的 `workflow_review_material.review_gate` 显示当前受审步骤、最低独立审核数，以及副作用尚未启动的事实。上游步骤的输出只出现在 `upstream_outputs`。审核员据现有材料独立登记通过或返工，执行权由原工具在执行时核验。

长材料归档后，审核员可用原工具读取同一候选的分页。首次查询提供材料摘要和 `read_example`，续页使用 `material_cursor`。读取时每页重新核实原派工、版本及材料摘要。页已读完只表示到达投影末尾，`source_coverage` 保留原始材料的完整程度。

受审工具步骤若引用可变资源，宿主按原只读权限取得内容摘要，并将解析后的参数与摘要绑定进审核版本。审核员可从 `binding.tool_precondition` 核对工具、参数摘要和资源约束。资产投递的 `expected_bundle_sha256` 覆盖本次选择的资产、依赖及附件。发送方在写收发箱前，用本次实际要发送的同一批字节核对摘要。旧票缺少所需摘要或内容已经变化时，原任务需提交新候选重审。

## 查看工作流健康情况

模型可通过 `tool_search` 查找 `business_workflows_health_get`，在原业务工具上调用 `workflows.health.get`。`params.workflow_ref` 是工作流定义标识，`params.limit` 可取 1 至 100。响应中的 `sampled_runs` 是实际读取的运行数。`coverage`、`field_coverage` 和 `source_coverage` 给出统计范围及字段缺失情况。需要导出时，可用已授权的写文件工具保存原始 JSON，保留 `null` 和操作引用。

## 2026-11-19 M48 运行投影消费与引用覆盖

后台资源报告在 WRI 中按状态区间读取未决项，按主键批量核对本轮引用，并在同一库的 `meta.settled_cursor` 续扫已终结样本。首次缺库沿原回填入口恢复，本轮保留未知覆盖。健康采样使用 `runs_workflow_time` 和 `(sort_time, run_id)` 游标，正文仍从原 `run.json` 有界读取。WRI v4 追加迁移到 v5，`runs` 表结构保持原样。 原业务健康查询继续读取单页，支持分页的调用方经采样端口取得续读游标。

计划和业务空间引用按来源与目标保存覆盖代次、位置与有界阻断项。源快照内容变化会重置覆盖，回收仍在原资产锁内重取源快照并判定。现有上游端口仍提供完整的当前配置快照。

`background_report_settled_sample_entries` 在宿主配置加载，默认 256 条。报告接收已加载配置，也支持既有无配置参数入口按宿主默认配置路径取值。

## 2026-11-19 M35 工具操作引用

执行器用同一存储身份写入操作类型与幂等命名空间，并在工具结果中附上版本化操作引用。工作流绑定和恢复依照引用核对存储身份、原操作号和参数摘要。展示回执保留域工具名称，源账本继续校验 owner、run、task、attempt 和幂等键。

未执行的旧定义沿原版本解码表读取退役叶工具，保留冻结定义，并核对当前动作授权。无引用的存量运行继续按原账本身份核对。测试覆盖真实业务空间创建、已提交写入的中断恢复和同键重放、旧定义读取及拒绝未授权动作。
