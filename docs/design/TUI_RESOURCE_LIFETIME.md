# 客户端、状态连接与空闲用户的资源寿命

状态：2026-09-23 独立性能切片已实现，专用测试机本片验收已通过；尚未发布默认运行环境。

## 解决问题

长会话反复重排、净化稳定历史，TUI 随阅读内容增长持续占用 CPU；旧测试客户端长驻
轮询挤占本机 HTTP 入口。用户要求长历史有界、退出立即释放客户端资源，并希望在
1C2G 环境服务 10—100 个 IM 身份，约 50 个同时执行槽，空闲身份不保留完整运行环境。

## 合同

- 身份数量、等待消息、正在执行的任务和 HTTP 在途连接分别计数。128 个 HTTP 槽不是
  128 个用户；普通空闲 IM 身份不创建 TUI，不持有执行槽。
- 继续使用既有持久请求队列、owner/thread 身份和准入计数。满额请求留在原 pending；
  任务结束释放准确的 user/conversation/global 槽，不新建另一套排队状态。
- 50 个执行槽是可配置上限，不是 1C2G 可以同时运行 50 个任意浏览器/脚本的保证。
  验收分别报告空闲、排队、等待模型、实际工具执行的内存和 CPU。
- 客户端退出只关闭本进程的 UI、动画、轮询和连接；持久任务遵守原独立生命周期。
  关闭窗口、EOF、异常退出也必须清理；tmux detach 与明确退出保持不同语义。
- 测试客户端必须保存静态画面和原账索引后退出，不把存活的 tmux 进程当作证据仓库。
- 稳定显示内容按不可变块复用；新内容、宽度/模式变化和装饰变化才重新处理对应内容。
  终端控制字符过滤必须保留，不能通过隐藏失败或移除安全检查制造“更快”。
- `TuiStateStore` 在同一发布状态内共享不可变快照；接受事件和拒绝诊断均使缓存失效。
  稳定块按完整 tuple 等值复用，不能只比较长度或最后一块而漏掉历史替换/重排。
  provider 按稳定/活动容器分别复用版本键，只保留当前两组强引用，不能用裸对象 id 作为永久身份。
- 排版缓存仅保留当前来源与显示宽度/模式的一份静态前缀，采用原字符和条数预算；
  在首个活动块前切开，后面的稳定块、活动块与插话仍按原事件顺序组合。
  动态角色不纳入静态前缀，超预算部分继续显示，不删除正文。行组构造器逐行净化，
  已检查的不可变行组拼接和切片可复用；搜索/装饰产生的普通行组仍通过最终安全出口。
- 可见帧最多以 20 Hz 合并，周期动画仅 4 Hz；按键、滚动和新事件立即申请下一帧，
  不等待动画定时器。事件、原文、模型与工具执行不受帧率控制，完全空闲页仍不周期重绘。
  此选择针对 Python 终端整屏布局成本；真实按键延迟与 CPU 必须同时验收，不能只报告 CPU 下降。
- 原文归档、历史页和当前视口分别有界。千万行原文验收核对首尾及跨页内容，不全量
  载入 TUI，也不能删掉早期历史来伪装内存稳定。
- Gateway 连接有容量和寿命边界；离开的客户端不留下永久占槽的半请求。
  状态传输失败不代表任务失败，不静默补发任务或改变消息身份。
- TUI 请求观察到达等待截止点仍先读取 canonical terminal。无终态时只显示等待提示并沿同一请求、
  同一 chunk byte cursor 继续观察；无活动轮询从 0.1 秒退避到最多 1 秒，活动恢复后回到短间隔。
  页面退出终止本地观察，不写取消、不重提请求。plain 和其它未声明续等的调用方仍保持有限等待。
  `gateway_request_timeout` 在 TUI 中是无活动提醒窗口，不是服务端任务终态或客户端永久放弃结果的依据。
- 空闲 owner 的轻量身份与持久状态保留；重资源仅由准确在途使用持有，释放不能取消
  活动子代理、审批、持久唤醒或共享插件连接。需要跨模块调整时先核对各调用者。

## 已落地与容量边界

- `owner_agent_idle_seconds` 默认 60，0 关闭；只读轮询和维护不续期，在途租用、活动后台线程、
  curator 与已有持久硬事实保护实例。完成的 curator 每轮及时释放，不等待下一次 60 秒派发；全局关闭策展时不构造软实例。回收注册表、池和调度投影，不删除资料或调用共享插件 stop。
- 显示 journal 为近期诊断窗口：256 事件、2048 去重身份、262144 个文本字符、4096 个流游标；
  UI 消费后正文仍在 reducer/canonical 历史。普通稳定块、近期身份和冻结阅读分别有界。
- 历史读取默认页条数仍由原配置控制；单一超长工作组达到 800 条或 8 MiB 即返回续页游标。
  单条 JSON 记录仍需完整解析，这不是“任意大小单条消息都只用常数内存”的承诺。
- Ctrl+O 冻结窗口最多 20000 块；连续上翻保留阅读侧前缀，释放远端末尾，Ctrl+End 回实时正文。
  原文仍按稀疏索引读取，缓存最多八页，不把千万行展开成一个内存数组。
- HTTP 保持 16 worker / 128 在途；socket 空闲读写上限 5 秒，排队超过 2 秒返回显式 503。
  这是半请求、排队和网络寿命边界，不限制持续正常输出的业务任务，也不隐藏真实传输失败。
- 低资源验收 profile 使用 `gateway_global_inflight_limit: 50`、`background_owner_workers: 2`、
  `background_threads_per_owner: 2`。未改变项目原全局并发默认值 500；部署低资源主机时必须显式选择
  该 profile，50 是上限而非建议始终满负载。重工具需要更低并发及独立进程资源预算。

## 验收顺序

先做资源寿命、终端安全与原有阅读/插话定向测试，再做受控 HTTP 慢连接/断开与并发。
最后在独立测试机、同一 Gateway 下运行官方 MiniMax-M2.7 的真实原生 TUI：启动、长历史
原地展开/滚动、插话、退出和重连；另做 1C2G 限制下的 10/50/100 身份队列与资源测试。
合成规模夹具、假 LLM、真实工具和真实模型证据分别记录，不能相互代替。
