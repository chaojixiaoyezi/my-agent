# 文件修改的有界语法反馈

状态：2026-09-27 已实现，异常隔离修复后六文件215项及独立窄复核39项通过；组合与真实 TUI 验收待做。

## 解决问题

真实长任务的两个原生 `write_file` 调用成功保存了不能解析的 JSON。写入成功是真实事实，
但当前工具没有把语法问题反馈给模型。新能力在原工具回执提供客观语法观察，不改变任务完成条件。

## 唯一执行位置

- `write_file`、`edit_file`、`apply_patch` 继续共用原单文件原子发布入口。
- 写入临时文件、完成 append 拼接后，从仍持有的同一文件描述符读取有限候选字节。
  以真实目标格式解析；不能以临时文件后缀判断，也不在发布后重新打开目标猜测本次写入内容。
- 仅原发布成功才返回该候选诊断；失败发布不产生成功诊断，部分补丁仅携带已提交文件的观察。
- 观察登记、删除及回执渲染的普通异常不能改变原写入成功事实；无法安全保留观察时丢弃本次诊断。
  取消控制仍由原执行链传播，不能被诊断降级吞掉。
- 不改已有 PDF/Office/压缩包等格式硬门、权限、配额、版本前置条件、来源引用或操作重放。

## 观察合同

- 首片只实现标准库 JSON 纯语法解析，接受对象、数组和合法标量；格式映射不作为可写文件白名单。
- 当前语法有效、当前语法无效、超预算未检查、读取或解析能力不足分别表达；未知格式正常写入。
- 观察包含目标路径、格式、固定代码以及可用的行列位置，不回显原文或臆测“本次引入”的错误。
- 无效 JSON 仍可用于分块写入和故意损坏的测试夹具；工具写入成功保持成功，不自动重试或修文件。
- 同一结构观察进入 `result_envelope`，同时生成有界的模型可见 `output`；不能只存隐藏字段。
- 每调用读取字节、诊断条数和反馈字符有有限上限；超限不把截断内容送入解析器，不冒称全量通过。
- 同一补丁的新增、更新、移动、删除及部分提交保留原事实；删除无语法观察，移动归到实际新地址。

## 配置与边界

增加总开关 `enable_file_syntax_diagnostics`，默认关闭；同步 AgentConfig 与默认 YAML 的中文说明。
验收环境显式开启，日用配置不自动改变。资源预算由同一诊断模块限制，不引入额外模型、网络、
Shell、LSP、后台工作或持久诊断账本。来源授权不随解析或反馈扩大。

普通任务仍由模型根据工具事实自然结束；不扫描产物目录、不重新引入 closeout 验收器。
本能力不保证模型修复错误，不证明 JSON 业务字段、来源忠实度、创作质量或通过包内检查器。
Shell、插件和其他写入者不属于三个原生文件入口的保证范围。
