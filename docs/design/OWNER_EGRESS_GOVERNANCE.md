# 普通用户业务出站治理

## 运行范围

部署主管理员先为每个普通用户固定一个独立 Linux 网络命名空间。以后可在 Gateway 运行时修改全局默认策略及个别用户策略。管理员账户、通道接收与回复，以及管理员明确共享的模型服务继续使用原控制面。普通用户自定义模型地址及其探测在受管部署中不可走宿主网络，用户仍可选用已授权共享模型。明确指定 DeepSeek 的搜索发送到固定官方地址，并使用当前用户的官方凭据及当前出站策略。

清单按规范 owner ID 绑定。全局默认应用于选择 `inherit` 的普通用户。设为 `unrestricted` 的已登记用户可使用不限目标端点的原生执行与已纳管网页工具。设为 `allowlist` 的用户只可连接明确允许的 IP 和端口。空白名单完全禁止该用户的受管业务出站。TCP 与 UDP 共享同一端点口径。运行中未登记的新用户及身份无法绑定的群会话仍可读取、管理原本已授权的本地状态，宿主网页请求和原生进程走拒绝回执。

目标、计划、本地文件和受信派工继续经过原授权。子代理及后台任务沿发起 owner 的规范身份工作。没有受管网络传输的连接器暂不可启动，包括普通 MCP、插件连接和未隔离的受控命令。已落盘且尚未结束的本地任务由原 Gateway 恢复规则处理，新执行仍通过当前 owner 的出站边界。

## Linux 部署

使用专用非 root Gateway 账号，清除附加组。系统需要支持 pidfd、用户和网络命名空间、`nsenter` 和 nftables。由部署主管理员在同一专用账号下启动持有进程，例如用 `unshare --user --map-current-user --net` 创建每用户命名空间。每个持有进程应保持存活。由宿主管理员为命名空间预先配置各自的网络接口和路由。内核 UID/GID 映射必须是 Gateway 账号当前 UID/GID 的单一等值映射。

在 MyAgent 根的 `config/owner_egress_namespaces.json` 保存名册，所有者与 Gateway 进程账号相同，权限为 `0600`。字段 `holder_start_ticks` 为 Linux `/proc/<pid>/stat` 的第 22 个字段。

```json
{
  "schema": "owner_egress_namespaces.v1",
  "enabled": true,
  "owners": [
    {"owner_id": "local/alice", "holder_pid": 1234, "holder_start_ticks": 45678},
    {"owner_id": "providers/feishu/users/ou_example", "holder_pid": 1235, "holder_start_ticks": 45689}
  ]
}
```

名册上限为 5000 项、2 MiB。启动检查文件描述符软上限是否至少为 `2 × 用户数 + 128`。每用户常驻两个命名空间描述符，启动和批量规则核验最多并发 16 个内核操作。这些是实现边界，尚未做 5000 用户负载验收。需要按实际租户数和系统开销配置 Gateway 启动等待时间。

新部署在启动前配置名册，再通过原账号和渠道入口创建用户。未启用的普通部署可省略该文件。持久覆盖记录已有部署继续使用同一名册及原命名空间。宿主重启后从原名册重新建立持有进程，并更新实际 PID 与启动时间。已有覆盖部署要关闭全局白名单时，从管理端切换为 `unrestricted`。

### 已有用户原地接管

1. 让旧 Gateway 正常停止，在原 MyAgent 根放好受管名册。保留原工作空间、账号及任务历史。
2. 以同一 Gateway 宿主账号运行 `my-agent gateway egress-prepare-takeover`。命令检查旧 Gateway 的状态和进程出生身份，并将原状态摘要、名册和当前 Linux 启动身份记入原出站策略数据库。此时对未绑定用户的业务出站按受管部署拒绝。
3. 重启 Linux 宿主。重新配置各持有进程的接口和路由，并更新名册里的实际 PID 和启动时间。保持原数据根、Gateway 配置和名册的规范 owner ID。
4. 正常启动 Gateway。只有系统启动身份确实变化、原状态摘要与名册仍一致、命名空间 FD 和内核规则全部核验后才完成接管。旧 Linux 系统上的进程及其套接字已经随重启终止。原数据和逻辑任务仍走既有启动恢复。

热改规则不需要重启。受管 Gateway 在同一 Linux 启动代内正常重启，会核对原网络和用户命名空间的 inode，并通过原进程出生身份确认上次 Gateway 已完全退出。原实例、宿主或 holder 证据缺失时，启动给出具体拒绝原因。

## 管理员操作

先用 `admin_controls(action="egress_list_users")` 查询真实用户，按显示名或规范 ID 筛选。用 `egress_set_users` 提交批量规则，用 `egress_set_default` 修改全局默认。用 `egress_get` 核对指定用户的已保存规则、有效规则、运行绑定和内核读回状态。模式字段和端点均走结构化工具参数。

切换时，受影响租户的宿主网页请求先停止新准入并排空。已建立的原生连接按新内核规则逐包检查。Gateway 先安装并读回新旧规则交集，提交策略后再核对目标规则。全局切换仅重配继承默认的租户，控制面为批量准备和最终核验保留 30 秒预算。批次遇到失败时按用户返回持久提交和内核核验状态，可据此核对实际规则。已有流量已经送达应用的数据仍由应用持有；撤销限制作用于随后经过内核的流量。
