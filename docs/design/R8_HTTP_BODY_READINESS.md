# 有界正文就绪与普通HTTP容量

状态：独立源码候选；不代表已部署或正worker/TLS模式验收。

原明文Count0 lane只等待首字节。52条声明4096字节、实际仅发送1字节的普通连接可以占住32个普通worker，让随后完整小请求排队2秒后503。控制池仍可用，但不允许把普通业务借入控制池。

## 运输合同

原单readiness线程每连接至多消费8192字节前缀。这是预读窗口，不是payload上限；头/正文超窗、模糊framing、Expect握手、Transfer-Encoding及真正keepalive连接仍走原普通handler。合法大正文不截断、不改写、不拒绝为“过大”。

只有头完整、唯一合法Content-Length（或原无正文语义）、精确正文均已到达时，才标为运输完整。此标记不解析JSON、不赋予身份/owner/业务权限，不代替原handler认证与解析。当前Gateway原JSON、文件及流响应均明确Connection:close，通过handler运输能力声明保留原单请求边界；普通持久handler必须保持默认能力，只有原明确关闭的请求可使用保留位置。不能从路由或prompt猜关闭/授权。

消费过的唯一前缀与原生socket一起由组合式PrefetchedSocket持有；初始化不detach、不重建原生socket，异常时原对象始终保有FD归属，关闭只调用同一原生对象，不盲关旧descriptor数字。复用标准makefile/SocketIO，reader先原样读取前缀，再读取内核新数据；不拼装新HTTP请求，不丢流水线剩余字节。file reader仍存活时沿标准socket文件引用延迟关闭，最后一个file退出才物理关闭。读完或实际关闭后主动释放前缀，Future暂留票据也不留正文。原流交接只有前缀已回放完才允许detach；普通keepalive真实第二请求仍走原handler循环，不强制断开、不提前EOF。

## 容量与公平

合法头在原排队截止前完整、原混合池确有空席时，部分正文直接交原handler慢读，保留无过载时2–5秒内完成小正文的原成功机会。头完成时刻仅为本连接瞬时运输事实，真正准入仍领取原容量槽并由worker重核原accepted_at截止；没有续期。原截止前混合位置后来释放时，原回调唤醒readiness推进等待责任，队列快照在推进后再捕获，避免覆盖新票据。

普通worker总数N不增加：N>1时原混合池最多N-1个，另一个普通保留位置只接运输完整的小请求。完整请求优先使用空闲混合容量，满时使用保留位置；慢/大请求始终保有混合池入口。控制执行器和容量独立，普通请求不使用它。N=1时维持原路径，不额外起线程。

所有普通票据继续共享原max_outstanding_requests，pending继续原pending_limit，无第二无界队列、磁盘spool或长期账本。前缀驻留上界为8192×(pending_limit+普通在途容量)，默认约4MiB，另有固定倍数的单窗解析临时空间和原固定元数据；并非整个进程内存上界。每个selector事件只读至本前缀剩余预算，消费后的旧字节不再持续触发可读，未完成请求不会忙转。真正超过在途总容量仍按原503，不保证过载时无条件接收。

原ticket的worker/expiry CAS、一次关闭、一次槽释放和排队取消物理移除保持；两个普通执行器共用同一责任。完整业务handler本身可能长时间运行，运输就绪不承诺业务耗时或抢占已执行的副作用。

## 截止与适用范围

配置数值保持：原accepted_at为准，排队2秒、socket传输5秒（均按原配置）。预读不刷新截止：晚到的头或尚未取得原混合位置的过载小正文，仍按原accepted_at排队截止拒绝；已经在原截止前取得混合位置的合法慢正文，沿原handler/socket读取语义继续，不因正文晚于2秒完成被额外拒绝。没有完整头的预读pending沿原5秒绝对等待期限；已完整头但仍无席位时受更早原排队截止约束。没有增加队列、worker或请求重试。原worker内的持续滴流与任意业务handler耗时仍受原合同，不宣称增加了可抢占硬总时限。未放宽任何100ms验收阈值。

本片仅原HTTPLaneRouter启用的明文、无drain_runtime模式；TLS、控制lane关闭及正worker原来源/生命周期分支不变，不宣称获得该优化。若扩展须单独核原出生、排空和TLS读取合同。
