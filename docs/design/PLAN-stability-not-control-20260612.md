# 计划:稳而不管(Stability without Control)

状态:**第一批+2-2 已落地**(2026-06-12;1-1 注入瘦身/1-2 质量类退出阻断/2-2 skill 激活完成;2-3 自学习钩子已落地;3-1 R10 验证完成(减负立竿见影,质量超历史最好 2-3 倍;详见 R10 审计);待办=知识召回最后一公里(skill 卡进主 run prompt+lessons 召回命中排查)、2-1 错误分类(低优先))。
实锤来源:R9 质量退化取证(单篇产出 4.6KB→953B 缩水 4 倍;周榜单周 29KB→7.8KB)
+ 用户裁决 + 三路对照组深读(长期助手/通道运行时/会话运行时/工具运行时/终端应用/轻量运行时)。

## 根因定性(用户裁决 + 取证一致)

1. **为机制改考题**:R7 起测试 prompt 写死产物数量/格式("必须 24 个 WEEK01.xlsx")
   ——违反"真实测试用普通用户中文"铁律(memory-hot 第 1 条),把模型的优化目标
   从"做好任务"扭成"凑满数量过门"。
2. **流程左右模型判断**:出口打回、续航催促、对账返工、注入膨胀(1300→1900
   token)叠加,模型注意力从任务本体被挤走(R5a 模型 28 轮静读 2335 行源码 vs
   R9a 44 轮伺候 15 个文件指标)。
3. **验收门只认数量格式**,"浅而全"成为过门最优解——机制在客观上奖励糊弄。

## 对照组核心结论(三路调研,详见会话记录 2026-06-12)

- **零验收门**:六家全都没有"数量/格式合规"式验收;质量来源=skill 知识文档
  (通道运行时 57 个 SKILL.md 带依赖声明、会话运行时 150 行决策树)、工具 schema 约束
  (工具运行时)、prompt 一致性(轻量运行时)、**会话后台评审自改进**(长期助手
  background_review:"评审目标不是质量检查,而是学习与行为调整")。
- **流程指令极少**:长期助手 系统提示的硬性要求仅两条——TASK_COMPLETION
  ("交付物是真实产物+真实执行结果,不是描述")与 TOOL_USE_ENFORCEMENT
  ("说了要做就必须当轮调工具")。其余复杂性(错误分类/重试/轮转/压缩)全部
  藏在框架代码,**模型看不见**。
- **失败处理=代码硬逻辑**:长期助手 ClassifiedError(auth/rate_limit/billing/
  context_overflow/model_not_found/policy…)逐类映射恢复动作,不让模型参与。
- **记忆有界+按需召回**:长期助手 memory 2200 字符硬上限、query-based prefetch、
  volatile 层 ≤ 总预算 10%;compact 摘要带"摘要是背景不是指令,最新用户消息
  是唯一事实源,持久记忆永远优先于摘要"的固定前缀。

## 行动(三批,每项自检:这是在管模型,还是在让底座更稳/给模型知识?)

### 第一批:流程减负(做减法,把判断还给模型)

1-1 **注入瘦身**:逐段量化每轮注入(workspace 段/工具目录/各类 hint/返工
    JSON/出口指令),目标 volatile 注入 ≤ 总上下文 5%。指挥性文案收敛成
    长期助手 式的两条核心引导;事实性字段(路径/资源)保留。
1-2 **质量类 finding 退出续航打回**:出口合同的续航只服务"客观未收口"
    (非终态子代理/open capreq);expected_outputs 等质量/数量类 finding
    改为**只进报告供把关,不触发打回**——对账事实保留,凑数压力解除。
1-3 **测试方法论回归**:R10 起 prompt 用 R5/R6 原版自然语言(普通用户口吻,
    一个字不加);验收=人工质量判断(深度/针对性/完成),门结论仅供参考。

### 第二批:吸收"稳"设计(做加法,但全部藏进框架/知识层)

2-1 **错误分类自动恢复补全**(长期助手 ClassifiedError 蓝本):盘点现有
    provider 错误处理(ptl_retry/transient_resume 已有),补全分类→动作映射,
    模型无感。
2-2 **skill 体系激活**(用户点名;通道运行时 形态):skill=领域知识文档而非
    流程指挥。首批内置 skill 候选:深度代码分析方法(怎么读一个项目才算读懂)、
    PDF 翻译工具链(pdf2zh/reportlab 等可执行路径)。渐进加载(Level 0 索引
    →按需读正文),让模型"知道怎么把活干深"。
2-3 **自学习闭环激活**(长期助手 background_review 蓝本+用户"没做好要学会"
    要求):任务结束后 fork 轻量评审(受限工具集),对照产物与目标产出
    教训/skill 更新候选;enable_self_learning 与 learning drafts 机制已有,
    补"任务结束钩子→评审→草稿"的接线。默认仍走用户确认提升正式。

### 第三批:验证

3-1 R10:三任务原版自然语言 prompt,零插手;验收只看质量(单篇深度/介绍
    针对性/翻译产出),与 R5a/R6b 历史最好成绩对标。

## 风险边界

- 减负不动安全硬门(危险路径/越权写入)与诚实底线(不许编造)。
- 孤儿回收/进程治理/resume 持久化全部保留——它们是模型无感的框架稳定性,
  正是对照组"藏在框架里"的同类。
- skill 内容只写知识与工具用法,不写"你必须第一步第二步"的流程指挥。
- 全程零任务专项;三个测试任务仍只是镜子。
