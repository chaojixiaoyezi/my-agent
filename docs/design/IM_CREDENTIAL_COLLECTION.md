# 群任务的私聊凭据收集

状态：2026-10-12，用户询问方案后的设计记录，尚未实现通用 API 凭据工具。本文件不代表当前离线包已经能自动弹 API 账号卡；个人解锁密码首设门是本轮实际实现与验证的另一功能。

## 推荐行为

群里单独 @机器人并提出 API 工作，模型可以选择请求缺少的账号、密码或 Token。运行时向原发起人私发卡片；群里只显示收集状态和最终工作结果，不放凭据字段或回传值。

不要求发起人事先与机器人私聊。群入站已经有可信平台用户 ID，可尝试直接发送；实际成功取决于应用机器人能力、用户可见范围及发送权限。飞书拒绝私发时，群里提供进入机器人私聊的入口，不改发群内密码表单。依据：[官方发送接口](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[官方机器人告警方案的可见范围说明](https://open.feishu.cn/solutions/detail/alert?lang=zh-CN)。

初次进入私聊的用户先完成个人解锁密码设置，再领取自己的原任务凭据卡。个人密码只用于验证本人继续操作；API 账号密码用于目标服务，两者不能共用库或互相代替。个人密码哈希不能用于恢复 API 明文。

## 归属与干扰

- 2026-10-12 补充评估：入口先完成可信机器人提及规范化和命令识别，敏感控制不能因带有 @前缀落入普通持久消息或模型；相关复现与安装/帮助方案见 [设计台账](../../DESIGN_LEDGER.md#飞书命令角色帮助与离线更新入口2026-10-12评估完成待实施)。
- 每次收集有独立 request ID，并绑定 app、owner、平台 actor ID、原群/话题、thread/task/run 引用和有效期。
- 发送目标由可信来源绑定解析，不让模型自由填收件人。群里后来发消息的人不改变原收件人或凭据归属。
- 私聊入口携带的是领取请求引用；只有原 actor 能领取、提交、取消。其他成员点入口或提交别人的卡片不修改原请求。
- 并发请求各自保留准确引用，不用“最后一条群消息”或“最近的私聊”选择任务。重复提交幂等；过期/任务取消后提交不继续旧工作。
- 原任务通过原生命周期让出等待，不占住群里其它人的正常聊天；提交完成后只唤醒对应任务。

## 秘密的使用边界

凭据表单回调不进入普通聊天入站、transcript、模型上下文、日志或产物。群里结果和私聊回执只包含字段填写完成状态，不回显账号、密码或 Token。

模型只得到凭据引用与可用状态，具体工具在执行时解析。引用必须绑定 owner、原任务、允许的目标服务、用途和期限，不授予管理员目录或插件权限。工具错误、调试输出和发送回执需用同源秘密遮蔽；不能仅靠 prompt 要求保密。

现有实现只有模型供应商/OAuth 凭据与个人密码验证，不应改名当通用 API 凭据库。实现时需要唯一的通用凭据请求/加密保存入口；不能恢复已退役 SecretStore，也不能把明文放在 task attributes 或配置投影里。

按本轮复用优先要求，先盘点并复用现有私聊卡片、回调认证、身份绑定、个人锁、加密存储可共享部分、投递和任务唤醒；只为尚缺的目标服务凭据请求、授权和引用补最少通用能力。保持供应商凭据、个人解锁密码与任务凭据各自语义，不另建身份、任务或消息账本。

默认按本次任务授权，结束、取消或超期后失效。用户若需要长期监控，应明确选择保存供该监控计划使用，并保留更新与撤销入口；既有运行中的计划不得静默换另一个人的凭据。

## 验收

1. 从未私聊用户的群请求：能私发时直接发送；发送拒绝时只给私聊入口；首设个人密码完成后领取原请求。
2. 同群两个发起人、同人两项任务、错 actor、群干扰、转发卡片、重复/过期提交均保持准确归属。
3. 没填或密码/Token 失效时只等待对应任务；其它聊天仍正常，原告警在个人会话锁定时仍可推送。
4. 各层模型请求、消息账、日志和工具输出中不包含原始表单秘密；秘密引用跨用户或不同服务不能解析。
5. 真飞书测试应用验证卡片实际送达、表单字段支持与回调，不把模拟发送当成平台验收。
6. 现有个人密码卡中的输入类型和客户端版本说明不是通用凭据卡兼容性证明；需核对官方卡片格式并验证桌面/移动端实际遮蔽、提交和清空行为。未证明兼容时不承诺已经支持密文输入。

建议下一步：将此功能独立实现为通用凭据收集合同，先做 Store/授权/回调测试，再接原工具执行与任务唤醒，最后做真飞书验收。可并行只读审阅卡片和凭据边界，领域写入与通道回调保持一个实现负责人。
