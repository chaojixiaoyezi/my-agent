# 长时间运行：等待、通知与缓存诊断

状态：实现及定向回归已完成；正常 TUI 通知、并行与恢复主链已验，慢模型长任务循环恢复未通过。

## 目标与已有主链

健康慢模型可以长时间预填充、思考及生成；UI、用户输入、其它会话不应随之阻塞。
连接、首事件、流中空闲、工具等待、显式总预算是不同期限，不用一个墙钟超时混为任务失败。
复用 provider 活动续租、直属孩子通知、持久输入回执、Compact/操作账本与前台端点占用。
输出上限、断网及服务端淘汰缓存仍是客观边界；不用无限重试、删除历史或新的完成判官掩盖。

## 仅思考响应与续跑历史

真实抓包发现：一轮正常停止的响应含约 3.7 万字符思考，无正文、无工具，被误判为
`MODEL_EMPTY_RESPONSE`；续跑只加提示，没有带入刚生成内容，用量也走异常缺报。
另一条缺口是正常响应返回后，零工具 `continue` 分支没有保存 assistant 原生轮。

- Chat/Messages 的有效 typed 思考（含签名、密文）按正常响应返回；真正空内容仍按原错误处理。
- 零工具续跑先把真实正文/思考追加到既有 IR，不以工具轮号合并连续模型响应。
- 未执行或不完整工具块不带入可执行历史，不伪造调用/结果，不把思考当最终公开答复。
- 空正文复用原两次预算；仅思考首轮也适用，预算耗尽仍诚实收口，不无限重试。
- 普通最终回复与实际工具轮沿原保存入口，避免双写；已有历史不倒推补写。

该修复不保证模型单次输出不重复，也不改变采样、服务缓存、权限或长流等待期限。
定向验证覆盖流式/非流式、连续仅思考、下一工具轮、真实出站字段、签名、用量和未执行工具过滤；
真实慢模型按一条 TUI、不派子代理、原始出站证据和产物复核单独验收。

## 后台进程长等待

`process_session(action=wait)` 默认 30 秒，上限 600 秒，工具外层预算略长于等待上限。
等待不持注册表锁，使用单调时钟和宿主取消令牌，不循环调用模型。取消等待不伪造命令退出；
整个回合显式取消仍按原进程树策略执行。届满返回 `running + wait_timed_out`，不是任务失败。

## 完成通知

`background_process_notifications=true` 时，主会话启动后台命令会将 store/thread/task/run
收件地址冻结到受保护的进程记录。地址由宿主注入，模型不能指定，后续不能改绑。

- 原 Gateway tick 和活动主回合安全点调用同一收割入口，不另建调度器或模型轮询。
- 核对 Popen/PID 出生标识与 host 退出回执后，将 `managed_process_exited` 投入原 wake 队列。
- session ID 决定去重键：先入队再标记发布，崩溃重入不丢通知或重复交付。
- 明确 `killed` 只记观察，不叫醒重启。欠通知记录不会被普通终态裁剪删除。
- owner 发现层将欠通知记录作为硬事实并纳入签名，支持 Gateway 重启及热缓存淘汰恢复。
- 通知只含退出码和日志引用，不重复灌入全文；命令退出不等于业务任务通过。
- 原主任务自然结束后，只有受保护进程记录、收件身份和通知回执全部匹配才允许补报；
  队列筛选和 claim 后的最终准入共用此校验。interrupted/cancelled、未结束 Goal 不因此复活。命令本身不重跑。
- 信号已入队但发布回执尚未写成功时返回 `receipt_pending`，先保留信号，由原收割入口重投补齐回执。

通知作用于主会话；子代理仍走直属父级生命周期交接，内部后台工具可长等/查询。
不会因孩子的后台命令结束启动影子主代理。关闭开关不影响主动查询、等待及停止。

## 缓存诊断

`cache_diagnostics_enabled=true` 在真正 HTTP 出站处计算不可逆摘要，放入原调用账本的
`request_surface/cache_diagnostic`。不保存正文、密钥或完整地址，不改请求前缀或裁剪记忆。

同 owner/thread 比较；无 thread 时限同 run。端点、模型、system、tools、请求选项、消息前缀
分别比较。只追加与历史缩短分开；超过 512 条消息标明 `partial=true`，不谎称完整前缀相同。
数据有界且不进入 UI 排版热路径。客户端摘要稳定不能证明服务端缓存存在，后者保持 unknown。
关闭开关不计算摘要。同端点普通策展避让继续复用 foreground scope，不控制外部应用或别名端点。

## 后台异常退避

真实组合发现：旧会话模型未配置时，仅延迟 30 秒不能恢复缺失配置，仍会永久重复抢工位和报错。
`cli/gateway_lane_retry.py` 统一管理进程内 owner/thread 失败：本地缺模型或模型引用无效时，
等待该会话的规范模型配置可用，再进入原执行车道。只改新会话默认模型不会偷换旧会话；不发网络探针。
普通宿主错误仍由 `background_main_error_backoff_seconds`（默认 30 秒）按单调时钟冷却，零值保留。
健康会话及前台消息不被阻塞，失败事件仍留在原持久队列；成功或 owner 淘汰后清除临时记录，
最多保留 1024 条，超出只淘汰临时退避，不删除持久任务。Gateway 重启重新判断，允许首次记录原错误。
状态读取和 worker 更新共用短锁，配置读取在锁外；不暂停 Goal、不改慢流时限、不强杀模型。
真实 TUI 补测发现 Goal 的旧错误分支会先把目标标成 blocked、消费原唤醒，导致配好模型也无法接回。
现让同一 typed 本地配置异常只释放调度 claim、保留 active Goal 和原 wake，不累计周期策略的失败退休次数。
已有 blocked/paused 目标不会批量激活，须用户显式恢复；其它执行错误和额度限制继续沿原状态处理。
真正 HTTP 拒绝不等于本地缺配置，不能用这个检查推断远端账号可用或伪装为已经通过真实模型验收。

当前真实验收：缺配置目标等待后，经 TUI `/model` 选择真实模型，原 goal/task 自动继续并完成，
CSV 工具 16 项测试独立重跑通过；另一正常窗口日志工具独立完成，16 项重跑通过。
四个旧失败会话在约 15 分钟观察期各记录一次错误，没有每 30 秒热重试。底座联合定向 384 项通过。
首次候选仍会将 Goal 标成 blocked，该失败现场保留；最终候选通过显式恢复旧目标后验证新的缺配置等待，
没有直接编辑目标文件伪造成功。旧 blocked 目标不因升级被批量自动激活。

最近一次缓存前缀比较与该次响应的缓存百分比一起保存到已有 thread 的 `model_metrics.cache_diagnostic`。
只保留原因码、共同消息前缀计数及是否覆盖完整；原文、摘要数组、URL 和密钥不进入该显示副本。
重启后可读最近结算的快照，新进程第一次请求仍明确标记“无比较基线”，不会假装知道服务端缓存状态。

## 本轮实测追加修复

- 子代理输出达到上限后需要沿用自己的会话模型续跑。后台派工不再把共享宿主的当前连接
  作为隐式 override；普通创建、直属父级接续与周期恢复使用同一个 child 模型引用。
  显式测试/嵌入注入仍可用，且隔离到派工线程，避免并发派工互相污染。
- 回合中断原先可能只留下用户消息。运行循环现在在异常退出前将当前原生 IR 交给宿主保存，
  前台、孩子与 CLI 复用原会话身份；后台普通续做另有逐片宿主回合编号，将空正文 native 与公开 final 关联去重。
  停止/静默不生成假回复，不丢已发生事实；未知工具结果不自动重放，窄审计保持隔离。
  硬杀未保存内容及旧历史缺口不能从界面文本猜造恢复。
- 精确编辑的未命中/不唯一返回 `EDIT_TARGET_MISMATCH` 状态类错误，携带当前片段、版本与 read_file 参数；
  格式错误仍用原参数错误。文件不写入、不隐式放宽匹配，避免错误地鼓励原样重试。
- 后台长工作片可能开始时仍有孩子运行，却在结束前已经接收全部结果。删除以旧阶段快照强制再开一轮的
  过时门；关闭和汇报检查当前子树、未读邮箱及明确 Goal 状态。未读信封和活跃孩子仍保留。
  否则回复被抑制而所有事件又已消费，会形成“做完了但最后一句永远没发”的死角。
