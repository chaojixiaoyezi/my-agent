# R8 线程任务历史与候选当前态增量账本

## 常规消费者的历史窗口

线程历史页迁移完成后，普通 Gateway 请求使用 `TaskStore.context_report`，只读取最多128个近期物理位置、完整活动集，以及请求/目标/工作区的准确引用。明确旧成员的文件丢失仍可降级；从未登记的绑定继续拒绝，不能由 required 参数伪造历史成员。活动索引命中后仍核对 canonical TaskLink 的线程归属。

直属子代理汇总合并同线程全部未处理观察与有界近期观察窗口。当前义务不能被后来的普通事件挤出；已处理旧历史的数量未知时，即使窗口内没有完成项也保留 coverage。投喂给模型的旧根/子任务结构化 ID 同时进入公开回复脱敏表。观察投影尚未追平时保留 typed partial，不把空结果当作没有待交付。

任务续接使用准确成员读取和最多16跳继任链，保留取消、失败、环及跨线程/目录拒绝。派生编号只探测同一请求的冲突编号，取消了无关历史 TaskLink 的加载；大量重复 `visit` 仍随该请求的冲突链长度增长，不能称固定次数。

显式完整历史 API 的语义保持；按历史名称挑选终态任务等入口仍需原完整历史。它们不能用近期窗口替换而漏掉合法旧任务，本片不宣称这些显式历史操作已经改成常数开销。

状态：本地实现与定向验证中，待主分支集成及远端 CI；不代表运行服务已切换。

## 解决问题

长寿线程每新增一个任务会重写全部历史 task_ids；候选单条审核又会复制、编码并替换整个 candidates.jsonl。两者累计写入随历史增长，单条热操作不能保持有界。

## 线程历史

- TaskLink 继续拥有任务身份、线程归属与状态；新增 `threads/task_history/<thread_id>/` 只拥有线程历史成员顺序，不拥有执行权。
- 每页最多 128 项，SHA256 分片成员记录提供确切成员定位，`index.json` 的 count 是已发表边界。首次写在原线程锁内先完整迁移旧数组，再更新线程 JSON。迁移中断保留旧完整数组，重试覆盖尚未发表的尾部。
- 线程 JSON 的 `task_ids` 是最近最多 128 项加全部活动项的展示窗口，`task_history_version=1` 显式标记协议。`to_dict` 不读盘。活动投影在原线程锁内重读精确 TaskLink，迟到的 bind/status 投影不能重新激活已终结任务。
- `task_ids_page` 返回 `(ids, next_cursor)`，单页最多128个物理位置；`iter_task_ids` 仅供显式历史导出和维护。精确选择、收割与状态幂等使用 canonical TaskLink/成员定位；保留清理及显式归档遍历完整分页家族。
- 历史目录被手动删除后，新任务仍能建立，原 TaskLink 精确查询仍有效；重建头标记 `incomplete`，完整历史查询返回明确错误，不能把剩余窗口伪装为完整历史。整个 owner 目录删除后按原新用户初始化重建。

## 候选当前态

- `candidates.jsonl` 的新格式是单行 `candidate_ledger=memory-candidates-v2` 头，指向同目录 `candidates.jsonl.records/` 的当前根；头与节点共同组成唯一当前态权威，不再维护第二份 JSONL 当前态。
- 正文单条内容寻址；通用 HAMT 保存 ID、序号、观察键、证据目标版本绑定、各状态当前集合与计数。只覆盖通用索引的读写叶进行内存规划，未增加领域专用路由或依赖。
- 惰性工作副本只读取命中的候选；审核、批次 CAS、晋升、排除标记、合法/拒绝观察、广播去重与冲突预演均使用 ID/观察/版本索引。待晋升查询只遍历当前 pending/approved 集合，统计读取已封印计数。显式完整列表、保留清理和冷转仍按真实扫描量收费。
- 旧 JSONL 保持严格解析和重复 ID 拒绝，首次正式写一次性迁移。之后不再回写旧格式。输入模型的归一化仅发生在该条私有副本，调用方对象不被修改。
- 写者先规划所有正文/节点/清理义务及新头，统一按新旧共存峰值做 quota 准入；随后逐个准确写叶消费原 coordinator 门，最后发表唯一头。quota 拒绝前没有文件写入。新头未发表可证明时，失败回收本次新生节点；结果未知时保留恢复材料。
- 新头封存旧路径及正文回收义务，提交后逐项删除，最后删除义务文件；中断可在下一次写/硬删除重试完成。当前单根以外旧节点不保留为历史正文，避免正常更新无限堆积与硬删除残留原话。冷档沿原 owner 封印、正文脱敏和月档核验。
- Curator 跨文件事务把新节点和头都纳入原 quota/备份/回滚，节点先、头后、state 最后，事务成功后才回收旧根。Skill transfer 同样在原候选锁与 registry 提交范围内规划，finish 前保留旧根，失败恢复原头及本次新节点。
- 原 owner/source/目标版本/CAS、正式晋升与人工确认边界保持；不扩展自学习授权，没有新配置或第三方依赖。

## 验证边界与后续

运行时测试覆盖长历史迁移/分页、中断重试、终态 Event 交错、BFS 穷举、固定种子回放、单候选写禁止全表迭代、状态集合与计数、quota 拒绝零写、硬删除中断恢复以及删除 owner/历史目录的降级自愈。旧候选、晋升批次、Curator 事务、coordinator、Skill transfer 和保留清理测试继续核对原业务语义。

未启动真实 Gateway、未运行真实用户任务、未访问真实 owner 数据；完整跨平台及 GitHub CI 由集成者在最终组合提交验证。

建议下一步：先集成并运行候选/线程历史与维护组合的严格 gate，再跟踪远端 CI。其他 agent 可独立复核节点生命周期和事务回滚，但不得并行修改同一写者；Claim 的物理退场不能用 TaskLink 活动集替代，相关闲置检查须保留独立的 Claim 证明。

## 配额结算前像补修

候选头发表后的旧节点、旧正文及 cleanup 义务文件删除，也必须经过本次已持有的 quota admission 登记前像。清理入口接收明确的 admissions 元组，在 unlink 前按零字节追加登记原大小；不在首次新旧共存峰值检查中预支未来删除收益。退出仍依据实际落盘字节结算。普通候选、脱敏、Curator 提交/恢复与 Skill 迁移都透传原持有准入，不再领取 owner 锁。

固定结构的 `memory/curator/pending_condense.json` 本来就在领域锁外写，归入既有宿主控制文件的目录摘要豁免；它仍按真实字节计费，由正常对账补正，不豁免候选正文或内容寻址节点。回归同时验证大于前台窗口的真实配额基线不被候选自身回收撤销，以及净额可容纳但新旧共存峰值不可容纳时必须拒绝且原头/节点不变。
## 正式记忆代次清理的配额收口

正式代次发表后回收旧正文及空代目录，继续使用同一次已取得的配额准入，按零追加登记删除前像；首次新旧共存峰值不抵扣未来删除。辅助目录行只有在目录已声明、完整旧摘要的所有子项贡献都已逐项抵消为零且路径确实消失时才退役。缺失证明、部分扫描或未声明子项仍使基线变脏并拒绝未知增长；不清空业务数据、不复用过期用量证明。

增量头损坏沿原 `CandidateStoreCorruptError` 暴露，并保留 JSON/schema 原异常为 cause；只读失败不写、不返回旧候选或空候选。旧布局回归现使用合法内容寻址计划、跨解释器原子发表和同 inode/尺寸/mtime 的头更新，点查仅解析目标记录并验证返回隔离。
