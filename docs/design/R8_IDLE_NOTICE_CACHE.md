# R8 空通知消息页缓存

状态：本地实现与真实HTTP回归已完成，待总控集成及CI。未启动真实业务服务或调用模型。

## 解决问题

旧实现缓存整份空通知响应，仅以事件中心owner主题标记和120秒TTL失效。默认事件中心ring=0时完全不生效；没有发布同进程hub事件的canonical写、权限变化、任务状态与内存过程事件可能在TTL内被隐藏。

现在删除整响应缓存。每请求仍走原认证、owner/actor解析、精确线程解析、审批消费者与请求、活动任务、内存过程事件及执行目标读取，只有最终为空的canonical消息页可以复用。长轮询的订阅与等待仍只负责提示，不参与消息是否完整或权限判断。

## 唯一缓存来源

`idle_notice_page.read_idle_message_page`只接受已知原生`ConversationStore/MessageStore`及同一storage对象。普通消息布局依赖一个JSONL：无冷热manifest时才允许缓存。只用已存在目录FD验证真实消息目录，以源dev/ino/size/mtime_ns/ctime_ns/mode和父目录身份作为版本；缺失源也必须由同一真实目录中的存在事实表达。

正式消息追加改变长度，正式原子改写/轮转/重建改变inode或产生manifest，删除、权限和原位修改改变存在性、模式或时间。源读取前后版本不一致则不缓存。跨进程写入无需通知当前Gateway。

存在manifest（包括准备中或损坏清单）、自定义读口、链接/硬链接、不安全父链、源读取失败等均回原读口；不把只核hot文件的stamp冒充整个冷热布局版本。缓存只保留空列表对应的cursor，不保存正文，最多512项。TTL只约束进程内复用寿命，不作为完整性或失效证明。

## 配置与性能边界

沿用`gateway_idle_notice_reuse_seconds`，默认120，0关闭；YAML和dataclass只更新中文说明，不改默认值或增加开关。不依赖`gateway_event_hub_ring_events`，默认ring=0同样减少源消息页打开。

性能收益明确收窄为普通canonical空消息页。整个通知请求仍读取权限、线程、任务、审批、过程流与执行目标；不声称整响应O(1)，也不缓存冷热分段历史消息页。长期线程数量不影响缓存内存上界。

## 证据

真实Client→HTTP路由→原投影连续轮询验证：默认无hub时重复空页仅打开一次；活动/取消和内存事件仍逐次可见；隔离子进程沿正式MessageStore追加的通知在TTL内立即出现；切换actor不会拿到旧线程消息；旧凭据撤销后立即403。

定向测试另外覆盖游标变化、非空页不复用、到期、关闭配置、损坏manifest、原子同长度换库、权限变更与源读取期间并发提交。原消息页读口返回值及失败语义保持。

建议下一步：总控合并后跑HTTP/通知/认证组合及严格gate，跟踪远端CI。可并行只读复核所有消息写口是否仍遵守append/原子replace合同；未知新布局保持不缓存，不能通过延长TTL或增开hub补完整性。
