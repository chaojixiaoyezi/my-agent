# 管理员共享模型目录

## 目的与当前状态

同一 Gateway 下，管理员可以保存模型 A/B/C/D，显式开放给用户；用户各自选择会话模型。
已实现服务端配置、菜单及定向测试；真实 TUI 验收结果由本轮验收记录单列，不能用本文件代替。

## 权威与开关

- 私有 provider/model 继续只有 `config/model-profiles/<owner 身份摘要>.json` 一份。
- `config/shared-model-profiles.json` 是共享开关目录，只保存 `shared:<原模型 UUID>` 引用，不保存凭证。
- 新部署目录不存在，等同全部私有。每次在 `/model` →「默认模型与共享」→「共享给其他用户」中确认才开放一个模型。
  这是逐模型显式配置开关，不新增会自动发布模型的全局 YAML 开关。
- 共享范围是同一 Gateway 已认证的用户；费用由被发布的模型账号承担，确认框会说明。
- 管理权限复用可信 owner 的 `is_permission_admin`，来源定位复用 canonical `local/main`，不接受客户端路径或 owner ID。

## 使用和隔离

1. 管理员新增模型，选择是否共享，默认不共享。
2. 用户在「选择模型 → 对话模型」选择私有或已共享模型。会话持久记录只有模型编号。
   IM 用户没有菜单，在聊天里发送 `/model` 查看带编号的可选模型，再用 `/model <编号>` 为当前会话选择。
3. 「我的新会话默认模型」改变当前用户未来默认，不改变已有会话。主/子代理仍按工作片冻结配置。
4. 发布和撤销都不改变任何会话的选择。撤销后正在执行的请求不中断；下一调用明确失败，不能偷偷切换供应商。
5. 删除、禁用、撤销或目录损坏时，菜单明确标记不可用，仍允许手动改选可用的私有、共享或显式部署连接。软件没有预填模型，列表有共享项也不代表已选用。
6. 子代理可引用可用共享编号；名称重名需要编号，管理员同一私有模型的共享别名不重复消歧。
7. 主动连接测试复用已有网络入口，共享配置仅为单次内存快照；成功和异常出口都清洗 key 和自定义头值。

这不共享聊天、Memory、工作目录、管理员权限，也不把连接配置注入业务任务。私有配置被用户主动编辑时，
引用它的未来请求会使用新版本；已经执行的请求保留原快照。供应商间缓存命中不作保证。

## 其他用户的初始模型（2026-09-30，已实现）

- 用途：管理员指定一个模型，给**没自己选过模型**的普通用户（包括飞书等 IM 用户）用，让他们不配置也能直接对话。
- 存储：同一个共享目录里可选的 `initial_profile`（`shared:<原模型 UUID>`），必须同时在已发布列表里，读取时不满足按目录损坏处理。
  设置入口 `set_initial`（只有管理员；只接受管理员自己的 API Key 聊天模型，订阅/OAuth 账号不能给别人用）：同次先把该模型开放共享，
  再写初始模型；空值清除。每次保存都换代，旧建议失效。
- 生效规则（`model_profiles.selected_model_config`）：普通用户的选择引用是 `default` 时，解析为管理员初始模型；管理员（local/main）
  自己的 `default` 仍是部署配置。用户自己选过的会话模型或新会话默认都不被覆盖。会话仍只存 `default`，管理员换初始模型后，
  这些用户的下一个工作片跟着换；子代理按父级冻结的具体编号继承。
- 撤销该模型的共享会同次清除初始模型，没选过模型的用户回到部署默认（撤销确认框会说明）。原模型被删除时按共享模型原规则
  明确报错「共享模型原配置已删除」；共享目录损坏时明确报错。两种情况都不悄悄换成别的模型。
- 展示：普通用户的模型列表里，「默认」一行换成初始模型的公开字段并带结构化 `default_source=admin_initial`，TUI 和 IM `/model`
  都标「管理员指定的初始模型」；不可用时标不可用并给出提示。管理员列表带 `initial_profile` 与逐行 `initial_for_others`。
- 回归：`test_shared_initial_model.py`（后台）、`test_tui_manage_models.py`（菜单按键）。
