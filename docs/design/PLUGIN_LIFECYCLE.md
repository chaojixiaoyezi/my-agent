## 解决问题

my-agent 自身保留完整的会话、任务、内置工具和恢复能力；插件提供可选的新命令、工具和 Skill。
用户觉得插件难用、卡住或没有价值时，可以停用或卸载，继续使用原来的核心能力。
安装、切换版本和撤销可选能力尽量不重启 Gateway；不要求所有内部模块都变成插件。

“不用时不影响”必须落实为可核对的边界：

- 安装但停用：除包文件、管理记录及安装操作本身外，不导入插件代码、不起进程、不注册定时器、不发请求，不向新工作片注入插件提示或工具目录。
- 已启用但未调用：默认按需启动；可发现的命令/工具元数据可能有少量索引或 token 成本，不宣称完全零开销。主动后台工作另需显式配置。
- 停用或卸载：撤销后续调用入口，取消其在途工作并有界回收精确归属资源；其他插件、内置工具和无关会话继续工作。
- 不改用户的模型配置、核心权限、历史、记忆或 Goal 状态；既有文件、已发请求和审计事实不因卸载而假装没有发生。
- 插件升级回退只回退版本与注册，不承诺撤销外部副作用；已执行但结果未知的操作仍保留未知事实。
- 先前已发送的模型上下文无法收回；历史中的插件调用及结果继续保留，不能为了“干净卸载”改写历史。

## 现有基础与缺口

| 位置 | 已有事实 | 尚缺的部分 |
| --- | --- | --- |
| `agent/extensions/plugin.py` | 按管理员显式配置加载 Python entry point 或模块；注册工具、记忆源和 CLI 命令 | 进程内启动加载，没有完整卸载、版本切换和资源清理协议；失败配置按现行合同阻止启动 |
| `cli/parser.py` | 插件命令接入 argparse | 不是 TUI 动态 `/xxx` 命令；TUI 当前还使用静态目录与处理器 |
| `agent/tooling/registry.py`、`agent/tooling/models.py` | 权限过滤后的逐次运行工具快照，已绑定 schema、策略与 handler 对象；MCP 连接准备 | 尚未绑定插件包版本、激活代次和独立执行端点；冻结 handler 引用不等于冻结它引用的外部进程版本 |
| `agent/tooling/mcp_client.py`、`agent/tooling/mcp_registration.py` | MCP 工具变更通知、运行边界重发现、连接重试、工具目录替换 | 不是包安装器；停用必须同时阻止重连和重新注册，不能只删工具名字 |
| `agent/capability/skill_service.py` | Skill 索引、正文指纹、逐次运行快照 | 热切换需保留旧版本正文，不能覆盖文件后声称旧任务仍能读取同一份内容 |

上述路径均相对于 `agent_py_agent/`。现有经验候选继续复用 CandidateService，不能重建第二套长期记忆或草稿事实源。

### 第 1 步接线核对与迁移约束

本节按 `ba90862f9` 定向读取现有入口及回归；描述实际依赖与后续必须保留的边界，不代表插件装卸已经实现。
工具快照已经有实现绑定，因此继续沿原执行器扩展生命周期约束，不再增加一个插件工具执行器。

| 当前入口 | 已核实的依赖与行为 | 后续接入约束 |
| --- | --- | --- |
| `cli/parser.py::main` | chat/resume 先走轻量解析；其他命令才加载管理员启动扩展并注册 argparse 命令 | 动态 TUI 目录从 Gateway 读取；不能为补全或帮助把插件导入重新塞回客户端启动链 |
| `agent/core.py` 与 `extensions/plugin.py::activate_agent` | 先创建工具注册表，再顺序调用启动扩展的 tools/memory hook，再注册编排工具与能力目录；hook 失败中止装配，没有贡献事务回滚 | 保留管理员启动扩展的失败语义；可装卸插件的候选验证和原子发布不能直接冒用该 hook |
| `ToolRegistry.runtime_snapshot`、`models.py::ToolRuntime` | 每轮冻结 schema、策略、handler 及当时可用性；`ToolExecutor` 从同一快照取实现，调用侧不重查当前工具字典 | 保留已有实现绑定；新增插件代次和撤销约束，不能只删除目录项或修改一次 availability 就宣称停用 |
| `ToolRegistry.with_access_policy` | 权限视图重建基础工具字典，其他 handler、MCP 客户端、重试字典和准备锁沿原共享对象 | 插件撤销的权威须覆盖同 owner 的所有权限视图及已冻结快照，不能只清理发起管理操作的那个字典 |
| `executor.py::_execute_authorized`、`_invoke_with_operation_policy` | 参数校验和 pre-handler 回调先于副作用操作领取；只读失败可按原条件重试，写操作仍沿原 operation、资源锁和对账链 | 等待审批、锁或重试后都须受当前撤销事实约束；仅在最初解析或 preclaim 阶段检查一次不足以覆盖在途停用 |
| `registry.py::_prepare_registry_clients_for_run`、`mcp_registration.py::refresh_registered_mcp_client` | 新运行边界重连同一个 client 对象，再替换该连接的工具目录；旧 proxy 仍引用原 client | 插件端点绑定到激活代次，旧代次不得原地重连成新版本；停用先阻断重连再清理，不能用关闭全部 MCP 代替精确撤销 |
| `capability/skill_snapshot.py::SkillSnapshot.read_body` | 快照固定路径和正文摘要，读取时重新读文件并比对；文件被覆盖会返回 `SKILL_SNAPSHOT_STALE`，快照没有保存正文副本 | 插件版本文件按代次保留，仍沿现有 Skill 身份、快照和正文校验；不能覆盖旧路径后假称旧任务仍有原内容 |
| `conversation/control_commands.py`、`cli/chat_parts/slash_commands.py`、`tui_input.py` | 迁移前 slash 正则不接受首 token 的 `@`；首片已移至公共命名空间判据 | 第 3 步在公共入口识别完整插件命名空间及错误形式，再让 TUI/plain/Gateway 共用声明；不能只增加一个补全项 |

拟议插件的“可调用”检查与在途资源登记，须在同一生命周期权威中形成不可被停用穿插的准入动作：

- 停用先取得该边界时，调用拒绝且不启动实现；调用先取得时，其精确 owner/run/attempt、插件和激活代次已登记，随后停用可以取消并追踪它。
- 审批通过只表示该操作获准，不保证插件仍启用。等待审批期间停用后，旧批准不能恢复已撤销代次；重新启用生成的新代次也不能让旧调用自动换实现。
- 原工具 operation、幂等记录、资源锁和副作用对账仍是唯一执行账本；插件注册只补充生命周期归属，不再复制一次业务执行状态。
- 已经发出的请求按实际取消/退出/未知结果收口，不能在停用后改写成“从未执行”。目录刷新、快照存在及模型报告均不能证明资源已经退出。

上述准入和代次约束在第 4—6 步实施，并覆盖停用与审批、资源等待、重试、重连、权限视图交错；本轮不改核心运行语义。
现有 17 项定向回归已通过：启动扩展注册与失败、工具快照不扩权及冻结可用性、MCP 重连与目录替换/退避、Skill 过期读取、公共未知命令与 TUI 补全。
这些是既有合同的自动化证据，不是插件热卸载或新增真实 TUI 验收；第 1 步按用户确认的框架/交付分账收口，原长任务失败及后续推进门槛仍由执行 Goal 记录。

## 核心与插件边界

| 核心持续负责 | 插件可以贡献 |
| --- | --- |
| owner/thread/run 身份、任务状态、执行租约、取消与恢复 | 通过声明接口使用当前调用身份，不自行认领其他任务 |
| 模型循环、历史、记忆、权限、审批、工具执行账本 | 领域工具、外部服务适配、可选 Python 依赖 |
| 注册目录、安装管理、生命周期及资源归属 | 命令描述、工具 schema、Skill 包及自有设置 |

插件、工具和 Skill 不等价：插件是安装/升级/卸载单位，工具是可执行能力，Skill 是按需读取的方法说明。
用户按插件装卸；单个工具的允许范围复用既有 tool policy，不再造一个工具安装器。
插件只拿最小公开能力，不拿完整 Agent/Store，不 monkey patch 核心；注册返回可精确撤销的句柄。
首期不开放任意持久状态迁移、认证替换、模型循环替换或常驻后台回调；这些需要各自明确的合同和迁移设计。

| 插件 | 可增加的专项能力 | 使用示例 |
| --- | --- | --- |
| 日志诊断 | 读取已有日志与任务记录，整理错误时间线、重试和耗时分布；不接管日志事实源 | `/plugins@logs analyze --path ./logs --level error` |
| 表格增强 | 复用表格库进行多表合并、去重、公式检查和导出，减少重复编写处理程序 | `/plugins@sheet merge a.xlsx b.xlsx --key 订单号` |
| 文档增强 | 提取扫描文档文字、比较文档版本、套用导出模板 | `/plugins@docs diff a.docx b.docx` |
| 网页采集 | 提供专用浏览器执行器或提取工具，输出结构化数据和来源 | 正常聊天：“整理这些页面的标题和链接”；显式入口为 `/plugins@web` |
| 桌面应用适配 | 为特定应用提供可选自动化适配，与既有 Computer Use 权限和结果记录衔接 | 正常聊天：“把结果填进当前表单，提交前停下”；显式入口为 `/plugins@desktop` |

| 测试机诊断 | 通过已授权连接读取资源状态、服务状态和日志，复用原执行/归属协议 | `/plugins@server status --target testbox` |

一个插件可以同时带命令、工具和 Skill；启用后也可以正常用中文提出需求，由模型调用获准工具，用户不必记住 slash 名称。
基础文件、终端、会话和任务能力继续保留；上述增强不要求先从核心移除既有能力。
例如卸载表格插件会撤销其专用工具和依赖进程，已有表格文件保留，普通对话与基础文件/终端工作仍可进行。
这些例子只属于插件内容层，不在通用生命周期、任务状态或恢复代码里增加相应业务特判。

## 执行与版本

推荐可装卸的 Python 工具运行在独立进程，以现有 MCP/工具执行链承接调用。
插件依赖装入独立、按版本固定的环境，不写 Gateway 的 Python 环境；仍然每台机器一个 Gateway。
首个贯通样例使用本地已构建包，远程来源、源码构建与分发渠道后续单列，不先做插件市场。
进程隔离可以隔离常见阻塞、崩溃和依赖冲突，但不是文件/网络安全沙箱；执行权限和宿主资源限制仍需真实落实。
不能把第三方自称“只读”的 manifest 当成安全保证，也不能只靠杀父进程声称后代全部退出。
调用并发、输出和等待必须有界；资源限制按平台实际能力验证，避免独立进程仍耗尽核心需要的宿主资源。

已有进程内插件保持现行明确启动配置；它们不自动获得可热卸载承诺。
不用 `importlib.reload` 实现生产热升级：外部引用、既有实例及并发执行不会自动统一切换。
有需要常驻核心的受信扩展可以继续要求重启；优先让命令、工具和 Skill 这些外围能力可装卸。

拟议的最小描述包括：稳定插件 ID、版本、API 兼容范围、包摘要、执行入口、依赖、命令/工具/Skill 声明、设置及资源清单。
安装及激活记录只有一个权威来源；Gateway 工具目录、TUI 补全和能力搜索均为其权限过滤后的投影。
描述中的权限/effect 是申请与声明，最终授权仍由 owner 策略及具体操作审批决定。
管理范围按 owner 明确隔离；共享启用必须由管理员显式声明，不能因某个会话启用而影响其他 owner。

## 生命周期与卡死卸载

安装状态、期望启用状态、实际可用状态分别记录，不能用单个 enabled 布尔值掩盖“已装但启动失败”。
操作带唯一 operation ID、目标插件及代次，重复操作幂等；不通过自然语言描述推断操作完成。

1. 安装候选版本并校验依赖、声明和兼容性；安装默认不启用，不接入当前模型上下文。
2. 启用时准备候选执行端点，校验目录、命名冲突及健康，再原子发布同代命令/工具/Skill 引用。
3. 升级失败保留当前有效版本并报告候选失败。显式新启用失败则保持不可用；不伪装成功或偷偷换成其他实现。
4. 升级成功后新工作片使用新代次，旧调用绑定原版本和端点；旧版本无引用后回收。长任务恢复必须沿保存的绑定或显式报告版本不可用。
5. 停用先持久化撤销意图，使新调用、重连、自动恢复和后台唤醒都不能重新激活该插件，再移除当前目录贡献。
6. 旧快照也须在工具执行门检查撤销；停用后不得以“快照里还有”启动下一次调用。在途调用先协作取消，超过期限再终止插件专属执行资源。
7. 卸载继承停用流程，待引用和资源退出后删除包及版本环境；失败保留实际状态，可重试清理，不自动重新启用。

插件自有数据目录（第 10 步实施）：每个 owner 下每个插件 ID 固定一处 `<owner>/data/plugins/data/<插件ID>`，
由宿主在启动插件进程前以 no-follow 方式创建，经环境变量 `MY_AGENT_PLUGIN_DATA_DIR` 传入；包不能声明或改写该路径。
它跨版本更新、停用和重新启用保留；卸载只删除包与版本环境，不清这个目录（重装同 ID 插件会看到原数据）。
清理插件数据需要单独、明确的范围选择，当前未提供该命令。它不是 OS 沙箱，写工作区仍须走写入上下文。

随包 Skill（第 10 步实施）：包描述 v3 在 v2 基础上增加 `skills` 名单（面板可为空）；Skill 文件放在入口包的
`skills/<名称>/SKILL.md`，随插件 wheel 一起经哈希校验安装，构建期要求 wheel 内 Skill 目录与名单完全一致。
插件启用（激活 phase=active）期间，宿主把该激活环境里的这个目录作为来源 `plugin:<插件ID>` 的 Skill 根，排在
工作区、用户、共享、内置之后，优先级最低，不能覆盖同名 Skill；受 Skill 总闸控制，但不受旧的来源名单限制
（插件启用本身就是显式授权）。停用、卸载或换代后，下一次 Skill 快照不再包含它；当前回合已冻结的快照保持不变。

注册、进程、连接、定时器和订阅均带插件/代次/owner 归属，调用资源继续带原 run/attempt 身份。
插件调用的撤销返回结构化结果，不等于停止整个会话或父任务；依赖该能力的后续工作沿原模型/调度链处理不可用事实。
宿主管理可幂等、逆序清理注册句柄；不能依赖卡死插件自己运行完 shutdown 才释放入口。
管理路径有独立的执行与超时边界，不与插件阻塞调用共用一条必须等完的链。
资源终止沿现有精确身份与进程树原语，不按进程名称批量杀掉其他会话；未确认退出必须显示清理未完成。
关闭其中一个插件不能调用“关闭全部 MCP 客户端”代替精确清理。

核心管理入口不能被插件覆盖或卸载。可选插件失败要隔离到其贡献；显式依赖它的能力显示不可用，不能无提示地继续。
现行管理员启动插件的 fail-closed 行为仍然有效；迁入新协议须明确标注角色、依赖和失败策略，不能顺手放宽。

## 命令与安装使用方式

### 从安装完成到真正可用

安装只是保存包；配置齐全、授权满足、成功激活后，插件贡献才进入当前作用域的可用目录。
管理界面必须区分“已安装未启用”“待配置”“已启用”“启用失败”“清理未完成”；不能把安装命令退出成功显示成能力已经可用。
这些是底层安装、期望状态和实际状态的展示组合，不再另存一套 UI 状态权威。
用户可以先安装，也可以明确选择“安装并启用”；即使合成一个操作，两个阶段的结果仍分别记录。

启用成功后展示简短的使用卡：能做什么、从哪里进入、两条普通中文示例、必要设置，以及停用/卸载入口。
第 5 步按现有 `PluginManifest` 的摘要、动作参数与设置 schema 生成这张卡；`/plugins info <ID>` 和成功启用回执复用同一投影，普通中文示例由公开动作描述组成，不执行模型或插件代码。当前 `PluginCommandCatalog` 的作用域与 revision 仍只负责发现和旧选择拒绝，不增设卡片缓存或持久状态；列表显示原声明简介，帮助和补全继续消费原声明，动作用法与使用卡共用参数格式化。已实现的 `/plugins@` 不再在顶层 `/help` 标为未开放。此段已本地实现，仍待发布和新版原生 TUI 验收。
能力发现和调用路径应明确区分：

| 插件贡献 | 用户如何使用 | 核心如何连接 |
| --- | --- | --- |
| 工具 | 直接用普通中文提出需求；也可从工具目录点选或显式指定工具 | 沿现有能力搜索、ToolRegistry、权限及执行账本；模型看到名称、用途和参数，具体调用仍由模型决定 |
| 命令 | 输入 `/plugins@插件ID`，通过补全选择动作和参数 | 从同一动作描述生成帮助、补全和分发；插件命令统一在各自命名空间内，不扩散顶层 slash 命令 |
| Skill | 显式选择方法，或由模型按需读取 | 继续使用现有 Skill 索引/快照，启用不等于将全文常驻系统提示；Skill 本身不授予执行能力 |
| 设置与展示 | 在 `/plugins` 中配置、看状态或打开插件提供的入口 | 首期由核心按声明渲染设置表单、状态和操作项；后续富界面再约定展示槽位，不向 TUI 注入任意插件 Python |
| 事件响应 | 用户启用相应行为后，在任务完成等指定时机生效 | 后续从既有结构化事件发布只读订阅，具备作用域、超时与撤销；不先开放任意核心状态拦截或常驻回调 |

“模型能找到插件”依赖真实可见工具目录和按需说明，不靠在 prompt 中追加一句“你现在有某插件”。
“看得到”也不代表无条件执行：所需连接/依赖、当前作用域、权限与撤销状态仍由现有执行门检查。

以自有表格插件为例：插件 ID 为 `sheet`，声明 `merge` 动作、`sheet.merge` 工具和一份处理 Skill；启用后用户既可说“把三个表按订单号合并”，
也可输入 `/plugins@sheet` 选择操作。完整参数可直接调用工具；中文需求则进入正常模型任务准备参数。
这些入口最终执行同一个工具实现、同一份权限与取消协议，不分别维护“命令版”和“模型版”业务代码。
停用后快捷命令、能力索引、Skill 注入与设置之外的运行入口一起撤销；核心管理页继续提供诊断和卸载。

采用用户提出的主入口：`/plugins <管理动作>` 管理插件，`/plugins@<插件ID> [动作] [参数]` 使用插件。

TUI 的 `/plugins` 面板是主要入口，支持补全和选择，不要求用户记全套子命令。
完整形式的管理命令与面板动作共用同一管理接口；管理子命令不能与插件业务动作混在同一层。
管理操作本身不需要 LLM；调用授权沿现有权限门，不让模型猜测一段话是否等于安装授权。
一般只删除插件包/缓存，保留用户产物、历史和审计；清理插件持久数据必须另行明确选择范围。
卸载不是暂停 Goal，也不是中断整个会话或停止其他任务资源。

`@` 后使用稳定、唯一的插件 ID；展示名可以中文，补全同时显示 ID 与用途，不用展示名称猜执行目标。
不同插件可以都拥有 `run`、`check` 等动作；一个插件内的动作名必须唯一，并声明工具/模型任务/展示等执行类型和目标。
第一版只保留上述插件命名空间，不再引入 `/sheet`、`/logs` 或 `/tool` 作为另一套入口；这些此前只是未实施的例子。
核心 `/stop`、`/interrupt`、`/goal` 等保持原语义，插件不能覆盖或重新解释它们。
命令目录只设一个权威注册入口，整合现有控制解析与 TUI 静态目录；帮助、补全、可见性和分发共用声明。
TUI 从 Gateway 获取 owner 可见的版本化目录，不导入插件 Python；版本过期的选择返回刷新事实，不执行错目标。
命令描述显式区分管理控制、工具调用和模型任务；插件有副作用的命令仍经原工具执行/审批/账本，不另开绕过通道。
普通中文聊天继续可由模型选择获准工具；显式插件命令只在所选动作声明为模型任务时进入模型，不能因参数错误自动转成聊天。
参数已完整的显式调用可以直接走同一工具执行链；附件仍用现有可信回执，不用展示文字授予路径权限。

参数约定：

- 支持子命令、位置参数、短选项和长选项，例如 `-n 20`、`--limit 20`、`--limit=20`；类型、默认值、必填、重复与多值规则来自动作声明。
- `-abc` 只有在 a/b/c 均为已声明的无值短开关时才展开；有值参数使用明确的独立值，不模糊猜测 `-xx` 是长参数还是组合开关。
- 单动作插件可以显式声明默认动作，支持 `/plugins@插件ID -参数`；无参数默认显示帮助/操作菜单，不隐式执行业务。
- `-h` / `--help` 为保留帮助选项，`--` 结束选项解析；含空格的参数支持引号，跨平台路径与转义规则统一验证。
- 这是聊天应用自己的命令语法，不交给系统 Shell；不执行管道、重定向、变量替换或命令替换。引号中的这些字符仅作为参数数据。
- 帮助由静态声明生成，不导入/启动插件实现，不消耗模型调用；已安装但停用的插件仍能查帮助和设置，业务执行明确返回不可用。
- 未知插件、未知动作、缺值和未知参数返回结构化错误及准确用法；不自动安装、不自动启用，也不把整段误投给 LLM。

补全按输入位置逐级进行：`/plugins` 后补管理动作与目标；`/plugins@` 后补已启用插件；插件后补动作，再按 schema 补选项、值与允许的路径。
停用插件仍在管理列表中显示，显式输入其 ID 可查静态帮助；卸载后清除其已安装元数据和补全项，历史记录仍保留。
补全选择只填入输入框，不触发安装或执行；插件前缀中的 `@` 不得误触发已有的文件引用/路径补全。

命名空间首片在公共目录识别 `/plugins` 与 `/plugins@`；参数次片已补结构化插件 ID、动作、参数与同源候选，见下文。
后续仍须经宿主绑定身份、校验当前目录与分发；不能只修改 TUI 展示或将原始字符串交给 Shell。
TUI、plain 和 Gateway 共享同一判据；形似命令但缺插件 ID 等输入也要按插件语法报错，不能因现有正则未匹配而进入模型。

### 第 3 步参数声明与解析

状态：参数与补全修复已发布同版双机；TUI 146 已复验 Tab 后正常 Enter，两端各 13 类命令检查通过，143 原失败保留。
483 项相关回归和严格 gate 通过；150 已验活动请求中的静态分流，同一 attempt 自然完成，无模型插话或 Shell 副作用。
普通任务、校验器限制及活动首秒的覆盖边界见 TESTS，不代表动态目录、调用权限或装卸已实现。

公共目录继续拥有核心命令名称和插件管理动作；新增的参数声明直接驱动校验、静态帮助与补全。
核心自由正文不经过 argv 解析。插件命令先识别命名空间，再进行词法切分、动作选择和参数绑定；
成功解析只产生结构化请求，不代表已授权或已经执行。owner/thread/run 等身份由后续宿主执行链绑定，不能从参数注入。

词法沿标准库 `shlex`，关闭注释与反斜杠转义：单双引号包住空格，允许相邻片段连接，反斜杠始终原样传递。
因此 Windows、UNC 和以反斜杠结尾的路径不会被改写；需要字面引号时使用另一种引号包住它。
不支持用反斜杠转义空格或引号，不执行变量、命令替换、管道或重定向。特殊字符只作为参数数据，由声明决定是否接受。
完整命令的未闭合引号报错，不能退回简单 split；补全使用同一词法的未完成输入模式，不把半段输入当成可执行请求。
参数间接受 Unicode 空白，引用内原样保留；引用 `"-x"` 或 `"--"` 不会取消选项含义，字面位置值须写在 `--` 之后。
稳定插件 ID 为 1—64 位英文字母开头的字母、数字、点、下划线或横线，保留大小写；展示名称不参与查找。

参数声明包含位置或显式长短选项、值类型、默认值、必填、多值及 choices。重复选项仅在声明允许多值时接收；
同一长短别名算同一参数。短组合只接受全部无值旗标，有值短参数必须单独给值；`--` 后均按位置参数处理。
带负号的字符串选项值使用 `--name=-x`；数值类型可以单独接负数。布尔旗标不声明 choices。
帮助选项为保留的 `-h/--help`，作为选项出现时可以省略业务必填参数；出现在 `--` 后只是普通数据。
未知选项、非法类型、缺值、多余位置参数和重复项均返回明确的结构化原因与当前动作的准确用法。

插件贡献仅以宿主提供的只读描述集进入解析、帮助和补全，不在解析层增加安装表、持久状态或代码加载入口。
本片的管理帮助可用；安装、启停、卸载和插件业务执行继续明确返回未开放，完整装卸在第 4 步实现。
尚未实现的动作不作为可执行候选展示，但用户可显式查看其参数帮助。动态 owner 目录、代次刷新与调用授权仍需和生命周期接线后验收，不能以纯解析通过代替。
实现分为 `command_arguments.py` 的不可变合同/词法、`command_binding.py` 的绑定/帮助、
`plugin_commands.py` 的命名空间/静态回执及 `plugin_completion.py` 的候选投影。原笼统的插件不可用文案分支已删除。
CLI 和 HTTP 都消费公共回执；旧控制枚举未增加插件类型，原始插件输入仍禁止进入 Gateway 普通文件队列。
补全保留已输入前文，仅替换当前参数；光标位于参数中间时暂不显示插件候选，避免破坏光标后正文。
候选再经公共绑定器确认确实落到预期参数；默认动作首个位置值、负号值与停用插件均有明确边界。
自动补全只提示未完成名称或已进入的参数，不在完整输入后自动补可选旗标；显式 Tab 可继续发现可选候选。
接受候选只填入，下一次 Enter 在没有未完成输入时提交原命令；`help install` 不得被补成 `help install -h`。

参考边界：本地 Codex `578c1b2230288104041e880a86d0f7f3a5ca6e47` 的 `slash_command.rs`、`prompt_args.rs`、
composer `slash_input.rs` 和分派局部保留 slash 后自由正文；Hermes `0a62610f10cc34d696b2239b2c69fa1ba0f1ca63`
的 `commands.py`、`completion.py` 与 `cli_commands_mixin.py` 局部使用默认 shlex 并在失败后退回 split，
本项目不沿用该词法降级。现有参考补全主要覆盖名称和简单子命令前缀，没有可直接复用的完整参数解析器。
先核对两份合同索引及模块索引：合同检索无命中，模块索引分别有 9/4 条匹配；仅用于定位，不视为全库审阅。
跨平台路径、未完成引号、短组合、`--`、help 和多值通过合同用例固定，再经实际 TUI 验公共入口与隔离。

  候选携带原 revision，接受候选后手工编辑或继续 Tab 补全参数仍沿首次选择的版本，清空/离开命名空间才解除绑定。
  补全和命令的网络工作离开输入事件线程，目录不可用时不能回退到本地旧目录或普通聊天。
  普通核心命令维持现有分派。plain+Gateway 同样以显式 `use_gateway` 选择远端宿主，不能按是否完整 Agent 猜本地模式。
- HTTP `/ask`、`/control` 的插件命名空间也应用同一宿主目录；只读帮助允许直接读取当前目录，业务请求须携带 revision。
  旧文件消息队列继续拒绝插件原文，不新增 ControlKind，也不利用旧控制的默认停止分支。

本片不为目录读取增加配置开关：仅响应显式插件命令或 Tab，不增加启动请求、模型上下文、长期写入或后台轮询。
冷 owner、跨 owner、伪造正文身份、旧目录提交、过期异步响应及客户端离线先用合同/HTTP/客户端替身验证，再做真实 TUI。
构造客户端不读目录，异步响应按原 owner、会话、模式、端口及请求先后核对，较早的结果不能覆盖新缓存。
Ctrl-S 和取消 Ctrl-R 沿原 `TuiDraft` 保存/恢复候选版本；提交清空显式移除绑定，不能依赖 Buffer.reset 发出正文事件。
动态安装、实际激活版本的撤销和在途工具取消仍由第 4—6 步验收，不能用空目录或摘要校验代替。

参考核对：Codex `578c1b2` 的 `tui/src/app/background_requests.rs`、`chatwidget/plugins.rs`、
`app-server/src/request_processors/plugins.rs`、`effective_plugin_change.rs` 和 `protocol/v2/plugin.rs`。
借鉴宿主身份、声明投影和异步结果复核作用域；其列表协议没有整体目录 revision，列表还可能刷新远端缓存，不能照搬为纯读取。
Hermes `0a62610` 的 `hermes_cli/plugins.py`、relay command manifest/transport 与 authz 入口采用进程内发现或静态镜像，
没有可直接套用的 owner 版本目录；帮助触发发现/导入、全局清表也不沿用。索引仅作定位，未运行两者测试或审阅完整安装/认证链。

### 对结构拆分的直接要求

1. 插件描述集中声明身份、配置 schema、能力贡献与使用说明；插件作者只写描述和自己的实现，不修改核心帮助表、解析器或模型循环。
2. 同一份有效贡献集驱动模型可见能力与 TUI 发现；继续复用既有工具/Skill 注册，不复制一个“插件专用执行器”或历史库。
3. 命令描述明确指向管理操作、工具或模型任务；TUI 只消费公开目录和结构化结果，业务处理由宿主原执行链负责。
4. 插件宿主持有执行进程、注册、连接和订阅的撤销句柄；管理路径独立于业务调用，候选版本验证完成后才发布。
5. 首个插件交付贯通“安装 → 必要配置 → 启用 → 发现 → 中文/显式调用 → 停用/卸载”，更新/回退和更丰富展示随后按批落实。

上述是拆分时需要的接口职责，不要求一个职责机械拆成一个类/服务，也不先制造大型 SDK、市场或全能事件总线。

### 第 3 步首片接线与实现边界

`request_execution.py` 的旧队列拒绝，不能只改可见 TUI。

第一片先统一无 UI 依赖的声明与分类、帮助及静态补全来源，保持原控制执行、权限和回执链；

不提前显示可安装、可启用或可执行。实现前还须核对对应成熟参考源码，并固定现有别名和自由正文的兼容范围。

原控制类型、持久回执及 Goal/Audit 正文解释保持原位，不新增可落入旧停止分支的插件控制类型。
`/plugins` 和 `/plugins@` 前缀（包括缺 ID、异常 ID）必须在所有入口明确拒绝；这一片只预留命名空间，

## 实施顺序与验收

整体实施顺序统一维护在 [拆清依赖与插件的合并计划](MAINTAINABILITY_AND_JEV_REVIEW.md#下一轮结构整理顺序待实施)，
本文维护插件合同与验收，不另设一套重构排期。先明确边界、拆开后台调度依赖，再按第 3—6 步完成首批插件交付：

- 公共命令声明与解析：`/plugins` 和 `/plugins@ID` 转为结构化请求，明确参数、帮助和分发类型。
- 最小装卸链：显式本地包安装、配置、启用、隔离进程、版本与贡献绑定、停用及卸载。
- TUI 使用链：动态目录、逐级补全、静态帮助和使用卡；显式命令与普通中文调用都复用原执行与权限链。
- 故障与长任务验收：管理和业务执行互不阻塞；精确撤销、清理及重连抑制经实际 TUI 验证。

首个示例使用标准库实现只读功能，不为其业务在核心增加特判。安装默认不启用，帮助不执行插件代码；
宿主进程与依赖隔离、注册所有权、实现代次和有界撤销必须首批具备。
在线来源安装、更复杂的依赖解析、更新/回退及丰富展示在首批贯通后另行实施；未实现动作不显示为可用。
第 3—6 步全部验收前，只能报告各片进展，不能把命令补全可用等同整个插件系统可用。
合并计划第 9 步保留剩余 TUI 整理，增加有限展示描述与可撤销只读订阅；第 10 步增加
[约 10 个简易插件的样本验收](PLUGIN_SAMPLE_ACCEPTANCE.md)。Audit/摄取重构已移出本轮，不是插件交付前置条件。
样本均使用本项目 Python 接口；第一个只读包优先选 workspace-peek，纳入同一批样本，不另造平行演示链。

开发反馈沿合同、替身及回放；真实验收只走实际 TUI，常规使用官方 MiniMax-M2.7，视觉使用同密钥引用的 MiniMax-M3。
核对 provider/端点与实际模型，每台机器共用单 Gateway；逐批详细矩阵见 [执行 Goal](../tasks/REFACTOR_PLUGIN_GOAL.md)。
拟议并发矩阵：A 运行带插件调用的长任务，B 运行正常内置任务，C 管理插件启停/卸载；升级/回退在实现后的专项轮次加入。
测试者只提交需求、执行明确的用户管理控制并观察，不代写被测任务文件、不旁路调用模型代替 TUI。
每轮公布实际 TUI 编号、tmux 名称与查看方式；编号由真实创建结果产生，不能提前编造。

必须核对：

- 缺省未安装、已装停用、启用、卸载四种状态：停用前后内置有效能力/模型配置等价；用同输入的新基线会话核对，过滤临时 ID 后提示和工具目录不混入插件内容，旧会话的真实调用历史不要求消失。
- 插件启动失败、调用卡死、卸载清理失败：管理入口可用，B 正常，Gateway 无需重启，无遗留重试或自动复活。
- 开始/执行/结束事实绑定同一实现代次；旧任务恢复、权限撤销、依赖不可用与版本切换不得静默混用。
- 命令、工具、Skill 和搜索投影一致撤销，旧快照无法继续调用；插件资源退出有证据，用户文件及核心历史保留。
- 启用成功卡能说明用法；待配置与启用失败不会误显可用；通过中文需求、显式命令和完整参数进入时，共用同一工具与权限账本。
- `/plugins` 管理与 `/plugins@ID` 调用分流一致；帮助、补全及 schema 同源；未知/停用目标、缺值、重复选项、组合短开关、引号、`--` 与跨平台路径均不误执行或落入聊天。
- 两个 owner 的注册/调用/管理隔离，命令冲突、重复操作及失败后重试可解释；升级回退保留外部已发生事实。

本轮仅记录方案，未进行上述插件真实验收，现有 TUI 通过记录不能替代它。

对 my-agent 的取舍仍是提案，未更改实施状态：

- 浏览器流程和桌面/数据库适配适合作为独立执行能力；保留现有工具权限、真实副作用记录和精确资源归属。
- 回答复核与上下文消融适合作为可选诊断；质量分数不成为完成、权限或状态硬门，额外调用和自动续跑应显式配置。

### 安装后交互机制的官方核对

- [插件管理页面](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-plugin-manager/README.md)：
  Web 安装完成提供立即启用选项，关闭则保持已装停用；安装成功不保证激活成功，配置页由插件向公开槽位注册。
- [命令注册](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/interaction/commands/README.md)：
  描述进入可发现目录，注册/撤销通知界面刷新；普通命令和结果不自动进入模型消息，生产方可以显式发起模型工作。
- [工具教程](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/tool.zh.md)：
  插件向公共 tools 服务注册 schema 和执行函数，用户在对话里要求使用后，由模型发出调用并消费工具结果。
- [扩展形态映射](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/extension-cookbook.zh.md)：
  工具、UI、Skill、事件、模型适配等分别使用对应扩展点，不能推导出“所有插件装完都有一个 slash 命令”。
- [插件教程](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/index.zh.md)：
  通过上下文登记的贡献随插件卸载清理，外部资源须登记清理函数；命令取消仍受 handler 协作边界约束。

本次只借鉴交互与注册/撤销机制；现有 my-agent 的 `register_commands` 实际接 argparse，TUI 仍是静态目录，
所以动态命令发现和安装后使用卡仍需开发，不能称为已有功能。
