# AGENTS.md 归属、指向与自动学习分离

状态：**设计已定（用户 2026-10-08 拍板），第 0 期实施中，第 1 期待实施**。本文是这一主题的唯一权威设计；`DESIGN_LEDGER.md` 只保留摘要和链接。

## 1. 背景（结构化事实，2026-10-08）

- owner `local/main` 的 `AGENTS.md` 有 170KB、489 条。其中 475 条由 memory-promotion 自动写入，13 条由 `update_persona` 工具写入，1 条是基线。
- **10-07 一天自动加了 246 条，10-08 加了 191 条**，以前每天 0–13 条。
  - 437 条全部是 `auto_eligible`，430 条被标成 `user_explicit`。
  - 来源只有 9 个线程，全是开发派活会话（ds1–ds8、mc3）：派活任务书以"用户消息"的形式输入工人 TUI，被当成了用户本人说的长期工作约定。
- 根源有两点：
  1. 程序把 AGENTS 设计成"模型可以自主维护"，自动晋升不需要确认（`promotion.py` 的 `_commit_persona` 和 `_absolute_authority_block`）；
  2. 会话没有"是否参与学习"的结构化来源标记。
- 注入时每个人格文件预算 2 万字符，取开头 75% 和结尾 25%（`persona_repository._bounded_prompt_content`），中间看不到；结尾现在全是开发纪律。文件硬上限 2MB，到了会写入失败。
- 对照主流产品（Claude Code、Codex、Gemini CLI、Cursor、Copilot、Hermes、OpenClaw、ChatGPT），共同做法是：
  - 指令文件归人写；
  - 自动记忆另存，可以查看和删除；
  - 子代理、定时、后台、外部内容不学，来源不明的不算用户说的；
  - 写入时有硬上限；
  - 满了就合并、替换或过期淘汰，保留出处和旧版本。

## 2. 用户决定（2026-10-08，要点）

1. **AGENTS.md 只能由用户写**。不同用户只能改自己的；管理员在完全访问模式下有权限，但不动别人的。
   - 用户可以配置自己的 AGENTS.md **指向哪个文件**，自己改或让 my-agent 改都行；默认是自己的。
   - 可以指向本地文件，也可以指向网络文件，但必须有权限，不能越权。重点是多用户隔离。
2. 自动学到的内容另放一处，参考 Codex 和 Claude Code：重复或相似的直接合并或更新。
3. 子代理可以学，但要打标签；其它自动化来源（派活、定时、后台等）不学。
4. 写入时有硬上限。
5. 清理已经误加的条目：先留快照，再移到归档；可以检索，但不注入。

## 3. 目标设计

### 3.1 指令文件归属与隔离

- 写 AGENTS.md 只有两个入口：
  1. 用户直接编辑；
  2. 用户在**当前回合直接发出的请求**里让 my-agent 用 `update_persona` 改。
- 记忆整理（curator）、后台任务、定时任务、子代理、派活会话**一律不能写**。由程序硬拦：自动晋升路径直接拒绝 `agents` 目标。
- 写入身份只取运行时的规范 owner（runner 上下文），**不接受参数里的 owner**。参数和上下文冲突时拒绝，并给出 `scope_resolution` 和 `scope_warnings` 这类结构化事实。
- 管理员（admin）在 Full Access 模式下可以对别的 owner 操作，但必须显式写出目标 owner，并且记审计。任何隐式路径（默认 owner、会话推断）都不能落到别人的文件上。

### 3.2 指向配置（第 1 期）

- 每个 owner 有一条结构化配置 `agents_source`：`{kind: "owner_default" | "local_path" | "url", value, updated_by, updated_at}`。默认是 `owner_default`，也就是 owner home 下的 `AGENTS.md`。
- **本地路径**：
  - 读取前按该 owner 的路径权限裁决（复用 path access 和 owner scope 的同一套判定）；
  - 解析真实路径防符号链接和路径穿越，按 inode 防 TOCTOU；
  - 不能指向其它 owner 的 home、运行时目录或密钥目录；
  - 只读来源，`update_persona` 要拒绝写入，并给出结构化原因。
- **网络地址**：
  - 只允许 https；按该 owner 的网络权限裁决；走系统代理；
  - 有大小上限和超时；禁止指向内网和本机地址（防 SSRF）；
  - 内容要过现有的注入扫描；
  - 成功后缓存在 owner 自己的目录。拉取失败时用上一次成功的缓存，并给出结构化诊断，**不能静默变成空**。
- 配置入口：TUI 命令、飞书命令，以及让 my-agent 用工具修改（仅限当前 owner、当前回合由用户直接发起）。每次修改都记版本。
- 指向变化之后，按现有的冻结人格机制在下一次刷新点生效，不能把每一轮都改成缓存不命中。

### 3.3 自动学到的约定另存（第 1 期）

- curator 识别出的 `working_agreement` 不再进 AGENTS.md，改进**现有的长期记忆**，类型是工作约定。不另建一套权威。
- 写入前先和已有条目比对：重复或相似的直接合并或替换，保留出处（来源会话、消息引用）和旧版本，可以单条撤回。
- 注入有独立预算，并且有索引上限（参考 Claude Code：200 行或 25KB 量级），按最近使用或命中排序；快满时先合并再写。

### 3.4 学习来源标记

- 会话在创建时就带上结构化的学习来源字段（会话类型和是否参与学习）：
  - 用户本人的会话：学；
  - 子代理：学，但条目标记 `source=subagent`；
  - 派活工人会话、定时任务、后台任务、外部内容：不学。
- 已有的会话可以用命令改标记，或者写进 owner 的排除名单。
- curator 先看标记，再读对话。**来源不明的一律不算 `user_explicit`**。不靠解析消息正文判断来源。

### 3.5 上限

- AGENTS.md 写入后的字符数不能超过注入预算（2 万字符）。超了就在写入时拒绝，并给出结构化错误。截断只当兜底，不再当常态。
- 学习库同样设硬上限，写入时检查。

### 3.6 清理迁移（第 0 期）

- 先给 AGENTS.md、`persona/versions.jsonl`、候选账本做快照，放进 owner 自己的备份目录。
- 按版本记录里的 `source` 前缀（`memory-promotion:`）和 `entry_id`，找出**仍在文件里**的自动条目，通过 PersonaRepository 的结构化删除逐条移出（CAS，生成新版本，`source` 标成迁移编号）。
- 移出的条目连同出处（entry_id、candidate_id、来源会话、原版本）写进归档：可以检索，但不注入提示词。
- 来源会话写进学习排除名单。名单是数据，运行迁移时传入，**不写死在代码里**。
- 写一条结构化迁移记录（迁移编号、计数、快照位置、排除的会话）。迁移要求幂等，可以先空跑（dry-run）。
- 生产上执行前，必须先在 pytest 隔离 HOME 里用生产数据副本演练，再先空跑、后执行。

## 5. 风险与必测点

- **越权**：
  - 跨 owner 写；
  - 参数里的 owner 冒充当前 owner；
  - 符号链接或 `..` 指向别人的 home；
  - 检查和打开之间被替换（TOCTOU）；
  - 管理员隐式写到别人那里。
- **网络**：SSRF（内网、本机、重定向绕过）、超大内容、注入内容、拉取失败时静默变空。
- **记忆连贯**：迁移不能丢用户本人写的条目，能从快照完整恢复；待定候选不能因为硬拦而丢失。
- **缓存**：指向或内容变化只在冻结刷新点生效，不能让每轮的固定前缀都变。
