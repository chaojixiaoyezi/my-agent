# TUI 交互与实现规范

## 目标与边界

终端界面使用 Python 与 prompt_toolkit；结构化事件、会话和工具执行仍来自唯一 Gateway/ToolRuntime。界面不解析正文来判断任务完成、权限或恢复，不建立第二份执行事实源。

## 布局

- 上方为可滚动的用户消息、助手正文、思考、工具调用及结果；按真实事件顺序排布。
- 主代理活动行位于消息区底部、Context 与任务清单上方；不要与子代理汇总重复显示两个 Working。
- Context 区显示当前输入估算/容量、占比、已提交压缩次数和压缩阈值。当前上下文与累计消耗分开。
- Context 下一行固定模型统计：本次工作片的逻辑模型轮、当轮已解析工具数、最近结算缓存比例、当前代理会话累计 token；宽屏补充最近输出速度与输入/输出分项。空值显示 `—`，窄屏按宽度简写，不挤出多行。
- Todo 默认最多四条，保留最近完成、正在执行和下一条；Ctrl+T 展开全部。动画只对应运行中项。
- 输入框下为直属子代理列表：短职责、状态、耗时、当前上下文 token、压缩次数；按行宽截断。

## 消息与样式

用户行突出显示。助手正文使用普通正文颜色，插话回复不能被并入灰色思考。思考结束默认折叠；标签与展开提示使用同一弱化语义色。工具块显示脱敏参数、结果、失败原因和可展开原文；文件写入/修改展示结构化差异。

每个活动块有稳定 event_id/block_id/seq，更新只影响对应块；工具之后的新思考不能追加到之前的思考块。终态只冻结一次，重复或乱序事件不重复正文。

## 输入与导航

- 多行、宽字符、组合字符与 bracketed paste 按终端显示宽度处理。粘贴完成前不能误提交半条消息。
- 用户滚离底部后不强制跟随；回到底部恢复跟随。Ctrl+End/“回到最新”直接回底部。
- Ctrl+O 进入/退出详细阅读，Ctrl+E 切完整原文分页；长输出来自归档，不仅解除前端截断。
- 下键选中子代理、Enter 进入；隐藏项选中时须自动滚入可见范围。
- 子代理视角展示初始任务、思考、正文、工具和输入队列。Ctrl+G 返回父代理；Esc 停止当前查看的运行中代理，不能兼作退出视角。
- 运行中插话使用稳定消息 ID、持久 outbox 和消费事件。已消费的消息不能仍提示待发送，也不能超时后换 ID 重发。
- 鼠标滚动和选择复制应共存。F6 的宿主原生复制备用模式必须明确提示如何恢复应用滚轮；不能让用户误以为历史丢失。
- Ctrl+C 有选区时优先复制，无选区时才处理停止/退出。远程剪贴板失败必须如实提示，tmux 缓冲区成功不等于本机剪贴板成功。

## 运行与恢复

界面线程只消费不可变快照和输入意图；网络、历史分页、用量扫描和模型等待不能阻塞输入线程。历史采用有界视图、稳定锚点与归档引用，空闲刷新不能重排全部长文本。

启动显示真实连接状态，就绪后才启动工作线程。等待授权、等待子代理、等待模型和重连分状态展示；慢模型保持活跃不等于界面忙循环。退出客户端、tmux 断开和停止任务是不同操作，均走既有控制协议。

## 实现入口

- `agent_py_agent/cli/chat_parts/tui_events.py`、`tui_view_model.py`：事件信封和 reducer。
- `tui_runtime.py`、`tui_threading.py`：Gateway 事件投影与线程边界。
- `tui_view.py`、`tui_block_renderer.py`、`tui_markdown.py`：布局、缓存、样式和宽字符渲染。
- `tui_input.py`、`tui_interaction.py`、`tui_keybindings.py`：输入、快捷键、滚动和控制。
- `tui_input_delivery.py`、`tui_clipboard.py`、`tui_history.py`：投递、剪贴板与异步历史读取。

## 模型统计口径

`conversation/model_metrics.py` 将 `ModelCallLedger` 的当前 request/run 聚合与会话已落账事件合并，
排除相同 request/run 的持久快照以免重复。会话基数每个工作片读一次，不在 UI 帧或逐 token 回调里扫历史。
独立压缩在自身成功、失败或中断后向同一用量账结算；已绑定普通 request 的压缩仍归该工作片收口，
不跨 source 重复计费。独立请求使用 operation 唯一身份，不复用同一压缩代际的失败尝试。
`ConversationThread.model_metrics` 只是最新数字投影，主/子代理按 exact thread 分开；压缩、滚屏和重新进入页面不清累计量。
该字段同时从完整和精简的模型上下文中排除，不改变缓存前缀、预算、权限和任务结束语义。

| 字段 | 含义与边界 |
|---|---|
| 本次模型轮 | 当前工作片账本中的逻辑模型调用，不是用户消息数或工具执行步数；同一次调用的重试另列，账本内的辅助模型调用也属于调用消耗 |
| 当轮工具 | 当前响应通过工具协议解析的调用条数，不是注册工具数量，也不是成功数；模型还没返回或解析失败时未知 |
| 最近缓存 | 最近完成模型调用的缓存读 token / 该调用总输入 token；缺报保持未知，不能通过速度推测 |
| 会话累计 | 当前代理会话既有调用与本次已结算调用的输入加输出，缓存输入已包含，不能加两次；不自动合并子代理消耗 |
| 估算与缺报 | 无供应商用量的调用单列估算，显示 `~` 和缺报数；进行中调用显示待结算，不伪造实时账单 |
| 最近输出速度 | exact call 的供应商输出 token / 首 token 到结束的耗时；不是包括排队和首字等待的吞吐率；无计时则不显示 |

连续工作片的模型轮数会重新计数，但会话累计不重置；这是不同口径，不是上下文丢失。
独立压缩结束后也刷新累计；没有原始响应可核对的最近缓存和速度保持未知，不延用上一轮伪装本轮。
Goal 区只显示 `ThreadGoal` 的真实记录。任务清单、模型口头说已创建目标，不能替代 `create_goal` 成功回执。

主代理和子代理视角各自展示本代理 Goal 与 Todo，不借用父级目标。每个代理最多一个未结束 Goal；
Todo 可选，沿用原有进度组件，条目未勾选不会阻止目标完成。
方向键选中 Goal 后 Enter 打开全文编辑。Ctrl+S 或“保存”才提交，Ctrl+G 或“放弃/退出”丢弃未保存内容。
Esc 始终停止当前代理，不承担关闭或保存职责。读取与保存异步执行，不冻结模型流或 TUI 绘制。
保存保留身份、用量与暂停状态。后台修改引起版本冲突时保留草稿；“读取最新”提供全文比较，仍需再次明确保存。
编辑器打开时禁用背后聊天快捷键，换行和光标移动留在文本框内；显示明确的版本冲突原因，窗口不随反馈文案缩窄。
