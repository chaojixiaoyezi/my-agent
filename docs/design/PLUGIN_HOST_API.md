# 插件宿主只读 API

状态：第 10 步本地实施（包描述 v4）。上位合同见 [可装卸插件方案](PLUGIN_LIFECYCLE.md)，与 [插件展示](PLUGIN_DISPLAY.md) 共用同一套公开投影。

## 解决问题

网页控制台、桌面窗口这类"界面型"插件需要持续读取宿主运行状态（活动、上下文、会话、插件），
但插件不能拿 owner 身份去调 Gateway 内部接口，也不能读宿主私有目录。展示面板只能被 TUI 轮询时拉取，
不适合插件自己的界面。这里给界面型插件一条受控的只读通道，让插件可以挂接各种形态的界面，而宿主只维护一个接口。

## 协议

- 包描述 v5 在 v4 基础上允许工具项声明 `observation` / `observation_ref`（观察候选，见[插件观察候选结构](PLUGIN_OBSERVATION_CANDIDATES.md)）；宿主 API 名单不变。
- 包描述 v4 在 v3 基础上增加 `host_api` 名单，目前只允许 `"read"`。只有声明了它的插件，启动时环境里才有
  `MY_AGENT_HOST_API_URL`（`http://127.0.0.1:<Gateway端口>/plugin-host/query`）与 `MY_AGENT_HOST_API_TOKEN`。
- 令牌在插件客户端构造时发放，绑定该插件激活；每个请求都复核激活仍是同一代，停用、卸载、换代或 Gateway 停止即失效，失效后不复活。
  直连模式（没有 Gateway HTTP 服务）不发放。
- 请求：`POST`，头 `X-Plugin-Host-Token`，正文 `{"topics": [...], "thread_id": "..."}`；只接受回环来源。
- 主题白名单：`threads`（最近 20 个线程的编号、截短标题、状态、更新时间、压缩代次）、`activity`（指定线程的
  activity/run_state/context，与面板主题同一投影）、`plugins`（插件 ID、版本、启用状态、简介）、`gateway`（进程号与端口）。
  owner 未加载时线程与活动为空并标注 `owner_loaded=false`，不为插件加载 owner 实例。

## 边界

只读：没有提交消息、审批、停止、配置或文件访问；不含消息正文、摘要、路径、设置或密钥。
插件把令牌放进自己的网页时必须留在服务端（浏览器只拿插件自己的会话令牌），不能把宿主令牌下发给浏览器。
将来如需写入或控制类权限，另加权限名并单独设计审批，不扩大 `"read"` 的含义。

## 样本

`plugins/harness-console`（本地，待发布）是首个使用本 API 的界面型插件：网页与桌面应用窗口共用插件进程内只绑回环的服务，
服务端带宿主令牌调本 API 并做 1 秒缓存，浏览器只拿插件自己的会话 cookie；403 时页面提示"插件已停用或令牌失效"并停止轮询。
