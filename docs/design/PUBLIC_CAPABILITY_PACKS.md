# 公共能力包评估与发布范围

状态：2026-10-12，本地实现与相关验收完成，未发布；未发布，不改线上安装或既有离线包。

管理员使用 `/plugins install <包路径> --scope public`，仍经原 `/plugins enable <包ID>` 启用；默认 private。
public 只允许内容能力包，不能发布插件运行权限。原安装表升级 v5，旧 v1-v4 显式迁移 private。
所有 owner 从管理员唯一安装表发现 `public/<包ID>`；原准确引用固定摘要、版本与激活代次。
普通用户无需开启插件总闸；方法/模板/脚本内容按需读取，资源执行仍受自己的工具、路径和凭据权限约束。
主子代理沿原 pins/grants 同代使用；管理员更新或停用一次，后续发现改变，旧 reader 不会静默换版。
更新必须保持范围；改变范围需明确卸载后重装。
证据见 [本轮交接](../tasks/IM_MULTI_TASK_PUBLIC_PACK_HANDOFF.md)；下文保留原设计与权限矩阵。

## 用户要求

普通插件与管理员私有能力包仍只供管理员使用；额外增加管理员安装的公共能力包。
管理员按公共范围安装并启用后，普通 IM 用户及其任务中的子代理可以使用；普通用户不能添加或管理包。
公共指本安装服务覆盖的用户，不表示互联网公开下载，也不表示读取其他用户的工作区。

## 实施前源码基线（历史）

- `capability/package_provider.py::enabled_capability_packages` 仅从当前 owner 的 PluginInstallStore 发现 active 内容包；
  reader 固定该安装及 activation，读取前后复核原记录。当前未提供管理员公共安装的消费范围。
- `core.py::_capability_packages`、`package_selection_scope.py`、`subagent_package_entries.py` 仍受 enable_plugins
  总闸约束。公共包不能靠给普通用户开启插件总闸实现，否则普通插件能力边界可能同时被放开。
- 现有 package_snapshot、task refs/pins、资源 source_ref 均固定包/整包摘要/activation/成员摘要。
  新发布范围必须进入这一条准确身份链，不能只在目录展示加“公共”两个字。
- 原插件管理明确校验管理员身份；部分业务执行另读业务权限。实现前要按用户当前要求复核普通插件业务入口，
  不把“只允许管理员安装”误认为已经证明“只允许管理员使用”。本轮未声明这一新矩阵已被所有旧入口满足。

## 推荐权限与安装语义

| 范围/类型 | 管理员使用 | 普通 IM 用户使用 | 安装、配置、启停、升级、卸载 |
| --- | --- | --- | --- |
| 普通插件 | 允许，仍受原授权 | 不允许 | 仅管理员 |
| 私有能力包 | 允许，仍受原授权 | 不允许 | 仅管理员 |
| 公共能力包 | 允许，仍受原授权 | 允许，执行受自身权限 | 仅管理员 |

安装服务增加明确范围，默认私有；管理员显式选择公共，包作者的 manifest 不能自行决定发布给全部用户。
仍复用 PluginInstallStore、安装 CAS、包 blob、内容 activation 和原管理动作，不另建发布服务器或第二份安装账。
“安装”与“启用”沿现有生命周期区分：默认停用的公共安装不会立刻进入用户发现目录，管理员启用后才可使用。
原私有包不自动公开；私有改公共是准确安装/发布动作，必须可审计和读回。
自学习候选或自动自制包不默认变为公共，发布范围只能从已授权的管理员管理动作取得。

公共仅适用于 package_kind=capability 的内容包；不把带插件运行时、宿主工具、进程、面板或 host_api 的插件
当成内容包对普通用户开放。能力包内声明的脚本文本可以按原 source_ref 读取/物化，执行仍走用户原 Shell 工具。

## 使用、执行和数据边界

安装一次、按需读取同一份受摘要校验的包内容，不给每个用户复制独立安装表或整个包。
普通用户主代理发现公共元数据后按任务选用，子代理沿原 allowed_skills/grants 和 task pins 继承同代许可。
不默认将所有公共包正文塞进每次模型请求；不新增选包模型循环或公共包专用执行器。

分清安装发布方与执行用户：安装源/activation 来自管理员发布记录，工具、工作区、预算、审批、记忆和产物归消费用户。
reader 只允许该 public 内容包的声明成员，不给普通模型或 Shell 管理员目录读取权，不开放管理员私有安装/配置。
方法、模板、参考和脚本原文共享；用户输入、运行缓存、凭据、记忆和输出继续隔离。
包需要额外工具或接口时，从执行用户的原授权/凭据解析；公共安装不自动赠送管理员工具或密钥。
公共包本身不保存所有用户共同写入的运行目录，产物在各用户任务工作区登记。

安装范围、发布身份、包 ID、摘要与激活代次须可准确定位，不能从模型正文、包标题或目录路径猜授权。
同名私有/公共包的发现和资源引用应显式区分，不能静默覆盖或把同名另一个范围当作原包。
最终 scope 字段、安装键和引用 schema 由原安装/包引用模块统一声明，旧引用写显式迁移，不靠隐式别名兼容。
公共状态只有一处 canonical 安装事实；用户目录及公共列表只是当前有权消费的发现投影。

## 更新与撤销

管理员更新、停用和卸载继续沿原生命周期及读前/读后复核。
新任务按当前启用代次选用，在跑的主/子代理不得因同名公共包更新偷偷换成另一版。
旧引用失效时保留结构化原因，按原恢复合同处理，不对缺失成员或旧代次自动转投新版。
停用后关闭新发现/读取；已经进入模型上下文的内容不能被抹去，停包与停止运行任务仍分别控制。
不承诺当前原更新合同已经支持旧版无缝跑完；若后续需要版本排空，再在原 lifecycle 内设计，不另建快照安装库。

## 实施与验收建议

1. 在原安装声明/授权/回执引入发布范围，先证明只有管理员可设 public；普通插件与私有包保持用户要求的权限矩阵。
2. 接当前 SkillsService/package_provider 与包读取 chokepoint，准确组装消费用户可见的公共包；
   同步主/子入口与资源 source_ref，把内容包可用性从插件运行权限中准确分离，不能开启普通用户插件权限兜底。
3. 保持 pin/代次/撤销与现有执行链，联合普通 IM、定时后台、当天委派验证。

验收至少包括两个不同普通用户、管理员、主/子代理：公共安装启用后一致发现与读取，私有包/普通插件不可用，
用户不能安装、公开、升级或撤销；用户 A 的产物/配置/凭据不进入 B 的任务，用户不能读取管理员相邻成员。
同名范围、主子同版本、升级/撤销竞态、重启、原资源复制/执行和各用户额度必须分别验收。
仍按合同单测→fake tool/LLM→replay→单 Gateway 的真实 Linux/IM 少量验收，不把目录中有包当成任务实际用了包。

本轮读了本项目 CAPABILITY_PACKS、PLUGIN_PACKAGES 与发现/资源/主子入口源码；
参考本地 OpenClaw skills 文档将共享安装位置与可见权限分别定义的模式。不同用户的发布权、读取权和执行权
仍按本项目的结构化安装/授权合同实现，不照搬参考项目的文件目录可见性。

建议下一步：先明确安装范围和消费身份的最小合同，再完成两个用户的发现/读取/隔离切片。
其它 agent 可并行只读复核原权限与测试设计，不同时改安装表、包引用和读取函数；本轮不实施或推送 main。
