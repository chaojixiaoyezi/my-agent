# Compact 摘要生成事实

状态：2026-09-26 设计由 Codex 交接（原提交 `c9c7515fe`），产品实施归集成方，尚未实施。
同日集成方先落了前置一片：摘要请求 `none`、违规改走分段链和日志关联键，见 [会话上下文设计](CONVERSATION_CONTEXT_DESIGN.md)；
checkpoint 生成来源仍按本文待实施。

## 解决问题

当前压缩告警能描述响应形状，却不能准确关联请求；机械摘要的原因仅留在正文中。
分段摘要还可能混合模型与机械内容。不能根据一句告警、摘要标题或最后一次模型响应，
判定最终提交的候选由什么生成。

本片补充诊断来源，不改变摘要采用、覆盖、权限、取消、用量或恢复规则。
首片覆盖 transcript 候选与共用分段 producer；live-tool 持久接线另列，未接通时来源未知。

## 唯一链路

沿原辅助调用生成事实，随本次摘要结果传给原候选，最终写入原 v3 checkpoint。
不建立新账本，不向通用后端 `ModelResponse` 增加 Compact 专用字段。
共享返回类型若改变，所有直接消费者和替身同步适配，不保留无依据的双返回兼容。

请求身份来自当前结构化请求；调用身份复用原辅助调用观察中的 `call_id`。
请求、线程、运行或任务身份缺失时保留缺失，不从正文、路径或相邻时间推断。
日志使用墙钟时间，不能把原调用账的单调时钟起点当作 Unix 时间。
记录字段限于身份、来源、原因码、计数、响应形状和实际请求选项，不记录正文、参数、密钥或个人路径。
发送前的请求选项只能称为声明的请求事实；只有实际传输接点的证据才可称为发送载荷事实。

## 生成来源

本次摘要主体至少区分：单次模型、分段全模型、分段混合、分段全机械及未记录。
失败原因只归给实际采用的机械内容。曾返回无效响应、随后原纠正成功，不等于最后采用机械摘要。
完整来源保留、landmark 和媒体策略不自动归为模型失败；需要使用自身结构化原因表达。
继承的旧摘要来源沿 `summary_base_checkpoint_id` 追踪，不并入本次生成来源计数。

候选循环可能采用较早候选，故生成事实必须与候选同生存期，不能提交时取最后响应或请求级可变全局值。
原 `trigger_fallback` 只表达候选选择行为，不代表机械摘要。
一个请求可以包含多个候选和调用；请求用量不能全部归给最后采用的摘要。
调用明细有原 LRU 生命周期，checkpoint 中的引用不保证明细永久可查。

## 持久与兼容边界

v3 增加可选、带自身 schema 的诊断对象，准确请求身份随同原 checkpoint 保存。
原 `scoped_compact_checkpoint_id` 算法保持；诊断不决定覆盖、权限、CAS 或计费，
也不宣称由原 v3 内容身份封印。若未来升级为恢复权威，必须另行设计版本迁移。
旧 v3 缺字段为未知，不能默认成模型生成、零回退或空原因；v1/v2 仍按原版本读取。
坏诊断只使诊断不可用，不否定原有效摘要。历史记录不补猜外键。

取消继续中性丢弃，异常沿原链传播。追加后 CAS 未赢仍是孤立候选；CAS 成功后不回滚。
诊断缺失或写入失败不能增加模型请求、重试或新的业务恢复动作。

## 验证与交接

- producer：单次、混合段、全机械、纠正后成功、末段失败；原正文及调用次数保持。
- 候选：较早候选胜出时来源正确；请求与调用身份准确；日志无正文及凭据。
- checkpoint：旧 v3、新旧链、孤立候选、CAS 冲突、坏诊断与原身份算法保持。
- 取消：发送前后、候选后及提交边界不增加提交或失败计数。
- 共享消费者：live-tool 等原调用方保持原业务语义，不扩大本片持久覆盖结论。
- 真实：严格组件通过后，经独立原生 TUI 使用官方 MiniMax-M2.7，记录当前请求、实际摘要与原 checkpoint；不使用直连模型探针代替 TUI。

已观察到的旧 `TOOL_CALL` 告警与旧 checkpoint 仅有时间邻近，不能凭本次改动倒推旧请求。
现有合成序列化检查未发现 `tool_choice=none` 丢失，不因此确认旧发送载荷或供应商责任。
本片不添加去工具重试；后续如有准确新证据，再评估通用主链合同。
