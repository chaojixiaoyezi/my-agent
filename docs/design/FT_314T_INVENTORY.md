## 范围、状态和证据口径

这是供人阅读的设计文档，不是运行时输入，也没有脚本、AST 门或测试把本文当成允许清单。下面逐条保留规定扫描的命中；同一对象的声明、写入和线程提交可能有多条定位。`open` 不等于已证实缺陷，表示 Part B 尚需完成对应对象的自由线程行为验证或修正；已有锁和一次压力测试不能替代完整生命周期复核。`closed-A` 仅用于本片实际修复且有运行测试的行。非执行性的导入、注释、业务记录构造和只读常量单列为 `not-shared`，不计入 open/closed-A。

文件定位相对仓库根；表中 `agent/`、`cli/` 简写均在 `agent_py_agent/` 下。定位来自本片扫描版本，符号是后续重定位依据，不能把行号作为机器身份。`tests/ft/...::test_shared_state_target[...]` 等带“计划”的节点尚未实现，不声称已有测试证明这些行已关闭。Part B 应按对象增加真实交错/生命周期断言，不读取本文生成门禁。

- **FT1**：自由线程构建在导入后保持 GIL 关闭。新进程逐模块导入和延迟首次调用探针检查真实 `sys._is_gil_enabled()` 前后是否一致，不设置 `PYTHON_GIL=0` 强行阻止扩展开启 GIL。
- **FT2**：共享计数器和缓存不得依赖 GIL 原子性。这里只对 token LRU 关闭该项，不能外推到所有 open 行。
- **FT3**：3.12/GIL 构建继续受支持。新文件在 3.12 可收集运行；不支持 `thread_inherit_context` 的解释器仅跳过相应两组显式 flag，不跳过默认线程出生用例。
- **回退**：`PYTHON_GIL=1` 是解释器环境变量（class F），不是 AgentConfig 键；应在启动进程前设置并重启验证。它不能代替修复，也不能消除显式 `-X thread_inherit_context=1` 的上下文继承问题。
- **锁序**：token 缓存新增锁是叶子，只包 int 键/值的 pop、重插、发布和逐出；指纹、编码和 I/O 都在锁外。沿用 `_ITEM_LENGTH_CACHE_MAX_ENTRY_COUNT`，不增加配置或常数目录条目。
