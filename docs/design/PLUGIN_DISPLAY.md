# 插件声明式展示与只读订阅

状态：第 9 步已实施并发布（fae9d5855），本机真实 TUI 已验；已知缺口见下文「已知缺口」。上位合同见 [可装卸插件方案](PLUGIN_LIFECYCLE.md) 与 [样本计划](PLUGIN_SAMPLE_ACCEPTANCE.md)。

## 解决问题

activity-line、status-pet 等展示类插件需要持续显示当前运行状态。要满足的约束是：插件 Python 不能在 TUI 进程内执行；
不能新增第二份运行事实；插件出错、卡住或被停用时，不能拖慢核心输入，也不能留下面板、回调或定时刷新。

## 声明

插件在 `declaration.json` 中可选声明 `panels`（每个插件最多 2 个）：

| 字段 | 约束 |
| --- | --- |
| `id` | 小写字母、数字和连字符，1–32 字符，同包内唯一 |
| `title` | 1–40 字符 |
| `kind` | `text` / `table` / `status` 三者之一 |
| `topics` | 从核心公开主题中选择，至少一个：`activity`（当前工具、阶段、耗时）、`run_state`（working / waiting / idle / blocked） |

声明随包校验、随安装固定，不可在运行时增加主题或面板。未声明 `panels` 的插件与现状完全一致。

## 数据流

```text
TUI（面板打开时）--轮询--> Gateway /client/plugin-panels
Gateway 展示服务：读取该会话已有的公开投影 → 按插件声明的主题裁剪 → 与上次已渲染版本比较
  └ 有变化且该插件无在途请求 → 经固定代次的插件连接调用 my-agent/display.render
       ← 插件返回展示描述 → 核心按 kind 校验、截断 → 存为 (owner, 会话, 插件, 代次, 面板) 的最新结果
TUI 只渲染核心校验过的描述，不导入插件代码
```

- **只读、无副作用**：`display.render` 的输入只有裁剪后的公开投影（不含路径、正文或私有配置），不经过审批和工具执行器；
  插件在这次调用里不能调用宿主能力。
- **协商**：插件在 MCP `initialize` 的 `capabilities.experimental` 中声明 `my-agent/display`，版本为 `1`。
  声明了面板却未协商该能力，面板显示为"不可用"，不回退到其他通道。
- **有界**：每个插件同时只有 1 个在途请求，新变化只保留最新一份（合并掉中间版本）；请求超时 3 秒；
  描述上限为：文本 20 行、每行 200 字符；表格 20 行 × 6 列；状态 8 个字段。超出部分截断，并标记 `truncated`。
- **连接**：每个 (owner, 激活代次) 至多一条长连接，由有人查看面板时启动，连续 120 秒无人查看就关闭；
  沿用 `PluginMCPClient` 及其进程资源账，关闭与撤销按原清理链确认。
- **代次与撤销**：每次渲染前后都复核激活代次；代次失效时丢弃结果、关闭连接、清空该插件的全部面板。
  停用或卸载后，TUI 下一次轮询拿不到面板，也就不会再请求。
- **故障隔离**：超时、协议错误、描述不合规只把该面板标为错误状态并退避重试，不影响其他插件和核心接口。
  展示层不能发明运行状态，也不能代替取消、审批或调度。

## TUI

- `/plugins@<插件> panel` 或面板快捷键只切换本地显示偏好；关闭后停止轮询。
- 面板渲染只依赖核心校验后的描述；面板区域的高度固定且有上限，不挤占输入区。
- 面板请求在后台线程执行，失败时退避，与核心后台快照完全独立。
- 面板动作按本地插件目录解析；新开或 `resume` 后目录尚未经补全读取时，面板命令先做一次显式目录读取，
  仍取不到才交回宿主（宿主以 `display_client_only` 明确拒绝，不执行）。
- 使用卡的普通中文示例只取非展示动作；只有展示动作的插件改为说明"面板只能用命令打开"，
  因为模型无法调用展示动作，示例会落空。

## 已知缺口

- 还没调用任何工具的纯模型回合没有晋升为工作区任务，宿主活动投影里没有主行，面板和同会话其他窗口都显示"空闲"；
  本机实测首轮思考约 10 秒内一直空闲，首个工具开始后才显示"工作中"。发起请求的 TUI 自己的"Working…"动画不受影响。
  这是宿主活动投影的既有语义，面板如实映射，不在展示层补猜状态；是否让未晋升的前台回合进入投影，待单独设计。

## 验证

合同单测（声明校验、描述校验与截断、代次拒绝、单在途与合并、超时隔离）→ 假插件进程 → 真实 TUI（打开面板、
长任务期间持续更新、停用时在途刷新被撤销、再启用、卸载后新会话无残留）。
