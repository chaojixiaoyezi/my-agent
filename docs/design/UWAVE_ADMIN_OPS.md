## 前台宿主权限与输出

full-access 使用本次宿主调用冻结的前台管理员事实，不采信 prompt、普通工具参数或模型自报身份。共享 registry 中每次调用各自携带事实，不能因一次管理员调用改变下一次调用的边界。

业务范围、其它 owner、AGENTS/SOUL 等既有保护继续生效。当前 Gateway/adapter/supervisor 的自停检测使用准确服务 PID、进程出生身份及宿主服务根，不根据进程名称猜测。该保护不是任意 shell 程序的完整语义证明。

凭据快照只在当前调用中使用，在流、日志、归档与分页保留之前净化。不可读取的凭据来源要报告覆盖不完整，并保留对应路径保护；不能把无关诊断一起关闭，也不能将“快照没有读到”当作“该文件没有凭据”。EOF、取消与超时的未决敏感前缀不得原样输出。

## 只读 SQLite 的准确含义

只读查询不创建应用数据库、不迁移 schema、不修改业务数据、不 chmod、不创建应用 generation 锁或目录。通用 `io/readonly_sqlite.py` 使用 `mode=ro`、规范路径和文件身份验证；原运行库允许同用户不可被其它用户写入的目录。

SQLite 自身的 WAL/SHM 协调及冷库附属文件创建属于读取当前 WAL 所需的原生机制，允许发生，不能宣称完全零文件写入。禁止使用 `immutable=1` 读取活跃 WAL，因为它可能忽略已提交数据。缺失或不可信来源返回具体 unavailable/partial，不触发索引修复旁路。

数据库主文件的打开和关闭必须由 SQLite 管理。不能为了核验身份再裸 `open`/`close` 一个已发表数据库文件：POSIX 下这可能释放同进程其它连接的锁。首次创建只能在未发表的临时 inode 上完成裸文件操作，关闭后再原子发表；父目录 FD 与文件身份元数据核验继续保留。本轮真实双 TUI 长任务发现了运行库损坏，并另行复现了上述锁丢失机制；修复和重新验收必须保留原失败，不能把新库正常运行说成故障库已恢复。机制依据见 [SQLite 官方损坏原因说明](https://www.sqlite.org/howtocorrupt.html)。

## 存储与留存

`StorageLaneRequest` 沿原维护调度传递配置、预算、游标和写门。`global_indexes`、`task_call_telemetry`、`thread_index` 都使用原条数/字节/耗时上限；显式 0 或已过期预算不能变为无限。

候选引用扫描、计划生成与 apply 前复核均可让出并续扫。一个 apply 共享预算，不能每项重新领取完整预算。已完成的证明按源代次复用；代次变化须重新核实，不用缓存授权删除。`scan_partial` 从计划和 apply 两端合并传播，不能被后一个成功空步骤覆盖。

只读投影可在某条记忆来源坏掉时继续维护；删除仍按 legal hold、准确引用、原策略及写前复核保护。调度临时线程沿现有 `conversation_days`，不擅自缩短历史保留期；必须有准确调度终态、隔离执行和投递已结证明。不按年龄删除正式 memory、SOUL/AGENTS、业务资产或工作流定义。

## 计划重启配置

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `gateway_restart_mode` | `fast` | 只控制计划重启；可选 `graceful` 使用原等待流程 |
| `gateway_restart_fast_timeout_seconds` | `2.0` | fast 副作用关口排空预算，必须为正有限数；不是整个重启时延保证 |
| `gateway_restart_turn_wait_seconds` | `300` | graceful 原第一阶段等待语义不变 |
| `gateway_restart_drain_timeout_seconds` | `600` | graceful 原第二阶段预算；`0` 仍为不限制 |

安装更新停机沿原安全升级方式。fast 不继承旧 force 放行；graceful 的既有显式 force 配置保留兼容。准确模型传输可冻结为待交接，但继任者必须等前任物理退出再消费。不能将写工具、身份未知的后台工作或泛化 bounded call 冒充可安全重放的模型调用。

## 验收与已知边界

闭环报告的坏候选、学习材料、排除线程、唤醒、调度任务、投递锁、遥测行和派生索引故障均按原对象边界隔离。隔离不等于批准：坏来源仍不签发记忆晋升、Skill 覆盖、删除或重放权限；已核实的其它记录可以继续。投影缺表须使原域 checkpoint 失效并有界重建；派生回执库只有明确 SQLite 损坏码才走保全重建，I/O、繁忙或无错误码不能猜成损坏。

真实长任务还发现 SQLite 裸文件描述符的锁风险，以及留存扫描未完成时工具审计投影被一起延期。已将无删除投影推进与归档退休分开，保留原代次和 offset 增量推进；并修正全局索引实际维护入口。完成一次投影后仍须在原维护周期观察新追加，不能被旧 pending 集合饿死，也不能豁免整条含删除操作的维护通道。单元测试绿色不足以替代模型调用审计工具的实际读回。

子代理父根身份从已加载的宿主任务统一传给模型和工具遥测。遥测头里的默认 running/interactive 没有生命周期来源时，公开为 null 并解释准确查询入口；显式记录保留，模型 finished 不等于 TaskRun 已关闭。进程完成记录读取失败时保留原错误数，并在既有诊断字节预算内记录脱敏类型、来源、引用、副作用未知与下一步；正常后继继续，不重放原命令。

真实复验进一步发现两处审计可用性缺口。`audit_records topic=tool_calls` 目前只支持本人 owner 范围；不支持的范围必须明确返回具体错误码、未读取事实与可复制的显式调用示例，不能默默扩大范围。业务工具页游标改用规范行 ID 的固定上界、末行操作锚点和数据库文件身份，普通运行库写入及追加不使下一页失效；源替换、截断、锚点消失或筛选变更仍拒绝。其它可变观察域不取消原代次校验，不建立全表快照或第二份权威账。

最后真实读回已连续取得审计两页和业务工具三页；业务页间普通运行事件写入未使游标失效。相对时间窗随新游标保存原时长与绝对起点，重复相同 `since_hours` 续页不会重新按当前时间漂移；真改窗口仍须重新首查，旧游标没有原时长时不猜。只读运行库入口另补原恢复意图检查：待恢复时报告未知，不走写入修库或清除恢复证明。
