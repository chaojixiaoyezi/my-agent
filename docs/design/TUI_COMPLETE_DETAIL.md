# 完整原文浏览与回到最新

状态：原地展开、连续滚动和插话时序已实现；本轮真实 TUI 版本、证据及范围见 [验收交接](../tasks/TUI_READING_HANDOFF.md)。
当前未覆盖边界见 [STATUS](../../STATUS.md)；具体版本须重新做真实 TUI 验收。

## 解决问题

旧 Ctrl+E 只放开部分前端行数；正文2000行、活动思考50行、工具上游预览180行以及
每行终端宽度裁剪仍会丢失可见内容。旧完整提示没有区分内容未加载、未保存和仅折叠。
回到底入口混在长底栏末尾，冻结详情的“到底”还只是旧快照尾部。

## 交互

- 普通视图保留现有清晰的 Markdown、工具预览和已完成思考折叠。
- Ctrl+O 在当前消息位置进入冻结阅读；Ctrl+E 原地展开完整原文，再按原地收起。
- 普通、详细、完整原文共用块身份和来源行定位，保留消息在屏幕上的位置；快速连续按键也传递同一锚点。
- 完整原文保留正文字符与工具增删行样式，不重新解释 Markdown；长行换行而不删右侧。
- 滚轮与上下键直接移动视口，内部页边界自动接续；`[`、`]` 仅是可选的快速跳段入口。
- `/` 搜索只覆盖当前已加载窗口，提示明确标注，不声称已经搜索未加载的归档。
- 离开底部，或处于冻结阅读时，独立显示「↓ 回到最新 (Ctrl+End)」。点击或 Ctrl+End
  退出冻结阅读，到当前主/子代理的 live 尾部并恢复输入焦点和跟随，不停止代理、不发消息。
- 详情 End 同样回到最新；Esc 原有语义不变，不把它重定义为页面返回。

## 资源与历史边界

本地已加载原文按256行、12000字符双预算分页，超长逻辑行拆成2000字符片段，
每次仅格式化当前位置附近至多四页，不一次性画出整段长历史，也不删除中间文本。
存在后续页时，视口允许当前窗口末行滚到屏幕顶部，避免短页组合被终端页底限制卡住。
异步加载邻页保留同宽页内位置；初次展开时整个窗口加载完成前持续保留原消息锚点。
页索引是进程内的显示状态，不进入模型请求、Compact、会话消息或记忆。
远端归档采用稀疏页索引，十万页也只保存一条引用；按需异步读取阅读窗口，最多缓存8页。
失败页明确提示 `R` 重试，不自动重执行工具。页面内同一逻辑行的分片会重新拼接后换行；
跨页长行沿窗口继续，选择复制仅覆盖已加载窗口，不声称一次复制跨越未加载页面。

工具write/diff/patch必须捕获执行当时的完整快照，不能读取当前文件补造历史差异。
不可变归档、owner鉴权分页与轻量ref由独立展示归档模块承载；TUI不得自行访问宿主路径。
旧事件已经被裁剪且没有完整归档时，显示缺失说明，不承诺能恢复模型或工具未保存的内容。
正在生成的思考只显示当前已经收到的内容；冻结阅读不会偷偷替换新版本，完成后可回到最新再打开全文。

## 思考时序与慢模型

原问题有两处生产原因：真实 tool-start 没有关闭上一活动思考；预览先对全部思考做 Markdown
排版，再只显示前50行。修复后真实工具边界和模型 attempt 边界先冻结上一思考，下一delta
创建新 block。前台/后台/子代理共用同一展示边界，不能靠正文猜测任务是否结束。
活动预览在排版前限制4000字符/50逻辑行，详细预览12000字符/200逻辑行；原始block不修改。
活动思考超过预览预算时，提示实时刷新折叠原文行数和已接收字符数；无换行长段落也会
随字符数变化。原文按换行计数，跨字符上限的未完整行也计入；预览因终端宽度换行后
还有隐藏行时，单独显示「另折叠 N 行预览」，不把两种口径混作模型 token。
计数只扫描已收到的文本，不为隐藏尾部做 Markdown 排版、不修改上下文；字符数不增长
只表示当前没有新文本到达，不能据此认定模型死亡，也不伪造剩余百分比。结束后仍自动
收起，Ctrl+O/Ctrl+E 和完整归档读取方式不变。
长思考终态在服务端保存已公开净化的不可变原文，事件仍保留有界预览和ref。
明确失败的归档只能保留缺失提示，不能将已裁预览二次归档当成全文。

现有 writer 的 thinking 回调没有provider item/call ID。真实边界后、下一delta前的旧全文
只能给原block补原文ref，不能新增块或改变原位置；若旧调用全文晚到下一调用delta之后，
仍需要上游显式item身份才能可靠分辨。
本切片不以文本相似度猜归属，不宣称已经补齐这个跨调用乱序身份协议。

## 插话与历史顺序

Gateway 的 `submitted` 是新提供方调用前的显示边界，先冻结前一回答，再显示插话和后续回答。
后台 native 记录与正式投递快照按同一 `conversation_request_id` 合并显示，避免重连出现双份回复。
`consumed` 仅确认消费，不再切开已经流式输出的回复；重复的精确调用/输入批次不重复分段。
插话在原有显示检查点与最终显示快照中保留其提交位置，规范模型消息仍由原 guidance 消费流程独占。
跨工作片回放按 canonical 行位置和检查点块身份排序，同一输入按客户端消息 ID 去重，不比较正文。
旧记录若没有保存提交边界，只能保留已存在的行顺序，不能伪造缺失的事件位置或补写原账。
