# Owner 配额根目录的有界成员核验

状态：源码候选；远端 CI、发行与部署分别验收。本设计复用原配额账本、owner 锁、逐目录摘要和后台分片，不新增 watcher 或第二权威账。

## 为什么不能凭根目录时间免扫

账本每片原子替换会改变 owner 根目录时间。同 tick 的外写，以及“核对根时间→外写→替换账本→记新时间”的窗口，都可能被记成只有账本发生变化。根目录时间相同不能证明成员没有变化。

后台每轮结算因此必须重读根目录直接项。每个项仍经原生成器交还结算条目和时间额度；大根分片续作，不在每次准入遍历整树。中途冷恢复或读取失败按原合同保持脏，下一完整轮补正。

## 固定尺寸的可重建观察

原目录行旁可选保存 `root_membership`，格式为四个整数：全部非控制成员的数量、名字 SHA-256 的模 2^256 加和、无需额外 stat 定性的普通名字数量及相同算法的加和。顺序无关，不保存名单、正文或每文件长期索引。

- 原完整扫描、根结算重扫及有界完整核验顺手产生摘要，没有额外全树遍历。
- `root_membership_scan` 只描述正在枚举的根，随原游标持久化；完整根行发表时替换旧证明。
- 活跃新一轮尚未走完根时保留原完整基线摘要；结构化声明变更按实际前后存在性增减，已扫描前缀另按原游标调整。
- 缺字段、坏类型或不能完成分类时不猜完整。旧账由原后台扫描补齐，不在构造或普通读取时同步升级。
- 原根目录时间缓存与它的免扫参数退役；有限配额启用身份 LRU 仍独立保留。

## 增长与结算

只有启用配额的原写入路径参与核验。零或负净增长的前置 `check` 不增加根名字读取；下一次正增长仍 fresh 核验，不能复用前次未观察的结果。结算照实际变更核验。普通 TUI 查询未接入配额扫描。

在原轮转或本次触及范围选中根时，仍沿原 nofollow 目录打开与身份核验，实际读取至多 65,536 个名字。名字摘要一致只复用原完成扫描的分类，不把时间当证明。普通成员摘要变化不能仅凭数量相同采纳，避免删旧小文件、加新大文件的等量替换被放过。

只有锁侧车等需 stat 定性的名字变化时，沿原最多 256 次 stat 分类。新空 sidecar 可以按原合同采纳；原计费锁过多而无法证明时保持待对账。声明增删后的期望摘要由原前后像更新；结算仍读当前成员，外加成员不会被账本替换吞掉。

## 保留的界限与成本

- 原目录行已经超过 65,536 项时，前台保留原受控写代次放行、留后台对账的合同；这一区间没有完成前台成员核验，不能称作 fail-closed。
- 名字相同不证明同名原位内容、大小、类型或 inode 没变化。大目录这类内容变化仍由原后台完整对账处理；这里没有承诺文件系统原子快照。
- 原元数据表超额或不可用时，既有受控写代次回退边界保留，不冒充新成员证明。
- 正常实际增长可能前后各读一次直接成员，时间随根项数增加但受原名字上限约束；没有可靠变更日志时不能安全省掉这两次观察。大根增长可能超过 100ms，不代表通知或 TUI 只读延时退化。
- 时间预算为协作切片，单次原子 I/O 不可中断；不把测试的 max_ms 描述成硬响应保证。

建议下一步：集成后保留完整配额回归与原平台 CI；若大根实际增长成本成为瓶颈，应另以完整变更来源解决，不能恢复目录时间猜测。
