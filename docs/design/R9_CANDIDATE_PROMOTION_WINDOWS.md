# 候选晋升有界轮转

本片只改变后台积压发现，不改变正式晋升来源、证据、owner/actor、目标版本、配额或 CAS。新提交的候选仍沿本轮原直接审核链；显式完整列表接口保留。

原后台为选 32 条读取全部 pending_review/approved 正文。现在从原 HAMT 位置索引读取最多 128 条，再沿原三档优先级、created_at/ID 排序，选择最多 32 条。页内未选的精确 ID 留在原 Curator 状态的有界调度续点；下一片规范重读，不缓存正文或授权。页内剩余先处理，再进下一页，所以未能晋升的前 32 条不会永久挡住同页晚排序项。大积压由全库三档排序改为页内三档排序；小于一页的顺序不变。

生产调用先尝试原晋升，正常返回才在同一原租约下 CAS 发布续点。异常或进程退出不提前签末页完成，重启仍从旧页规范重验；部分已晋升条目由原状态/CAS 排除。完整一轮结束不主动重排全库。新输入仍可沿原整理触发后续重验。

续办使用原 owner 发现、租约和失败冷却，purpose=candidate_scan，不重新请求 pre_compact/daily_finalize，不调用提取模型或重做日报。间隔复用原配置，限制在 30–300 秒；foreground 避让保留。manual_only 或无晋升回调不启动轮扫。发现只点查候选头是否存在，不读全表；损坏仍报告失败而非空。若每页 128 条都可选，最多四片处理该页。13,141 条最多 411 片，默认 300 秒的纯调度间隔约 34.2 小时，另加前台避让/失败冷却；这是旧大积压上界，不是新候选的正常等待。

旧 JSONL 不强制全文迁移：沿同一严格只读打开器按字节续页，单片最多 128 个物理行、8 MiB；累计预算在上一个完整记录处让出，空行和合法无尾换行保留。续点只在同 FD/规范路径身份、大小、mtime、ctime、原生 ChangeTime 一致且越过原粗时钟保护窗口时复用，否则保守重扫。单个物理记录超过 8 MiB 明确失败、保留旧数据与游标，不签空或截正文。索引数据无新迁移或第二权威账。
