# 模型目录与配置边界

本文件说明模型目录的维护方式，不保存会快速过期的型号容量或价格快照。

## 当前配置

通过 `/model` 管理服务商与模型。地址、接口风格、模型 ID、密钥引用、上下文容量和启用状态应成套配置；目录里有型号不等于当前账号可调用。认证占位选项不代表已实现登录。

会话覆盖、用户默认和后台启动默认必须区分。不能根据显示名字推断实际供应商或接口；实际请求记录才是调用依据。不同协议的思考字段、工具回放和参数能力由协议适配处理，不能全局猜测。

## 元数据维护

- 型号、容量、输出上限和价格从当前供应商文档或发现接口核对，再由用户配置覆盖。
- 未知型号应允许显式配置；缺价格只影响估算，不阻止调用。
- 不在仓库保存个人账号、密钥、私有 endpoint 或可识别用户的 session header 值。
- 远端元数据不应替用户修改地址、认证信息和自定义请求头。

## 后续设计

建议目录键为 `provider + model_id`，记录能力来源与时间；合并优先级为用户显式配置、供应商发现、发布种子。单个运行回合使用固定配置快照，刷新目录不能中途切换协议。本段为设计方向，不等于自动发现全链路已经实现。
