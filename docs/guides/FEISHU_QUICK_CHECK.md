2026-10-15 `.20261015.12`用法：群主/已核邀请人用`@机器人 /group 监控 @某人`或`@机器人 /group 监控 全群`；全群包含以后入群的成员。只管监控，普通聊天/其它功能及原管理员边界保持。此中文入口从`.11`起提供，旧包仍为英文语法；最终补丁包为`.12`。群核验失败应查看具体阶段/平台码，不反复重授权；见[群合同](../design/IM_GROUP_GOVERNANCE.md)。

# 飞书 5 分钟手测清单

本地候选的`/verbose stream`仍编辑同一条短过程消息，默认100字符，工具或模型等待沿原宿主心跳更新；最终结果另发。模型说明在本次回复确认并完成安全投影后展示，未确认token不提前外发；不要把没有逐字刷新当成停止执行，可用`/status`查看真实任务状态。本轮真实验收与安装版本以发行回执为准。

群监控授权由当前群主或已核验的机器人邀请人设置，普通聊天和其它功能无需这道额外授权；配置仍守原用户空间及管理员权限。引用其它机器人真实消息再@助手说明订阅条件，pause/delete停止订阅，cancel只停当前执行。普通group_at不包含接收其他bot消息所需scope，产品不代开；详见[群治理合同](../design/IM_GROUP_GOVERNANCE.md)。本轮中文授权和图片真实整链验收另记，不能用合成回归代算。

给用户本人在真实飞书上做的快速核对，主流程总共不超过 5 分钟（第 6、7 项可选，另约时间，不计入 5 分钟）。
相关功能已有分层自动化证据：C11 用假飞书、真网关、真模型跑过部分链路，熔断体验修正另有离线合同测试，
插件命令另有 IM 控制测试（见 [TESTS.md](../../TESTS.md) 的 C11 节）；但真实飞书收发和私聊锁，仍需在真实飞书上补测。
手测不挡收口，有问题把下面说的信息发给开发就行。

## 部署者先查连接与代理

- `feishu_ws_proxy` 空值保持系统/环境代理发现（包括 `wss_proxy`、系统 SOCKS、`HTTPS_PROXY` 和 `no_proxy`）；无代理才直连。
  显式 HTTP/HTTPS/SOCKS URL 直接交给 `websockets`，不会在代理失败后绕过代理重试直连，也不改进程环境。
- 包固定使用 `websockets>=15,<16` 的正式代理接口，并随包安装 `python-socks[asyncio]>=2.7.2,<3`。
  如果日志出现缺少 `python-socks`，安装包的依赖闭包不完整，不能靠清空环境代理掩盖。
- SOCKS 复用上游 [正式接口](https://websockets.readthedocs.io/en/15.0.1/topics/proxies.html)；
  [python-socks 2.7.2](https://github.com/romis2012/python-socks/tree/v2.7.2) 使用 Apache-2.0，支持 Python 3.8 及以上，
  asyncio extra 在 Python 3.10 额外带 `async-timeout`。选择维护中的库是为复用握手、认证和异步取消；替代方案自写协议成本高且无必要。
  依赖仅在打包阶段安装，运行时不请求新的外网服务，不扩大飞书现有网络放行范围。
- 健康只读 SDK 原连接：`OPEN` 才健康，初次握手未成功、关闭或未知连接事实都降级；旧连接接口仅在明确 `closed=False` 时健康。
  `transport_health()` 返回固定 `status/reason_code`，不以线程存在或 SDK 启动日志代替连通证据。
- SDK 自带日志处理器也经过共享脱敏，保留错误类型和连接诊断，隐藏代理密码和 WebSocket URL 令牌。
  离线参数/健康回归不能替代真实入站和出站验收；未收到消息仍需按下方清单补测。
- 卡片诊断在原 SDK 分发和认证回环上记录固定阶段与错误码；消息、连接和 trace 仅可用不可逆摘要关联。
  不开启 SDK DEBUG，不记录载荷、表单、签名、引用或回执正文。诊断不改变 SDK 的分发、ACK、权限与重试；
  真实按钮未完成时，先区分未到 handler、身份/解锁拒绝和回环故障，不能靠无账或按钮闪动猜测。

开始前：
- 用手机或电脑打开飞书，进入和机器人的**私聊**；
- 验普通用户时保持普通身份，不要为了测试先绑定管理员。第 7 项管理命令需要已有管理员身份，普通用户跳过；
- 先发 `/goal` 看一眼当前有没有正在用的业务目标。第 4 项收尾会发 `/goal clear`，别把原有目标一起清掉。

## 1. 普通回复（约 30 秒）

- **发送**：`你好`
- **算通过**：你的消息上可能出现一个临时的处理中表情（样式从一组表情里随机选，可能是"处理中"类，也可能是笑脸、点赞等）；正常收尾会先撤掉这个表情，再收到一条引用你消息的回复。表情加不上时会跳过，不影响回复。
- **有问题**：超过 1 分钟没回复，或者表情一直不消失。把发送时间告诉开发。
- **说明**："十几秒内"只是参考，不是保证，实际取决于模型响应和网络。

## 2. 系统命令（约 30 秒）

- **发送**：`/status`
- **算通过**：很快收到一条状态回执，比如当前会话、模型、是否在运行，而不是模型在"聊天"。
- **有问题**：收到的是模型的闲聊式回答，或者提示"不支持的系统命令"。

## 3. 后台做完会主动发给你（约 2 分钟）

- **发送**：
  `请在后台派一个子代理，数一下你工作区里随便一个目录有几个文件、分别叫什么，做完把结果发给我。`
- **算通过**：
  1. 前台先收到派工相关的回复（可能不止一条，条数由模型回复、过程显示和分片决定，不保证恰好一条）；确认子代理确实派出；
  2. 之后收到一条**不是引用回复**的新消息，里面是统计结果。这条就是后台做完后主动发给你的。
- **有问题**：后台结果一直没来（等 3 分钟），或者**同一结果**收到了两遍（重复主动发送才算异常）。把发送时间告诉开发。
- **说明**：完成耗时取决于模型和调度，不以 1 分钟内为标准；如果子代理根本没派出，记"后台场景未命中"。

## 4. 持续目标空转后的熔断提示（时间不保证，看调度）

- **发送**：
  `帮我把这件事设成一个持续目标跟进：等我把读书笔记发给你，再整理成一页摘要。笔记我晚点才发。`
- **预期现象**：
  - 先收到一条确认；
  - 接下来**不会**再收到"在等你发笔记"之类的逐片空转消息（空转片正文只进会话历史、TUI 可见，不外发）；
  - 默认在**连续 3 个自动续跑片**没有工具调用或目标/任务状态变化后暂停，并**主动**收到一条提示（只推这一次）：
    `持续目标连续 3 片没有工具调用或目标/任务状态变化，自动续跑已暂停。请检查进度后用 /goal resume 恢复。`
  - 主动送达时提示**不带【提示】前缀**；只有没主动送达、随下一次前台回复补出时才会带【提示】前缀。
  - 工具调用、目标/任务状态变化、子代理还在活动、用户回合在场都会让计数清零或避让，所以耗时不固定：触发按"连续 3 个空片"算，不以 1.5 分钟为标准。
- **再发送**：`刚才那个目标现在是什么状态？`
- **算通过**：这次回复里**不再重复带出**上面那条提示（已主动推送过一次），回复能说明目标已暂停即可。
- **有问题**：
  - 还在陆续收到"在等你发笔记"之类的消息（空转片不该外发）；
  - 或者一直没收到主动推送的提示。观察窗口内没触发就记"熔断场景未命中"，不算失败；
  - 或者下一条回复又重复带出同一行提示。
  - 把发送时间告诉开发。
- **收尾**：发 `/goal clear`，清掉这个测试目标。

## 5. 插件命令（约 30 秒，step17a 起）

- **发送**：`/plugins`
- **算通过**：很快收到一条插件命令的说明或插件清单（纯文本回执），不是模型在“聊天”，也不是“不支持的系统命令”。
- **再发送**：`/plugins help install`
- **算通过**：收到 install 这个动作的用法说明。这两条都只查看，不会安装或改动任何东西。
- **有问题**：收到模型的闲聊式回答，或者提示不支持；把发送时间告诉开发。

## 6. 私聊闲置锁（可选，另约时间测，不计入 5 分钟）

自动化测试把私聊锁关掉了，所以这一项只能手测。生产默认是开着的：默认闲置 10800 秒（3 小时）后锁定。

- **前提**：私聊锁已启用。这个解锁密码和 `/admin` 管理员绑定不是一回事。
- **怎么测**：闲置超过锁定时间后，再发任意一条消息。
- **算通过**：先收到一张输入密码的卡片；输对密码后，刚才那条被拦下的消息会照常被处理。
- **首次设置**：没设过密码时，原消息应暂存并提示设置；未设置前继续发消息不能绕过。首次设置成功后，原暂存消息只恢复一次。生产密码由本人填写，开发者不代填或绕过。

## 7. step17b 只读快查（可选，约 1 分钟，不挤进 5 分钟主流程）

在已绑定管理员的私聊里依次发下面三条，都只查看、不改任何东西：

1. `/recover owner`
   - **算通过**：返回历史未知执行轮清单，或者说明没有此类记录。生产上目前有 22 条历史记录，会列出来；**只看，不处置**。
2. `/settings show subagent_takeover_hint_enabled`
3. `/settings show enable_memory_search_tool`
   - **算通过**：后两条都返回参数说明、默认值、当前运行值和修改权限。生产上 step17b 已打开这两个开关，当前运行值都应是 `true`；不要把默认值 `false` 看成当前关闭。

- **只查看**：不要追加恢复处置、确认码或 `/settings set`。
- **说明**：这一步只验证管理命令和开关显示，不证明模型已经实际调用了 memory_search（它是模型工具，不是 `/memory_search` 命令）。
