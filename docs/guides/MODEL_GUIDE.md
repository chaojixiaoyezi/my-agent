# 模型管理使用说明

这份说明讲怎么在 my-agent 里管理模型：新增、切换、设置默认、调智能程度、删除、共享、给语义记忆选向量模型，以及让 my-agent 自己帮你做这些。入口都是实际界面（TUI 的 `/model` 菜单，或聊天里的 `/model`、`/effort` 命令）；界面细节以你实际看到的为准。

## 模型都存在哪里

- 每个用户的模型配置单独保存（`config/model-profiles/` 下按用户身份隔离），密钥保存后不再显示，也不会出现在列表回执、归档或日志里。
- `/model` 菜单顶层有五个入口：**新增模型、选择模型、管理已有模型、连接测试、默认模型与共享**（2026-09-30 改版）。
- 软件不预置任何模型；没配置时聊天会提示先配置，不会偷偷换成别的模型。

## 一、新增模型

### 1. 填接口地址和密钥（普通 API 服务）

1. 打开 `/model` →「新增模型」→ 选接口类型：OpenAI Chat、Anthropic、OpenAI Responses 或 Jev 决策。
2. 填接口地址和密钥。密钥输入时是掩码显示，保存后不再显示。
3. 点「拉取模型列表」读取这个服务商有哪些模型；拉不到时也可以手动填一个模型名。
4. 勾选要用的模型（可多选）→ 一次添加。服务商没给上下文大小时，勾选框里填一个统一值（默认 128000），之后可逐个改。
5. 请求头、会话头名称、思考档位、结构化输出等放在「高级」里；「OpenCode Go 模板」可一键填好公开地址和会话头名称。

小例子：加 DeepSeek 官方接口，选 OpenAI Chat，接口地址填 `https://api.deepseek.com`，密钥填 `sk-xxxx`，拉列表后勾上 `deepseek-chat` 和 `deepseek-reasoner`，一次添加。

### 2. ChatGPT Plus/Pro 账号登录后勾选

ChatGPT 订阅不需要填接口地址和模型编号：

1. `/model` →「新增模型」→「登录账号」→ 选 ChatGPT 订阅。
2. 默认用浏览器登录：自动打开官方授权页，登录并同意后自动跳回完成；SSH、无图形界面等环境会自动改用设备码（网页输入验证码）。
3. 登录成功后自动列出这个账号可用的模型，勾选（可多选）添加，之后在 `/model` 里切换即可。

小例子：你有 ChatGPT Plus 账号，登录后看到 `gpt-6-luna`、`gpt-5.6-sol` 等模型，勾选想用的几个，就能在会话里切换了。

注意事项：
- 具体模型能不能用、设备码是否可用，由账号套餐和官方安全设置决定，软件只是把账号登录进来。
- 订阅/OAuth 登录的模型**不能**共享给其他用户，也**不能**设为其他用户的初始模型。
- 通用 OAuth 2.0（非 ChatGPT）需要填接口地址、Client ID、设备码地址、令牌地址等，属于较专业场景。

### 保存规则

- 同名模型、不同接口/地址会分开保存（每条记录有稳定编号），不互相覆盖。
- 批量添加是整批保存：全部成功或全部不写；重复添加同名模型不会产生重复记录。

## 二、切换模型、设为新会话默认

### TUI（终端界面）

- `/model` →「选择模型」→「对话模型」：只改**当前这个会话**用的模型。
- `/model` →「默认模型与共享」→「我的新会话默认模型」：只改**以后新开的会话**默认用哪个，当前会话不变。

### 聊天里（IM 等，TUI 也支持文字命令）

- `/model`：查看可选模型列表（带编号）。
- `/model <编号>`：为当前会话选这个模型。
- `/model default <编号>`：把这个模型设为新会话默认。

小例子：在聊天里输入 `/model` 看到编号 12 是 MiniMax，发 `/model 12`，当前会话换成 MiniMax；再发 `/model default 12`，以后新开的会话默认也是它。

注意：
- 切换只影响之后的工作片；正在执行的任务仍用切换前的模型，不会被中途打断。
- 同一个用户开多个窗口，各窗口可以选不同模型；「我的新会话默认」只影响新会话。
- 列表里 `shared:` 开头的模型是管理员共享的；普通用户的「默认」行如果标注「管理员指定的初始模型」，表示没自己选过模型时实际会用管理员指定的那个。

## 三、思考档位 /effort（智能程度）

「智能程度」控制模型思考多用力，用 `/effort` 命令查看和设置。

### 档位含义

| 档位 | 意思 |
| --- | --- |
| auto | 自动：不额外发参数，用服务商默认的思考方式 |
| off | 关闭思考（更快，但更容易答错） |
| low / medium / high | 低 / 中 / 高 |
| max | 最高 |

### 常用命令

- `/effort`：在 TUI 里会弹出档位菜单，上下键选好回车就设上（Esc 取消，什么都不改）；在飞书等聊天里会显示当前档位、在当前模型上怎么生效，最后一行列出能选哪些档位。
- `/effort low`（或 off / medium / high / max）：设置当前会话档位。
- `/effort default`：清除设置，回到全局默认（仓库默认 auto；全局默认可以用 `/settings` 改 `model_reasoning_effort`）。
- `/effort probe`：让软件后台实测当前模型支不支持调节，可能要几分钟，完成后 `/effort` 查看结论。
- `/effort revert <编号>`：撤销一次自动检测写入的修改。

### 不同模型实际怎么生效

同一个档位在不同服务商上效果不一样，软件按模型实际支持的方式发送参数：

- **按档位发送（effort）**：OpenAI 兼容接口发 `reasoning_effort`，Anthropic 兼容接口发 `output_config.effort`。DeepSeek 官方 OpenAI 兼容接口、ChatGPT 订阅的 Responses 接口默认走这种方式。
- **按预算发送（budget）**：Anthropic 兼容接口发思考预算（low≈2048、medium≈6144、high≈12288、max≈上限，再按输出上限夹取）；OpenAI 兼容接口只发开关。DeepSeek 官方 Anthropic 兼容接口默认走这种方式。
- **不支持（none）**：不发任何参数，`/effort` 会明确告诉你「当前模型不支持调节」，设置暂不改变请求；换到支持的模型后生效。
- **自动判定（auto，默认）**：只对实测确认过的服务商给默认方式（DeepSeek 官方、ChatGPT 订阅），其余一律按不支持处理；可以在模型编辑「高级」里显式声明控制方式。

**ChatGPT 订阅（Responses 协议）的特殊对应**：档位按服务商声明的可用档位对应——low / medium / high 取同名；max 依次尝试 max → xhigh → high，取第一个存在的（也就是不支持 max 时自动退到 xhigh 或 high）；off 只在服务商声明支持关闭思考时发送，否则不发、交服务商默认。没有声明档位的模型只发通用的 low / medium / high。

小例子：给 ChatGPT 模型设 `/effort max`，如果服务商只支持到 high，软件会自动按 high 发，不会报错；DeepSeek 官方接口设 `/effort low` 会真的减少推理量、回答更快。

### 各模型实际能不能调（2026-09-30 逐模型实测）

同一道题、每个档位多次实测后得出的结论（按模型档案声明为准，你添加的模型以它自己的声明为准）：

| 模型 | 大白话结论 |
| --- | --- |
| ChatGPT 订阅模型（如 gpt-6-luna） | **能调**（low 到 max），但没有「关闭思考」档（目录没声明） |
| DeepSeek 官方（OpenAI 兼容 / Anthropic 兼容） | **能调、能关**（部分题目上 low 和 max 差距小，属正常波动） |
| opencode 的 deepseek-v4.1-flash | **能关思考**，档位作用弱 |
| opencode 的 deepseek-v4-flash | **调了没效果**，按不支持处理 |
| MiniMax-M2.7 | **总是深度思考**，调了没效果，按不支持处理 |
| MiniMax-M3 | **只能开 / 关**（按思考预算处理） |

小例子：你在 opencode 的 deepseek-v4-flash 上设 `/effort max`，回执会如实告诉你当前模型不支持调节、设置暂不改变请求；换到 DeepSeek 官方或 ChatGPT 订阅模型就能真正调档。

### /effort 回执会如实告诉你实际发送什么

- 模型不支持「关闭思考」时，回执会明说「本设置不改变请求」，不会假装已经关掉。
- 档位被服务商声明换算时，回执会写**实际发送的档位**：例如你设 `/effort max`、服务商只声明到 high，回执写「实际发送 high」；模型不支持调节（没有声明思考控制方式）时写「本设置不改变请求」。

小例子：给未声明档位的 ChatGPT 模型设 `/effort max`，回执显示「实际发送 high」——这就是这个模型当前真正收到的档位，不是软件偷懒。

注意：调低或关闭思考会降低正确率，这是模型本身特性，不是 bug。

## 四、删除模型

### TUI 菜单

`/model` →「管理已有模型」→ 最后一行「删除模型（勾选一个或多个）」：只列你自己添加的记录，勾选一个或多个，确认一次后逐个删除；单个失败会说明原因、不影响其它。

- 正在用作「新会话默认」的模型会拒绝删除，先改默认再删。
- 删除后正在执行的请求不中断，但下一次调用会明确报错，不会偷偷换别的模型。

### 让 my-agent 删

直接说「删掉 xxx 模型」，它会用删除模型（`delete_model`）/ 删除服务商（`delete_provider`）完成；删服务商会连密钥一起删（不可恢复），需要你确认一次，而且要先删掉这个服务商下面的所有模型，否则会提示“请先移除该服务商下的模型”。

## 五、管理员：共享模型、给其他用户指定初始模型

管理员（本机 main 用户）可以把模型开放给同一台 Gateway 上的其他用户：

- **共享给其他用户**：`/model` →「默认模型与共享」→「共享给其他用户」，逐个勾选要开放的模型。共享只保存引用、不复制密钥，用户使用时由服务端解析管理员的配置；费用由被发布的模型账号承担（确认框会说明）。撤销共享不影响正在执行的请求，但之后用户再用会明确报错。
- **其他用户的初始模型**：`/model` →「默认模型与共享」→「其他用户的初始模型」，指定一个模型给「没自己选过模型」的普通用户（包括飞书等 IM 用户）当默认，让他们不配置也能直接对话。设置时会自动先把该模型开放共享；撤销共享会同次清除初始模型。

小例子：管理员把 MiniMax 共享出去并设为其他用户的初始模型；飞书里新来的用户没配置过模型，打开就能用 MiniMax 对话，列表里「默认」一行标注「管理员指定的初始模型」。

注意：订阅/OAuth 登录的账号模型不能共享、不能当初始模型；管理员自己的默认仍是部署配置。

## 六、派子代理时指定模型和思考档位

派子代理时（`create_subagents` 的 `model` 参数，整批或逐项）可以指定这个子代理用哪个模型：

- **管理员**：可以选自己目录里的任何模型（包括共享出去的）。
- **普通用户**：只能选**自己添加**的模型；管理员共享的模型（`shared:` 引用、或按模型名匹配共享模型）都不能点名，想用就省略 `model` 不填——子代理会继承当前会话的模型（父级会话本来就能用管理员共享/初始模型）。
- 单项 `items[].model` 优先于批次 `model`；省略时继承直接父级创建时的模型。
- `effort` 同样可以按批次或逐项指定智能程度；省略时继承父级档位。
- 孙代理默认继承它的直接父级；子代理的模型在创建时冻结，父级会话之后怎么切换都不影响它。

小例子：你说「这个任务用 MiniMax，子代理用 DeepSeek」，主代理派子代理时填 `model: deepseek-chat` 即可；如果你是普通用户而 DeepSeek 是管理员共享的，就省略 `model`，子代理自动继承当前会话用的模型。

### 怎么看子代理实际用的模型和档位

派出去之后，用 `list_agents` 看代理树，每个子代理节点都会带两个字段：

- **model**：实际使用的模型，显示为「名称（完整档案编号）」，例如 `deepseek-v4.1-flash（536c11f9-…）`（括号里是完整的档案编号，这里省略了后半段）；没指定（继承会话）时显示「继承会话默认」；读不到模型配置时显示「未知」。
- **reasoning_effort**：实际使用的智能程度档位，例如 `low`；没设置时显示「默认」。

小例子：你派了一个指定 `model: deepseek-v4.1-flash`、`effort: low` 的子代理，`list_agents` 里它的节点会显示 model 为 `deepseek-v4.1-flash（536c11f9-…）`、reasoning_effort 为 `low`；如果当时省略了 model，就显示「继承会话默认」。

## 七、让 my-agent 自己帮你管模型

不用自己进菜单，直接在聊天里说就行。my-agent 有模型管理工具（`manage_models`），能做的操作和菜单一致：列出、新增、批量新增、编辑、切换、设默认、删除、连通性测试、读取服务商模型列表、共享、指定初始模型。

| 你想做什么 | 怎么说 |
| --- | --- |
| 加一个模型 | 「帮我加个模型，接口地址是 https://api.example.com，密钥 sk-xxxx，模型名 xxx」 |
| 一次加一个服务商的多个模型 | 「帮我看看这个服务商有哪些模型，然后都加进来」（它先读取列表再批量添加） |
| 本会话换模型 | 「这个会话换成 MiniMax」 |
| 以后新会话默认 | 「默认模型改成 DeepSeek」 |
| 测试模型通不通 | 「测一下这个模型能不能用」 |
| 删除模型 | 「删掉 xxx 模型」 |
| 共享模型（管理员） | 「把 MiniMax 共享给其他用户」/「撤销共享」 |
| 指定初始模型（管理员） | 「给其他用户指定 MiniMax 当初始模型」 |
| 开语义记忆（管理员） | 「帮我开语义记忆」（向量模型和默认对话模型同一服务商主机时直接设好，否则请你去菜单里选；见第八节） |

安全边界：
- 密钥只在你那句话里出现一次；工具回执只显示「有没有密钥」，回复和归档都不会复述密钥。
- 删服务商会经统一确认门（密钥不可恢复）。
- 子代理运行中不能改模型目录，模型管理只由主会话代理做。
- 开关 `enable_model_profile_tool` 默认开启；关闭后代理不能管模型，但仍可用 `/model` 手动维护。

## 八、语义记忆 / 向量模型怎么开、花多少、存在哪

语义记忆的意思是：找记忆时除了按关键词，还按“意思”找，换个说法也能找回来。要按意思找，得先把文字变成一串数字（向量），这件事交给一个**向量模型**（也叫嵌入模型，只算向量、不聊天）。默认是关的：只按关键词找，不发任何嵌入请求。

### 怎么开

1. 先加一个向量模型：`/model` →「新增模型」，用途选 `embedding`。小例子：MiniMax 的 `embo-01`，接口地址填 `https://api.minimaxi.com/v1`，密钥用你的 MiniMax 密钥。模型名以 `embo` 开头的按 MiniMax 自己的格式发请求，其它模型按 OpenAI 兼容的 `/embeddings` 发。
2. 选中它并打开语义记忆，三种方式任选一种：
   - TUI：`/model` →「选择模型」→「向量模型」，选中后保存；选「关闭（只按关键词召回）」就关掉。
   - 聊天里（飞书等 IM，TUI 也能打）：`/model vector` 查看，`/model vector <编号>` 选用，`/model vector off` 关闭。
   - 让 my-agent 自己配：直接说「帮我开语义记忆」。
3. **重启 Gateway 后才生效**。保存后菜单和回执都会写“重启 Gateway 后生效”；`/model vector` 能看到“当前运行”和“已保存、重启后生效”两种状态。

谁能改：向量模型是**全局设置**，所有用户共用一个，只有管理员（本机主账号）能改。普通用户（包括飞书用户）只能查看。普通用户自己的记忆暂时只按关键词找，各自开语义记忆是后续项。

my-agent 自己配的规则（用户 2026-10-02 拍板）：
- 只替本机管理员配；
- 只能选管理员**自己目录里**、用途是 embedding 的模型，别人共享来的不行；
- 向量模型和当前默认对话模型是**同一个服务商主机**（看协议、主机名和端口，不看路径）时直接设好；不是同一个主机就不改，告诉你去 `/model` →「选择模型」→「向量模型」里自己选。因为换主机等于把你的记忆发给另一家服务商，这一步要你自己点头。

小例子：默认对话模型是 MiniMax M2.7（`https://api.minimaxi.com/anthropic`），向量模型 embo-01 在 `https://api.minimaxi.com/v1`，主机相同，my-agent 直接设好；如果向量模型是另一家服务商的，它会说明主机不同、没有修改。

设好以后要重启 Gateway 才生效。管理员的 my-agent 有安全重启工具（`restart_gateway`，默认开）时，可能顺手安排一次安全重启（先排空再换进程，TUI 和 IM 自动重连）；要不要先问你，看审批模式（自主工作 auto 和完全放行不会问）。没有这个工具时，它会提醒你用 `/restart` 或在终端运行 `my-agent gateway restart`。

注意：工具的语义检索（`tool_vector_search_enabled`，默认开）和记忆共用同一个向量模型。选了向量模型以后，工具检索也会用它发嵌入请求。选向量模型的入口不会改这个开关。

### 花多少

- 每存一条新记忆，嵌一次（正文加英文关键词）。
- 每次找记忆，一般要把这次的查询嵌一次。
- 同一段文字嵌过就不再嵌：找记忆时先复用 `memory_vectors.json` 里已经存好的向量（2026-10-02 起，第一次召回不再把记忆重嵌一遍），剩下的再查正文哈希缓存。
- 换了向量模型，旧向量不能混用，语义召回会先退回关键词。管理员在终端运行 `my-agent memory vectors rebuild --confirmed` 把已有记忆重新嵌一遍，这一步按记忆条数花钱。
- 价格看服务商的嵌入价目，一般比对话便宜很多。

### 存在哪

- 存在每个用户自己的 home 里，和正式记忆同一个目录（`memory/long_term/`）：
  - `memory_vectors.json`：每条记忆的向量，和当时被嵌入的那段文字副本；删记忆时一起删。
  - `memory_text_vectors.json`：按文字哈希存的向量缓存，不存原文。
- 文件权限是 600（只有本机这个账号能读写），目录是 700。
- 向量只存在本机文件里，不进任何共享向量库。不过生成向量时，记忆正文会发给你选的向量模型服务商，所以只有管理员能选。

## 九、常见疑问

- **为什么发了图片，模型没有自动换成能看图的？** 按这一轮是否带图自动挑能看图的模型，需要打开决策模型的「选模型」点位，默认是关的。开了之后：
  - 新会话、或者历史里都是普通文字的会话：带图时会自动换成声明了能看图的模型（例如从 M2.7 换成 M3）。
  - 会话历史里已经有宿主判断不了、能否原样交给另一个模型的内容时（比如工具调用的特殊内容块、压缩摘要、思考内容），为了不丢信息、不让新模型读错历史，会保持原模型不换（系统内部把这个原因记作 `history_modality_unknown`）。这不是缺陷，是有意的保守设计。
  - 小例子：一个已经调过工具、派过子代理、手动压缩过的会话，这时再发图，决策模型虽然建议换 M3，宿主仍保留原模型；原模型如果不能看图，就看不到图里的内容。
  - 想让它看图：开一个新会话再发图；或者用 `/model` 手动切到能看图的模型。
- **后台记忆整理用的是哪个模型？** 默认（设置里 `memory_curator_model_profile` 留空）跟着“说这些话的那个会话”的模型走：
  - 小例子：你开了两个 TUI，一个用 MiniMax、一个用 DeepSeek，整理时两个会话的内容分别交给各自的模型，各调各的。
  - 会话没选过模型、或者选的模型用不了（被删、停用、订阅登出），就用你当前选中的默认模型，运行记录里会写明原因。
  - 某个会话的模型整理时输出的不是合规 JSON，这一次会自动换你的默认模型再试一次，运行记录里有 `curator_thread_model_failed`。
  - 想固定用某一个模型整理：用 `/settings` 把 `memory_curator_model_profile` 设成那个模型的编号（重启 Gateway 后生效）。
  - 固定的那个模型某个用户用不了（比如它只在管理员自己的模型列表里），这个用户就改用他自己的默认模型整理，运行记录里有 `curator_profile_unavailable_fallback`。
  - 用户自己没加过模型：整理用的就是他聊天用的那个默认（管理员指定的初始模型，或部署默认），运行记录里 `curator_default_model_source` 写明是哪个；两个都没有时聊天和整理都用不了，管理员在 /model 里给“其他用户的初始模型”指定一个即可。
- **为什么列表里没有我想要的模型？** 模型是每个用户自己的配置，管理员共享的才有 `shared:` 行；先「新增模型」添加。
- **为什么 `/effort` 说「暂不改变请求」？** 当前模型没声明思考控制（不支持调节），换到支持的模型后生效。
- **为什么我设了 `/effort max`，回执说实际发送 xhigh/high？** 因为服务商只声明到那一档：档位会按服务商声明的可用档位对应，max 依次尝试 max → xhigh → high，第一个存在且服务商支持的就是实际发送的档位；这是如实说明，不是软件没设上。
- **为什么删了模型还能用？** 正在执行的请求用的是冻结快照；下一调用会明确报错，不会换模型。
- **界面和我看到的不一样？** 以实际界面为准；这份说明按 2026-09-30 的菜单结构编写。
