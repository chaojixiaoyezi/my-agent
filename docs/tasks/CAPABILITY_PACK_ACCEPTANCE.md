状态：验收设计与来源静态盘点；能力包实现、迁移样本和真实 TUI 均未验收。

基线：`8392507288310ecd8f3c7537a2a93f7c91072a1c`。本文件只规定测试范围、判据与取证方法，不新增运行时状态、机器路由或行业合同。

## 1. 验收目标与证据边界

- Skill 学习继续保存个人或公共 Skill；整套能力吸收形成独立能力包。包内方法、脚本、模板和 workflow 不逐个注册到全局 Skill 库。
- 不改变已有插件随包全局 Skill 的发现、优先级、授权和停用语义；两条路径必须分别验收。
- 能力包复用现有安装、权限、工具执行、任务、子代理、停止和恢复权威。包内资料是领域上下文，不能直接授予执行权或制造第二套任务状态。
- A/B 包可以各自迭代、独立停用，组合任务必须真实衔接输入输出。形成融合包前保留来源与逐项对照，不能把多个说明文件拼接当作功能等价。
- 功能覆盖、自然召回、执行稳定性和内容质量分别记录。目录出现、模型自述“学会了”、文件存在、某个旧样片可播放，均不能单独证明完整能力迁移。
- “全部覆盖”只针对事先冻结的来源版本和完整功能清单；缺依赖、未迁移、未运行、质量未达标必须留在清单，不能从分母删除后宣称 100%。首期切片通过率另算。

当前只核对下列入口及部分相关实现/测试，未逐文件审完上游，也未运行上游程序、测试、安装脚本、模型或扫描工具。
本地来源副本的 Git 状态均干净；版本为该副本的 HEAD，本轮没有联网验证远端可达性、最新版本或热度。

- 所有真实业务验收必须由实际原生 TUI 输入普通中文需求。测试者给出该场景的一次初始需求后观察；生命周期用例仅追加预先声明的用户控制动作，不替代理补脚本、改产物或代执行业务。
- 常规主模型及子代理使用官方 MiniMax-M2.7。执行前核对实际 provider、请求端点和有效模型，不能只看 UI 名称；凭据仅记录来源类型和是否存在。
- 视觉判断单列官方 MiniMax-M3，用同一私有凭据引用；不得静默修改日常模型。M3 的图像理解不算 H3 视频生成或 imagegen 出图验证。
- 每个已协调测试环境共用一个真实 Gateway；多 TUI 是不同客户端和会话，不是增加 Gateway。发布、部署、重启由唯一负责人操作，先固定安装包摘要和回退依据。
- Gateway、测试 owner、并发额度和资源预算须由主线与运行环境负责人确认后登记；本文件没有分配端口、机器或实际 TUI 编号。
- 日志、真实会话编号、机器定位和完整取证留仓库外。仓库只保留脱敏结果和可公开的用例；不写个人路径、地址、凭据、原始私人材料或聊天原文。
- 故障只作用于专属夹具/测试操作。禁止真断网、杀用户服务、修改共享凭据，禁止业务代理通过重启承载自身的 Gateway 制造恢复场景。

## 8. 自然召回、质量和性能计量

先冻结一组普通中文需求，包含每个首期包至少 5 个适用场景、5 个同义/省略表达，以及合计至少 10 个不应启动专业包的负例。
保留一部分未用于调试的需求作最终验收；相同语义的新会话至少复测 3 次。确有多个合理包时记录可接受集合，不把合法选择算错。

- **发现率**：相关能力进入可读候选的次数 / 适用场景次数。
- **正确使用率**：真正读取方法并调用正确工具完成约定步骤的次数 / 适用场景次数；只报包名不算。
- **误启动率**：负例中启动无关专业流程或工具的次数 / 负例次数；只出现简短可用目录与实际启动区分。
- **交付通过率**：满足冻结输入输出、来源、格式、完整性和内容要求的次数 / 任务次数；框架成功与内容质量分列。
- **代价**：目录/候选/方法实际展开字节和 token、额外请求数、工具数、墙钟时间、峰值资源、重复执行次数。

以上数字随完整样本集和失败案例一起报告。有限用例全部通过只能表述为“该版本在这组用例通过”，不能外推任意任务稳定 100%。
比较开关关闭、单包和 A/B/C 并存时的同类任务；除包相关设置外固定模型、输入、工具权限和机器条件，避免把模型/供应商变化当作包收益。
创作质量用可解释的问题清单和独立复核，不以模型一次自评分或机械阈值替代实际判断；质量检查失败可返工，宿主硬门只守权限与客观事实。
