# 通用能力底座提升 —— 跨任务健壮性 + 摄取召回(零上下文,纯工程口径)

> **给谁**:从零接手的开发代理　**日期**:2026-07-04　**来源**:四类真机测试(长时盯守 / 大体量建站 / 多项目分析 / 大文件全扫)+ 终端应用 同模型对照 + 公开可靠性研究。原始发现见 `DEV_HANDOFF_four_category_field_test.md`。
> **总方针(贯穿全文,重要)**:
> - **加底座、不加限制**:别加"必须写够 N 行""禁止返回空"这种硬规则。问题本质不是"做不到",是"**同样能力时好时坏 + 最后一口没送到 + 该看的没喂给模型**"。要治的是**底座的稳健性/交付/召回**,让已具备的能力**稳定复现**。
> - **通用、不做专项**:机制对任意任务/任意数据流成立;判据可运行时从数据自己学,但**代码/提示里不写死任何具体类型的判据或内容**。
> - **守铁律**:理解由模型干、代码只结构化执行(计数/状态/签名),禁自然语言/关键词匹配。
> - 参考 **终端应用 / 会话运行时** 的做法与公开研究(reliability = 一致性+健壮性+容错;验收建在"任务真完成"而非"组件返回")。

## 0. 定性:能力是有的,缺的是"稳定 / 送达 / 召回"

**能力反复被证明**:本轮用户A 大文件四问全答对(数字精确)、3 小时盯守逐条报 217 条全真 0 误报;历史上代码/分析也多次做得不错。**所以病灶不是"不会",是三处底座薄**:①同任务时好时坏(一致性);②活干完最后一口送不到用户(交付);③该判的没被喂给模型(召回)。下面 Part A 治前两个(跨任务通用),Part B 治第三个(摄取召回)。

# Part A — 跨任务健壮性 / 交付底座

## A1. 【头号】交付保障收口层:活干完了,别空手送给用户

**现象+证据**:任务实际完成,但**用户收到的最终响应是空的**,或成果落 `work/` 内部没进 `output/`。
- 大文件分析:`u-t4a` 答案全对,但其 `responses/*.json` 的 text 长度=0(正确结论卡在流式中间层)。
- 多项目分析:主报告落 `work/` 内部、没进 `output/`。
- 建站:成果在 `output/`(能拿到),但最终响应文本也空(无收尾汇总)。
- (盯守类因上一棒 §2 逐条送达兜底,结论稳定送达了 217 条——**证明"兜底送达"有效,但只覆盖了盯守,普通任务没有等价兜底**。)

**底座方向(非限制)**:任务收口前加**确定性自检**——①最终响应是否非空、是否说清"干了啥 + 结论/交付在哪";②声明的交付物是否真在 `output/`。不满足则**自动从已完成的工作合成一份收尾汇总 + 归集交付物**再收口。把"验收建在'任务真完成'上"。**对标 终端应用/会话运行时:每个任务必以面向用户的收尾汇总结束、绝不空手返回。**

## A2. 持续干到真完成:大体量任务别半道自认完成

**现象+证据**:要求"功能齐全的大应用",两用户都到 ~5000 行就自认做完(`u-t2solo` 4692 / `u-t2disp` 5456),没堆到预期;对应研究里"**长任务 meltdown / 成功率随时长骤降**"。

**底座方向**:主循环用**完成度验收驱动**(功能清单逐项核对,没实现且可跑的继续),而不是模型"觉得差不多了"。对标 终端应用 **todo 逐项打勾闭环 + 收尾前功能核对**。不是硬性"必须 N 行"。

## A3. 关键步骤结构化自检 + 有界重试:压"双用户方差"

**现象+证据**:同任务同模型,一个漂亮一个残废——盯守 217 vs 18、分析覆盖 5/5 vs 1/5、大文件全对 vs 漏异常账户。这是公认老难题"**agent 能力强但不一致**"(采样随机 + 受措辞细微变化影响大)。

**底座方向**:关键步骤后加**结构化自检**("要分析 5 个、现只覆盖 1 个 → 继续")+ **有界重试**;把易漂移动作从"纯靠模型自觉"改为"**结构信号驱动的闭环**"。目标是压方差,不是禁止某行为。

## A4. 持续型任务的委派语义:盯守被外包别停摆

**现象+证据**:盯守(无终态的持续型任务)被主代理**派给子代理**,子代理按"做完即退"**提前 DONE 退出**,整任务停摆(`u-t1b` 只 18 条;`wake_queue` 有 `subagent-finished...DONE`)。

**底座方向**:把**任务生命周期语义**下沉到底座——持续/驻守型任务委派时,子代理**继承"不到窗口不退"语义**,或由主代理自己扛不外包。补底座对"任务类型"的认知,不是禁止派子代理。

# Part B — 摄取召回底座:补"结构预筛"的盲区(监控漏了 3/4)

## B1. 事情本身:漏在"筛",不在"判"

盯守分两段:**①"筛"**(结构预筛/引擎挑候选)→ **②"判"**(模型逐条定性+报)。真机(3h、891 真目标):

| | 数 | |
|---|---|---|
| 真目标 | 891 | |
| **筛出给模型(候选)** | **234 = 26%** | ← 瓶颈 |
| 判+报出 | 217 | =筛出的 92%、**0 误报** |
| 漏 | 674(76%) | ~657 是"筛"就没筛出、~17 筛了没报 |

**分源盲区极不均**:一个源 **0/177(完全瞎)**,另一个 54%。**判得极好、被"筛"饿着**:结构筛只认"结构异常",而很多真目标"语义上真、结构上和常态一样",结构筛天生盲、某些形态直接 0%。**调某类参数治不了通用问题。**

## B2. 【模型抽检通道】别让"结构异常"成为进模型的唯一门票
加一条**抽检车道**:用模型空余判力,对"筛"放过去的常态流**按结构化规则抽有代表性样本**(每 N 条/分层)让模型判,撞见结构筛盲区。**通用**(零专项判据)、**有界**(抽样率固定=负载固定)、**守铁律**(抽样结构化、判定归模型)。

## B3. 【反馈学习】模型确认的"漏网真目标"→ 让"筛"学会以后自动抬同类
模型一旦确认一条"筛漏了的真目标",把它的**结构特征**反馈给筛、让筛以后**自动抬同类**(纯结构签名/首记号,不记内容)。与之前"从没目标的样本猜 target"(不稳)**根本不同**——这里锚定在**模型已确认的真目标**上,稳;盲区源召回由此从 0% 跳上去、机制自愈、无需人给判据。

## B4. 【自适应倾斜】抽检力度往"筛得差"的源上倾斜
按每源"筛出率/抽检命中率"的结构化统计,**筛得好的少抽、筛得差的(那个 0% 的)多抽**,力气用在刀刃。

## B5. 诚实边界
目标很稀疏(~1/3000),纯随机抽检对稀疏目标效率低 → **B3 反馈 + B4 倾斜是关键**;召回天花板 = 结构筛抬的 + 抽检撞见的 + 反馈学会后补抬的,受模型判力吞吐约束、**不会到 100%**,但要从 26% 显著上去、盲区源(0%)被救活。真实大规模监控/质检就是"机检 + 抽样复核 + 反馈"。

## 参考(方法来源)
- **终端应用 / 会话运行时**:任务必以面向用户的收尾汇总结束(不空手)、**todo 清单驱动**的持续闭环、收尾前核对成果。→ A1/A2/A3。
- **公开研究**:reliability=一致性+健壮性+容错;**验收建在"任务真完成"而非"组件返回"**;自检/重试/确定性合成保证输出;长任务防 meltdown。
- 可续查:*agent reliability / task completion verification / long-horizon robustness / sampling audit for monitoring recall*。

## 优先级(建议)
1. **A1 交付保障收口层**(头号,普适、见效快:普通任务从"空手"→"必送达")。
2. **B2+B3+B4 摄取召回底座**(把监控从 26% 往上、盲区救活)。
3. **A2 持续干到真完成**(治耐力,顺带压 A3 方差)。
4. **A3 结构化自检+重试**(治一致性)、**A4 持续型委派语义**(治盯守被外包停摆)。

## 约束
- **加底座不加限制**;**通用不专项**;**守铁律**(结构信号驱动、理解归模型)。
- 别破已验证 OK 的:**判这环 0 误报 / 逐条送达(§2) / 引擎宽抬+重判(§7) / 两层限流 / 建站交付**——本棒是**加保障层/闭环/抽检反馈通道**,不推翻现有。
- 过质量门(体量闸 strict `hard=0 high-risk=0` + 全量测试无新增回归)、每块真机回归(含多种不同结构的数据)、做完在本文档回填「已修+commit+数据」、纯工程口径。

## 本棒教训(接手者可复用)
- 离线台不是走形式:洪泛闸"被拒也计额"的永久闸死 bug 只有连续流台子才暴露(单测批量太短);**台子的时间轴形态(窗口是否持续占满)必须贴真机**,否则基线/上限双向失真。
- 反馈学习登记特征必须过**多数派过滤**(占字段样本过半不入围),否则确认事件里的共有字段(kind=login)会让反馈车道连常态一起抬。
- 贴线阈值型存量测试(compact 20k 窗口)对"模型可见文本合法增长"敏感:修比率不修语义。
