# 需求文档 · 盯守研判能力(零上下文 / 脱敏 / 直观)

> **给谁**:来把这套功能建/完善出来的开发代理　**日期**:2026-07-07
> **一句话目标**:要一套"盯守 + 研判"能力——从各种来源的记录里,把【真正要紧、需要人知道的事】一条不漏地挑出来报给用户,其余的不打扰。

---

## 先对齐核心认知(免得走偏,这几点是踩过坑得来的)

- **模型自己有判断力,能读懂一条记录、判断它要不要紧。** 已实测:把单条记录直接给模型,它判得很准(3/3)。
- **所以核心不是"教它怎么判 / 建规则库",而是"让它好好读、好好判"。** "先学日志结构 → 存规则库 → 按结构相似度匹配复用"那套**不要做**——来源几百上千种、手写不了结构,也没必要(模型本来就读得懂)。
- **之前的坑**:流程把记录**囫囵一大批扫一眼、一句"都没事"就打发**了,把模型的判断力浪费了、真要紧的事全漏了。**要让它逐条(或小批)认真读、把该对起来看的对起来看。**

---

## 七块需求

### 1. 核心 = 研判(读得懂、判得准)
逐条(或小批)认真读记录,判断"是不是真要紧的事",是就单条报、不是就放过。**不搞学结构/规则库那套。**

### 2. 四种"进数据"的方式(都要会)
1. **读流**:盯一条持续在涨的流。
2. **定时查接口**:每隔一段时间去查一次某接口,再研判。
3. **读大文件**:给它一个大文件,读完把要紧的挑出来。
4. **定向查 + 联合研判**:指定它查某接口、带某参数,把**多个来源的结果凑一起交叉印证**着判。

### 3. 正常量:让它好好读好好判
- 正常一天 **1000–100000 条**需要研判(上游设备已帮忙滤掉大部分没用的)。
- 这个量平均下来不大,**够模型逐条认真读**。别为省事囫囵扫。

### 4. 洪水:要能承接、优雅降级(边角保护,不是常态)
- 万一某段时间量暴涨(比如每秒上百条、持续几小时),**不能被淹死/崩掉**。
- 要有办法承接:**便宜地把明显没事的先滤掉(按内容,别误滤真事)、把"认真读"留给可疑的少数**;实在扛不住也要**有序降级 + 可核算**(丢了多少、凭什么丢),**绝不静默漏真事**。
- 别为这个边角把常态设计搞复杂。

### 5. 主代理自由:监控派给子代理
- 主代理**不亲自盯**这些流/接口——那会把它占死、用户找不到人。
- 主代理把监控**派给子代理**去盯,自己空出来:**随时能跟用户沟通、能接新活**。
- 子代理盯到真要紧的事,通过**事件叫回**主代理 / 报给用户。

### 6. 子代理存活 + 接管(挂了要有人接)
- 主代理要**随时发现盯守的子代理挂没挂**。
- 一旦子代理挂了,主代理**及时派一个新的接上,从挂掉的地方继续盯**(不重头、不漏段)。
- 这理论上做得到,因为**子代理有自己的"家"**——它的进度/游标/状态存在自己的工作区里,新子代理能接着它的进度往下干。

### 7. 轻量记忆:教一次别重讲
- 用户教它"**这个来源 / 这类事该怎么看**"(给几条样品 + 描述判据,用户不一定有真事正例,但会描述标准,模型有脑子自己领会)。它**记住**。
- 以后同一来源 / 同类事,**不用每次重讲**。
- 这是"**轻量记住用户教的判据**",不是那套复杂规则库。

---

## 怎么测(验收 · 每条都要真机验)

- **四种方式**各测一遍:读流 / 定时查接口 / 读大文件 / 定向查+联合研判,都能正常把真要紧的事挑出来。
- **正常量**(1000–100000/天):真要紧的事**抓得全、不瞎报**。
- **洪水**(每秒上百、持续几小时):**不崩、有序承接、丢弃可核算、不静默漏真事**。
- **主代理自由**:监控跑着的时候,**主代理还能随时回应用户**(不被盯守占死)。
- **子代理接管**:**故意把盯守子代理杀掉**,主代理要能**发现并派新的接上、从断点续、不漏段**。
- **轻量记忆**:教一次,重启 / 隔一段时间后,同类来源**不用重教**。
