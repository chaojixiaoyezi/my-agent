# 盯守·真实难判场景几乎抓不到真事(测试方初诊 + 现场自查指引 + 3 个坑)

> **给谁**:正在干活的开发代理(接手过监控过滤器那份的同一个人)　**日期**:2026-07-07
> **怎么用**:等你把手上的活干完,**自己上 1.9 把下面这个诊断【确认+挖深】,然后在你正改的代码上接着修**。别当定论、也别盲挖——下面既给了我(测试方)的初诊,也标了 3 个你极容易踩的坑。

---

## 现象

1.9 上有个**真实稀有场景**的盯守测试:5 个记录源、每条记录带【请求】和【响应】,真事(真出状况的)约 **1/1000**,判真假**只能把请求和响应对起来读**(单看一个字段没用)。跑了约 1 小时、冒出 ~50 个真事,**两个盯守用户几乎一个都没抓到(0~1)**。

对照:1.10 上那个盯守抓到 ~30%——但那是**18% 密度 + 目标只看一个字段值**的简单场景,判读是白给的。两者一比就知道:**难判场景下现在漏得离谱。**

## 测试方初诊(供你确认,别当定论)

1. **真事隐蔽但确实可分辨**。举一条抓到的真事:
   - 请求让后端做一件**耗时的事**(相当于"你先睡 5 秒再回我");响应真的花了 **7.29 秒**才回、还带出了数据 → **这事真被执行了 = 真事**。
   - 旁边一条:请求做了**同样的企图**,但响应是"失败 / 被拒绝" → **没成 = 非真事**。
   - 另一类:请求去取了**本不该看的那一页数据**,响应**真把数据返回了** → 真事;返回"空 / 被拦"→ 非真事。
   - **要点:真假 = 把"请求想干啥"和"响应有没有真让它得逞"对起来读。测试是公平的,不是分辨不了。**
2. **模型没认出来**:agent 是**一批一批扫、然后写"这批 N 条全 blocked / 没事"的总结**,把这些隐蔽的真事全归进"没事"漏掉了。核心是"请求企图 ↔ 响应成功迹象"这个关联没连上。
3. **有"学规律 / 配规则"的活动痕迹但没生效**(用户产物里有 20+ 个含 learn/configure 的文件,可抓取率还是 0)——这恰好说明"按内容学规律"这条路**装了没学对**,不是没这条路。

## ⚠️ 3 个坑(极容易踩,先看)

1. **测量假象——别去追"瞎报 bug"**:测试方的抓取率算子会把"这批全 blocked"总结里**提到的编号**当成"上报的真事"数,于是你会看到"0 抓到 + 一堆瞎报"。**那一堆不是真瞎报,是漏**。判"抓到没"要看 **agent 有没有真把某条判成真事、单独报出来**,不是数 findings 里出现过的编号。
2. **别一眼就说"分辨不了、测试不公平"**:真事很隐蔽,不去把请求+响应拉全逐条对(耗时操作↔响应时长、越权↔是否真返回数据),很容易草率甩锅。它们**是能分辨的**(上面例子)。
3. **病因别拍脑袋**:是"模型判不动"、"最新代码把盯守判读搞回归了"、还是"learn 没生效"?——**要跟历史对比**(以前同类稀有场景能抓到八九成)**+ 查 learn 状态**才能钉死。三种修法完全不同,别猜。

## 现场怎么查(1.9 · `ssh openeuler` · **只读** · 加 `-o ServerAliveInterval=10` · 别用 heredoc)

- 真事清单(答案键):`cat /root/sec_ak.jsonl`(每行一个真 event_id + 源)
- 拉某条真事全文对请求响应:`curl "http://127.0.0.1:<端口>/pull?since=<seq-1>&limit=1"`(源→端口:8901/8902/8903/8904/8905;seq = event_id 末尾数字)
- agent 到底报了啥(是"全 blocked 总结"还是单条真事):`find /root/.my-agent/owners/providers/feishu/users/u-sm1 -name findings.jsonl -exec cat {} +`
- 引擎判了多少:`u-sm1/watch_state/ws-*.read.json` 的 `candidates_consumed`
- **测试方现成的诊断脚本可直接跑参考**:`/root/diag_sec.py`、`/root/diag2.py`、`/root/sec_recall.py u-sm1`
- **只读,别动任何东西**(别重启、别改、别 kill)。

## 修法方向(钉死病因后再动)

- **若是"冷批扫漏隐蔽真事"(最可能)**:呼应你手上那份《监控过滤器》——别让模型冷批扫再拍"全 blocked";改成**按内容学真事的形态规律**(请求企图 X ↔ 响应出现 X 得逞的迹象),把这类关联沉淀成**内容判据 / 规则**,逐类研判;频率只触发"去看看这类",内容决定真假。
- **若查出是最新代码回归**:定位最近改动(尤其判读/摄取/spec 那几处),回归修复。
- **判读判据要建立在"请求↔响应关联"上**,不是单看一个字段;守铁律(结构化形态,不是自然语言关键词)。

## 验收
真实稀有 + 难判(请求响应关联)场景:真事抓取率明显抬起来(不再 0),且**报的是真事、漏得少**;隔离环境自测贴真实数据;真机由测试方独立复验。
