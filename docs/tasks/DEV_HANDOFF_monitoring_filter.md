## 问题 · 引擎"按百分比/频率过滤"记录,会把真事整批扔掉

### 现象(前因后果)

盯守要"稀有的真事一条别漏"。但引擎里有个减负机制:**它统计每个【结果端字段取值】在滑动窗口里出现的频率,某取值频率一旦超过阈值%(常态线),就判定这类是"常态",整批压掉、不再抬给判读。**

- 真事**稀有**时(比如几千分之一),它的取值频率远低于常态线 → 过滤器碰不到 → 盯守本来抓得挺好(历史真实稀有场景抓到八九成)。
- 但**只要真事变得频繁**(占比撞上那条百分比线),它就被当"太常见的常态"**整批扔在判读之外**——保安连看都没机会看。

上一棒对这个的"修复"是**把阈值从 2% 调到 25%**。这是**错药**:只是把线挪了挪,没换判据——真事哪天占比过 25% 照样被整批扔。**换数字不换病。**

### 证据

`docs/tasks/evidence/monitoring_filter/mechanism_and_data.md`:
- 机制代码位置(`ingestion/config.py` 的 `outside_normal_common_value_pct` + `ingestion/engine.py` 的 `SlidingWindowCounter` / `_suppressed_spec_hit` / `_suppress`)。
- 实测对照表:真事 18% 密度时,旧阈值 2% → 一段时间 ~18300 个真事只抓到 618/1526 个(整批被当常态扔);补丁 25% → 抓到 410/615(靠"没撞线"侥幸);真正稀有(1/3000)→ 本就抓得好(没撞线)。**抓得好不好取决于真事有没有撞上百分比线,而不是系统会不会研判——这本身就证明判据错了。**

### 根因

**拿"频率/百分比"当"是不是常态、该不该扔"的判据,是根本性错误**:
- 它零内容理解——不看请求、不看响应,只数取值出现多少次。
- "频率高 = 常态"这个假设本身就错:真出状况的事完全可能频繁发生。
- "事情多"被当成了"可以不研判"的借口——用盲扔来减负,等于放弃了盯守的本职。

### 修法方向(**换判据:频率触发调查、内容决定去留**)

把"按百分比免疫/丢弃"整条路**换成"按内容研判 + 内容过滤规则"**:

1. **移除/停用一切"按百分比免疫丢弃"的判据**(`outside_normal_common_value_pct` / `spec_target_common_value_pct` 这类频率阈值当去留依据的路径)。2%→25% 那个补丁不是终点,是要被替换掉的对象。
2. **频率只当触发器,不当决定**:某取值/某形态出现得频繁 → 触发"**去看看这一类到底是啥**"(按内容研判:这类记录的【请求】长这样、【响应】是不是那样),而不是直接扔。
3. **判为噪声 → 建一条【内容过滤规则】**:针对这一类(按请求/响应的结构化形态,不是关键词)生成一条过滤规则,可**临时生成**、也可**学出来复用**(复用已有 learn 车道:learn→configure→monitor)。以后这一类命中规则就不必逐条重判,达到减负——但减负来自"研判过、认得它了",不是"它太多懒得看"。
4. **判为真事 → 照报**(哪怕它频繁)。
5. **规则要可见可审计**:建了哪条规则、按什么内容判据、拦了多少、放行多少,都要能查、不静默。

**铁则(写进代码注释也行)**:量大 ≠ 可以不研判;事情多就**按【类】研判一次、建规则复用**,而不是按百分比盲扔。**去留规则永远来自内容判断,不来自计数阈值。**

### 验收(测试方真机 + 你隔离自测)

- **真事频繁也不被误杀**:构造真事占比较高(如 10–20%)的流,盯守**不再把真事整批扔**(旧机制/补丁都会),而是按内容认出它们照报。
- **真事稀有仍抓得好**:稀有真事(~1/1000~1/3000)场景抓取率保持高位(不回归)。
- **减负仍在**:高频噪声类被【内容规则】认出后不再逐条重判(吞吐不塌),但**任何被规则拦下的类都可核算可见**(建了哪条、拦了多少),零静默丢弃。
- **零"按百分比扔真事"**:代码里不再有"频率超阈值即丢"的去留判据。
