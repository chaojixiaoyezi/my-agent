# 摄取召回通用底座 —— 补"结构预筛"的盲区(模型抽检 + 反馈学习,非专项)

> **给谁**:从零接手的开发代理　**日期**:2026-07-04　**来源**:长时盯守真机测试(5 路高吞吐流、3 小时、真目标 ~1/3000 共 891 个)
> **总方针**:**通用底座,不做针对某一类数据的专项**。机制要对任意数据流都成立;判据可由运行时从数据自己学,但**代码里不写死任何具体源的判据/内容**。守铁律:理解由模型干、代码只结构化执行。

---

## 1. 事情本身:漏在"筛",不在"判"

盯守分两段:**①"筛"**(结构化预筛/引擎,从高吞吐流里挑出"值得模型看"的候选)→ **②"判"**(模型逐条定性、命中即报)。

真机实测(3 小时、891 个真目标):

| | 数 | |
|---|---|---|
| 真目标总数 | 891 | |
| **筛出来给模型的(候选)** | **234 = 26%** | ← 瓶颈在这 |
| 模型判 + 报出的 | 217 | 报出=筛出的 92%、**0 误报** |
| 漏掉 | 674(76%) | 其中 **~657 是"筛"就没筛出来**、~17 是筛了没报 |

**分源看,盲区极不均**:一个源筛出率 **0/177(完全瞎)**,另一个源 54%。

**判断**:**模型判得极好(0 误报、筛出的抓 92%),但被"筛"饿着——只喂进来 1/4。** 病根:**"筛"是纯结构的,只认"结构上异常";而很多真目标是"语义上"真(要读懂成对内容、判两段对没对上才知道),"结构上"和常态一模一样。** 结构筛对这种目标**天生盲**,某些形态直接 0%。**再怎么给某类数据调参数也治不了通用问题。**

---

## 2. 通用底座方向:别只让"结构筛"决定模型看什么

核心矛盾:**流太快模型读不过来** × **结构筛对语义目标是盲的** → 大量真目标从"筛"这一环漏光。通用解法三件套(都对任意数据流成立、都不写死具体判据):

### 2.1 【模型抽检通道】给模型一条"查漏"通道,抽检"筛"放过去的流
不要让"结构上异常"成为进模型的唯一门票。在摄取底座加一条**抽检车道**:用模型的**空余判力**,对"筛"判为常态、放过去的那条流,**按结构化规则抽一个有代表性的样本**(如每 N 条抽一条 / 分层抽样),让模型判。
- **通用**:对任何数据流都一样,零专项判据。
- **有界**:抽样率固定 = 模型负载固定,不会淹。
- **守铁律**:抽样是结构化的(每 N 条/随机),判定是模型的。
- **作用**:结构筛的盲区(那 0% 的源)由此有机会被模型撞见。

### 2.2 【反馈学习】模型确认的"漏网真目标"→ 让"筛"学会以后自动抬同类
抽检(或已筛出的候选)里,**模型一旦确认一条"结构筛漏了的真目标"**,就把这条的**结构特征反馈给筛**,让筛**以后自动抬同类**(纯结构化:记住该源该形态的结构签名/首记号等,不是记内容)。
- 与之前"从没有目标的样本里猜 target"(不稳)**根本不同**:这里的学习**锚定在模型已确认的真目标上**,是有据的、稳的。
- 一旦学会,那个源的召回从 0% 跳上去——**盲区被通用机制自己补上,无需人给判据**。

### 2.3 【自适应倾斜】把抽检力度往"筛得差"的源上倾斜
统计每个源的"筛出率 / 抽检命中率",**结构筛覆盖好的源少抽、覆盖差的源(如那个 0% 的)多抽**。把有限的模型判力用在刀刃上。
- 通用:靠每源的结构化统计自适应,不认具体是什么数据。

---

## 3. 诚实的边界(别高估)

- 目标很稀疏(~1/3000),**纯随机抽检对稀疏目标效率低**——所以 2.2 反馈学习 + 2.3 自适应倾斜是关键(把力气集中到盲区、且盲区一旦被撞见就"学会"批量抬)。
- 召回天花板 = **结构筛抬的 + 抽检撞见的 + 反馈学会后补抬的**,受**模型判力吞吐**上限约束,**不会到 100%**;但能从 26% 显著往上、且**盲区源从 0% 被救活**。
- 这套是**摄取底座的通用能力**(自动化筛 + 模型抽检审计 + 反馈自愈),不是给某类数据的专项——真实大规模监控/质检就是这么干的(机检 + 抽样复核 + 反馈)。

---

## 4. 验收(通用口径)

用**多种不同结构**的花数据流各测一遍(至少含"结构筛天生盲"的那种):
- 端到端召回较纯结构筛(~26%)**显著上去**;**原本 0% 的盲区源被救活**(> 0 且随反馈上升)。
- 误报仍接近 0(判这一环本就强,别破)。
- 全程**无任何针对具体数据类型的硬编码判据**;抽检率/倾斜/反馈都是**结构信号驱动**。

---

## 5. 约束

- **通用机制,不写死任何具体源的判据/内容**;判据运行时从数据学(锚定模型确认的真目标)。
- 铁律:代码判断只用结构化信号,理解交给模型。
- 别破已验证 OK 的:**判这一环(0 误报)、逐条送达(§2)、引擎宽抬+重判(§7)**——本棒是在"筛"这一环之前/之上**加抽检+反馈通道**,不是推翻现有。
- 过质量门(体量闸 strict hard=0 high-risk=0 + 全量无回归)、真机回归、纯工程口径。
