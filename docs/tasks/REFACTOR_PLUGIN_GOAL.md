# 十步重构与插件交付执行 Goal

状态：已获实施授权；当前先进行基线发布和同版部署，十步尚未开始，Goal 待部署验收后创建。
整体顺序由 [合并重构计划](../design/MAINTAINABILITY_AND_JEV_REVIEW.md#下一轮结构整理顺序待实施) 维护；本文记录执行状态和详细验收。
插件合同见 [生命周期](../design/PLUGIN_LIFECYCLE.md)，样本范围见 [10 个简易插件](../design/PLUGIN_SAMPLE_ACCEPTANCE.md)。

## 目标和范围

在功能和持久数据正确的前提下，降低模块间隐含依赖，提高可读性、可维护性、可扩展性及实现清晰度。
交付可安装、可停用、可卸载的 Python 插件接口与 10 个实际可用的简易插件；普通可选插件装卸不重启 Gateway。
Audit/摄取重构、auth 和 Jev 不在本轮范围，原有功能保留；共享模块受影响的既有回归仍须通过。
不要为了减少行数而削弱有效注释；删除无调用旧入口、过期注释、空转发与废弃代码，同批迁移全部直接调用方。
模块只接收实际所需能力；保持唯一状态源、权限门、工具执行链、历史与恢复协议，不能出现同义执行器或大上下文换名。

## 发布与部署前置条件

1. 审查从远端 main 到候选提交的全部相关 diff，确认当前文档与行为一致，隐私和原始测试资料不入仓库。
2. 跑相关 focused tests；发布范围的生产/测试增删超过约一万行时追加全仓 pytest。Ruff、doc sync、strict code-size、diff 与 clean-package 均通过后才能推送 main。
3. 核对远端 main 最新值，按正常快进发布；不覆盖其他人的新提交，不强推。确认远端实际 SHA，线上 CI 单独记状态。
4. 同一提交构建一个 non-editable wheel，记录校验和；本机和确认的测试机使用同一 wheel，各自保存旧 runtime、启动配置与回滚证据。
5. 在停止 Gateway 前确认活动任务和资源归属；每台机器只有一个 Gateway，默认 TUI 和 Gateway 使用同一个新 runtime。原会话、工作目录、权限和个人模型配置保留。
6. 每台机器从默认安装入口打开至少两路真实 TUI，验证官方模型、工具读写及子代理，核对实际包位置与进程；测试输出由 my-agent 自行生成。
7. 前置验收通过后创建详细 Goal，并进入第 1 步。单纯安装成功、端口监听或旧 TUI 的历史记录不能代替部署验收。

## 模型与环境约定

- 所有真实功能验收从实际 TUI 进入；普通中文需求只给一次，测试者观察并执行明确的控制/审批，不代做任务或补产物。
- 常规使用官方 MiniMax-M2.7；视觉使用官方 MiniMax-M3，复用 M2.7 的私有 provider/密钥引用，只切换模型名。核对实际端点、模型和图片输入事实。
- 测试可以放在本机或测试机；每个切片明确环境、源码/安装包 SHA、实际 Python/包路径和有效配置来源。日常默认模型不静默替换。
- 每步至少两路独立真实 TUI：一路运行受改动影响的任务，一路运行普通内置任务作为对照；控制、插件装卸及并发场景增加第三路或更多。
- 开始前报告实际 TUI 编号、tmux 会话/窗口及查看命令，不能提前编造编号；每台机器共用单 Gateway。
- 短任务验证后再运行有实际处理内容的连续长任务；涉及调度、子代理、工具循环及最终组合时，包含至少一轮约 15–30 分钟的持续任务，不能只靠空睡眠凑时长。
- 开发反馈使用合同、替身、回放与定向回归；这些与真实 TUI 分开记账，不能替代最终真实验收。
- 个人路径、账号、密钥、截图和原始日志在仓库外保存；仓库只写脱敏结论、测试名称和可复现的合成数据方法。

## 十步状态与逐步验收

### 1. 明确依赖与核心边界

状态：待开始。
核对调度、子代理、工具循环、命令、注册和 TUI 的直接调用；记录读取事实、持久写入、进程所有权、取消路径及不可变化的事务顺序。
明确插件描述、贡献所有权、激活代次、精确撤销和最小能力接口，先对照已记录的成熟参考，不预建空 SDK。
TUI：普通文件任务、一个子代理任务、一个持续任务并行建立基线；核对模型、目录、原生历史、输出及控制响应。
通过条件：依赖与验收基线有实际证据，入口能回答谁读/写/取消，未将既有失败误记为通过。

### 2. 拆后台调度

状态：待开始。
按纯准入/退避、进程内退避状态、唤醒/Goal 路由、租约/恢复依次小片迁移；不改变读取时机、锁、持久格式和写账顺序。
TUI：持续多文件任务与普通问答并行；Goal 暂停时当前回合可继续，中断回合与停止任务资源分别验证；恢复后不重复启动旧进程。
补充定时/唤醒、供应错误恢复、两任务竞争与隔离；会话断连重连、Gateway 重启恢复按同一实例顺序进行。
通过条件：原状态及资源归属正确、无重复执行/漏唤醒，真实长任务完成，旧直接入口删除。

### 3. 公共命令声明与解析

状态：待开始。
实现 `/plugins` 管理与 `/plugins@ID [动作] [参数]` 的结构化公共解析，身份由宿主绑定；帮助与参数从同一声明生成。
TUI：两路分别测试有效命令和普通聊天；覆盖未知插件/动作/参数、缺值、引号、空格路径、短开关、`--`、中文和错误恢复。
核心 `/goal`、`/interrupt`、`/stop`、`/model` 仍可正常使用；错误插件命令不能落入聊天或 Shell。
通过条件：TUI/plain/Gateway 判据一致；未实现的业务入口不假装可用，原控制语义无变化。

### 4. 首个只读插件与装卸链

状态：待开始。
以 workspace-peek 实现显式本地安装、默认停用、配置校验、隔离执行、贡献原子发布、版本绑定及精确撤销；依赖不污染核心环境。
TUI：管理会话完成安装/启用/调用/停用/再启用/卸载，另一会话持续执行内置文件任务；核对未安装、停用、启用及卸载后的目录。
覆盖包/配置无效、启动失败、重复管理请求、权限拒绝、旧快照撤销和进程退出事实。
通过条件：完整功能实际运行，管理不被业务调用阻塞；卸载不影响其他任务、历史或用户产物。

### 5. TUI 发现与使用链

状态：待开始。
实现插件列表、逐级补全、静态帮助、配置和使用卡；普通中文与显式命令共用工具/权限链。
TUI：一路中文请求使用文件预览，一路输入显式参数，第三路切换启停；验证目录刷新、停用帮助、过期目录及重新连接。
同时检查编辑、粘贴、中文输入、滚动、复制和长输出翻页，补全选中只填输入不执行。
通过条件：两种业务入口结果一致、参数/帮助/目录同源，核心输入与日常命令保持正常。

### 6. 插件故障与长任务

状态：待开始。
三路及以上 TUI 同时运行插件长任务、内置长任务和管理操作；受控测试包制造异常、阻塞、断连及清理失败。
验证运行中停用/卸载、等待审批时取消、重连不能复活、重复卸载、错误后再启用，核对专属进程及订阅清理。
通过条件：管理与无关任务可用，装卸不重启 Gateway，已发生副作用和未知结果如实保留；失败修复并重测后才进入下一步。

### 7. 子代理生命周期与交接

状态：待开始。
分开状态裁决、结果投影、持久收口及父级通知，保持 run/attempt 身份和唯一终态来源。
TUI：覆盖单子代理、三个以上并行子代理、主子孙递归、父级等待时插话、孩子失败/取消、结果通知重复及恢复后继续。
另一路主任务持续运行；核对并发重叠、实际文件、原生工具账、父级交接和取消后的资源退出，不能仅看模型总结。
通过条件：正常等待不误标失败；无漏交接、冒用身份或重复执行；长任务完成且产物与报告一致。

### 8. 模型与工具循环

状态：待开始。
沿现有 tool_loop 分离模型请求/响应、工具轮执行、Compact 协调与结束决策，不新建模型执行器。
TUI：多轮长文件处理、工具报错后修正、多工具/多子代理混合任务、Compact 后读回旧事实、回合中断和断线恢复。
对照一路普通任务；涉及视觉的片段用同密钥引用的 MiniMax-M3，核对图片进入实际请求及工具结果，而非只看模型名。
通过条件：历史成对完整、压缩提交正确、权限及取消不旁路；结果、用量与执行事实各守原权威来源。

### 9. 剩余 TUI 整理

状态：待开始。
分开输入/快捷键、状态消费和渲染；插件仅提供受限展示描述和可撤销只读订阅，队列有界。
TUI：多任务流式输出期间反复切会话、滚动/复制、输入中文/多行文本、审批、中断、重连；同时打开/关闭插件面板。
验证插件事件乱序、订阅积压、渲染错误和停用不会冻结核心输入或残留回调。
通过条件：屏幕读公开事实，输入和控制持续可用，插件代码不在 TUI 进程中任意执行。

### 10. 十个简易插件与最终组合验收

状态：待开始。
按样本计划完成 workspace-peek、context-inspector、savepoint-lite；worktable-lite、activity-line、status-pet、genui-lite；design-lite、image-text、browser-lite 三批。
每个包都实际安装、配置、使用、停用、再启用及卸载；提供工具的包增加普通中文调用，展示包直接用 TUI 操作验证。
组合长任务覆盖文件分析、页面/图表生成、图像理解、浏览器表单、多子代理汇总；同时另开内置任务和管理 TUI，逐个及批次卸载。
视觉使用 MiniMax-M3 并复用现有密钥引用；外部资源使用测试网页、合成图片与专属浏览器上下文。
通过条件：10 个包各自有真实结果；混装不串用户或资源，全部卸载后的新会话核心基线通过，原产物和历史保留。

## 每步推进与完成规则

每片记录源码/部署版本、结构变化、相关自动验证、真实 TUI 身份、模型/端点、任务时长、工具/子代理事实、产物读回及失败项。
每步完成前复核依赖方向、公共接口、重复状态、废弃代码、文档、配置及隐私；修复本片发现的相关问题并对受影响场景重测。
本步要求的测试未通过或缺证据时不进入下一步；不能降低测试标准、改报告、扩大尺寸基线或代写产物来宣布通过。
与本步无关的既有问题单列，不伪称本次重构已修；若影响必测主链，先按通用层定位修复。
发布时严格 gate 通过后才更新远端；需要更新运行代码时构建同版包并有序部署，不把修改源码目录等同安装版升级。
Goal 暂停只停止目标驱动的自动续跑；中断回合停止当前模型/工具执行链；停止任务资源只关闭精确归属于任务的进程、终端或子代理。
完成全部十步且证据齐全后才能将 Goal 标记 complete；遇到缺失信息按真实阻塞规则处理，不因费时或上下文不足停止推进。
