## 当前验收约定

先完成审计补修及严格本地门，在用户指定的 2C4G Linux 主机验证基础功能和关键回归；不在那里做大规模资源压测。随后按正式升级链更新本机，记录客户端与 Gateway 的实际源码版本和安装路径，再复用已打开的十个 TUI。

模型分组为五个 OpenCode 的 `deepseek-v4.1-flash`、五个 `minimax-M3.1-FLASH`。复用已有模型配置，核验真实请求使用的 provider/model。选择下面一至两个用例作一轮测试即可，不要求每个用例各执行两次。

单轮运行约一小时或收集足够诊断证据。用户最新要求让现有任务自然收尾，不再发第二轮、也不主动中断；保留日志、运行账本与退出事实。产物完成度、游戏玩法完整度、画面质量不作为本轮验收指标。额度耗尽单独记录，不算框架容量缺陷；未知工具结果与资源未确认仍须调查。

## 长期资料的升级与恢复验收

本机大量长期资料按线上级资料对待。升级须保留原owner/home和配置，沿正式自动迁移及恢复入口完成旧数据加载，尽量不打断正常使用；不要求用户手动清理目录、重建个人资料或补账。下列均为待验证条件，不是已经做到或绝对无损的承诺，程序能启动也不能代替数据验收。

- 升级前后对同一owner做结构化盘点并实际加载核对：会话/完整任务历史与活跃任务、正式记忆及候选状态/版本、技能和插件的身份/版本/启用配置、模型provider/model与既有显式配置、监控及调度任务的身份/范围/启停状态。盘点记录数量、稳定ID、版本与摘要，不在报告中记录凭据正文。
- 对原有长期会话、记忆条目和组件做实际读取/加载核对，区分物理表示迁移与逻辑事实变化。partial/unknown、缺源和损坏须明确记录并沿正式恢复链处理，不能变成“空数据”或用新home掩盖迁移失败；监控/调度恢复不得重复触发旧任务。
- 迁移和恢复期间核对持续进展与对应入口预算，记录已完成和未完成范围；安装成功、启动成功或一条新会话成功，均不能证明旧资料已完整迁移和加载。

候选旧JSONL会迁移为HAMT manifest和记录家族，thread.task_ids改为最近128条及全部活跃项，并用分页索引保留完整历史，Compact散节点会迁移为SQLite节点仓。保留旧程序不足以回滚这些数据变化，此边界已告知用户。本轮全量备份按用户最新要求停止并清理，不再阻塞切换，未完成副本不作为恢复来源；继续核对原配置和组件，禁止清空或重建用户资料来制造通过。

## 首次迁移与稳态的分别验收

用户接受刚升级第一次进行一次性历史扫描/迁移时的短时卡顿，不要求所有首次迁移都在50毫秒内分片完成。受管handoff仍保持原每拍最多16个物理位置及50毫秒合同，此约定不放宽该入口预算。

首次迁移完成后，常规启动、发消息和轮询不得反复全历史扫描。需验证持久完成标记、完成后的重复操作、进程重启后的跳过行为，以及迁移中断后的正式恢复；不能只凭同一进程的缓存命中认定稳态通过。普通旧线程当前首次写入经initialize做一次全量初始化，已有manifest后跳过全量初始化；主控制方仍在复核中断与后继行为，尚未据此宣布升级或稳态通过，也不承诺程序所有时刻无卡顿。

升级首迁的扫描量、耗时、CPU/RSS峰值与临时磁盘开销单独记账；完成后的常规启动、重复发消息/轮询及重启恢复资源另记。长期历史十TUI的稳态评估不能用首迁峰值替代，也不能掩去完成后反复扫描的成本。

## 资源评估范围

本机已有历史按一名长期重度用户处理；以十个真实TUI并发为验收基础，不新增五千用户实压。远期目标为同时五千用户、每人20–100个主/子/后台代理、10–30个监控，以及数月至数年的Gateway、单会话上万次Compact。此次只用实际资源增量按用户要求相乘估算，外推不是已验证的集群容量。

LLM推理硬件不计入本服务预算。共享Gateway、已有后台负载与本次TUI增量分别记录；CPU采用区间累计时间差，内存注明RSS共享页重复计数。给出十TUI合计、每活跃TUI增量和停止后回落，并标记本机其它活动造成的归因限制。合理扩容须随实际活跃工作量增长，不能靠持续堆加硬件掩盖历史扫描、泄漏或无人消费的后台任务。

## 观察协议

每个被测会话仅提交一次原始需求。开发者只观察真实 TUI、Gateway、模型与工具账本，不替被测代理编辑文件、补产物、执行其任务或反复提示推进。发现框架缺陷时先保留复现证据，按原模块合同修复和回归，再明确记录是否重新开始对应实测。

记录总耗时、各进程及整体 CPU/RSS、内存压力、进程/线程/FD 数量、首响应与持续输出停顿、工具执行与等待、Compact 时间、自愈触发/成功/未收口事实以及停止后资源回落。停顿需区分模型供应等待、工具长执行、资源竞争和框架阻塞，不能只凭界面不刷新判定死锁。

升级前记录既有运行版本与进程归属，按正式排空和升级协议操作。测试结果必须绑定实际提交与真实模型身份；本地单测、Linux 基础回归、真实 TUI 观察和 GitHub CI 分别记账。

建议下一步：由主控制方在最终定向回归通过后沿正式启动链切换，先核对原长期资料的自动迁移/恢复与实际加载，再执行本轮十TUI实测。按用户要求冻结分支CI独立并行，不等待已取消的备份；安装、服务切换与真实会话控制不由多个执行者同时操作。
