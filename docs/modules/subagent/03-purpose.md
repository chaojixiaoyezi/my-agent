# Subagent：初衷和想法

## 初心

让用户少说，但系统不偷懒。用户只说目标时，系统也要自动补上质量标准、证据要求、写入边界和父级验收，而不是把“完成没完成”交给某个 worker 自己判断。

## 服务谁

- 给普通用户：不用学习复杂派工术语，也能得到更稳的多步骤交付。
- 给父会话：有结构化计划、证据和验收清单，能判断 worker 产物是否可信。
- 给开发者和初学者：可以从 workflow、任务结构、测试记录里学习多代理系统怎样控制风险。

## 为什么这样设计

subagent 系统最怕的是“看起来忙，实际不可验收”。所以设计上先强调父级控制：

- worker 可以生产、检查、修复材料，但不能自封最终完成。
- workflow 模板描述拆工方式，不固定某一批永久角色。
- 质量契约把“什么算好、什么不能交、必须检查什么”写成结构化信息。
- 父级验收清单在派工前生成，避免事后临时想起要检查什么。

## 不做什么

- 第一版不把所有任务都强制变成复杂 workflow。
- 第一版不让 worker 直接写最终 `DONE` / `VERIFIED`。
- 第一版不一次性沉淀所有成功样本，只先建立可追加的位置和格式。
