# Log Analysis：初衷和想法

## 初心

把日志分析做成“证据优先”的小闭环：先可靠接入和查询，再让检测器和模型围绕证据工作。结论必须能回到原始事件，而不是只留下模型生成的一段话。

## 服务谁

- 给安全响应场景：快速看见可疑事件、证据、case 和初步报告。
- 给开发者：用离线 fixture 验证日志链路，不依赖真实 SIEM 或真实 LLM。
- 给初学者：通过 parser、store、detector、report 的分层学习一个数据处理模块怎么长出来。

## 为什么这样设计

日志分析天然有两个风险：数据量大，结论敏感。所以第一版把问题拆小：

- parser 只负责把输入变成统一事件。
- store 只负责本地保存和受控查询。
- detector 先做可解释的软规则。
- case 和 report 只引用证据，不假装知道没有证据的事实。
- 安全工具必须按 capability 授权暴露。

## 不做什么

- 第一版不承诺生产级大数据吞吐。
- 第一版不自动执行真实响应动作。
- 第一版不默认把安全工具暴露给普通聊天任务。
- 第一版不引入 DuckDB / Parquet / Kafka / ML 等重依赖，除非后续明确裁决。
