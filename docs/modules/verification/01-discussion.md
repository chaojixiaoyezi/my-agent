# Verification：功能讨论

## 问题

普通代码任务不应恢复一套统一“验收器”，但模型也不能把局部测试、过期测试或任意成功命令说成全量通过。

## 采用的方向

- 参考 长期助手 的被动 evidence ledger：只记录已经真实执行的验证命令和退出码。
- 参考 会话运行时 的 tool-result 事实边界：完成判断仍由当前主模型结合真实工具结果自然给出。
- 不扫描用户文字，不自动执行测试，不阻止普通任务收口，不把 targeted 升级成 full。
- 文件工具真实写成功后，当前项目的旧验证状态立即变为 stale。

## 不采用的方向

- 不恢复目录扫描、完成 marker、提交验收工具或第二套 closeout 状态机。
- 不按测试输出里的“passed/failed”文字作机器判断。
- 不为飞书或其他 IM 增加专属验证逻辑。
