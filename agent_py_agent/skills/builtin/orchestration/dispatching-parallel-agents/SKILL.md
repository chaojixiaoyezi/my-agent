# 派子代理并行处理

手上同时压着几件互不相干的问题时，一件件排队处理最慢。更好的办法是给每个问题单独配一个子代理，让它们同时推进，你自己只负责划分、派出和收口验收。子代理看不到你这轮对话的任何历史，它掌握的信息只有你写给它的那份任务说明。这是限制，也是好处：它不会被无关的内容带偏，范围窄、要记住的东西少，出错的面也小；你自己的上下文也不必装下每个问题的细枝末节，可以留给协调和判断。

## 拆之前先回答三个问题

1. **修好其中一处，会不会顺带改变另一处？** 几处故障如果可能出自同一个根因，拆开查只会让几个子代理各自绕远路。这种情况先放在一起排查：交给一个子代理统一处理，或者你自己查。
2. **它们的改动会不会落到同一批文件或同一份资源上？** 会的话，同时干活只会互相覆盖、互相抢占。仍然可以分给不同的子代理，但要等前一个做完再派下一个。
3. **不了解系统全貌，能不能把单个问题讲清楚？** 如果必须先看懂整体状态才能下手，或者连哪里坏了都还没定位，那就还处在探索阶段，先把情况摸清再谈分工。

三个问题的答案都指向“可以拆”，才并行派工。比较典型的信号是：失败分散在好几个测试文件或子系统里，根因看起来各不相同，而且每一个都能单独复现。

## 从划分到派出

以故障所在的位置为界划出问题域，一个问题域配一个子代理，边界通常就是一个测试文件或一个模块。划完再检查一遍：改动其中一个域，不应该影响另一个域的测试结果。

然后为每个子代理准备一份任务说明，让它知道：做到什么程度算完成；边界在哪里，哪些能改、哪些不能碰；回来时要交什么；以及理解这个问题所需的全部现场信息。

最后在一次 `create_subagents` 调用里列出全部子代理。它们一经创建就由宿主同时启动，你不必再逐个去开。哪一层的子代理要继续往下拆，调用的也还是 `create_subagents`。

## 任务说明要能独立成立

写完之后，设想把它交给一个从没看过这段对话的人：他能不能立刻开工？出现下面几种情况，说明还没写到位：

- 只写了“把登录那个偶发失败修掉”，却没附报错原文、失败用例名和复现命令，子代理得从头去找问题在哪。
- 没划出禁区，子代理可能顺手重构一大片。要写明类似“只改配置加载模块及其测试”的边界。
- 范围宽到“把这次合并带来的问题都处理掉”，子代理不知道做到哪里该停。要落到具体的文件或模块。
- 没约定回来交什么，最后只得到一句“搞定了”，你无从核对。要明确要求返回根因、改动清单和验证结果。

一份比较完整的说明大致是这样：

```text
你负责配置加载这一块。其他子代理正在并行处理别的模块，请只改 config/loader.py 和它的测试文件。

现象：升级依赖后，tests/test_config_loader.py 里有两个用例失败：
- test_default_timeout_applied：期望默认超时是 30，实际读到 None
- test_env_override_wins：环境变量没有覆盖配置文件里的值
复现：pytest tests/test_config_loader.py -q

先查清是加载顺序变了还是默认值丢了，再做最小修复。不要靠跳过用例或放宽断言让它变绿；如果确认是测试预期本身过时了，写明理由再改测试。

完成后交回：一两句话的根因、改了哪些文件和函数、复现命令现在的输出。
```

## 示例：一次合并之后

一次大分支合并后，CI 报了八个失败：配置加载两个，命令行输出格式四个，会话存档序列化一个，日志轮转一个。逐个看过报错，做了两处调整：输出格式里有一个其实是序列化字段改名引起的，把它并进序列化那一组；日志轮转要改的恰好是配置加载那个文件，不能和它同时动，于是排在配置加载之后。最终先并行派出三个子代理，分别负责配置加载、输出格式和序列化；配置加载那份结果回来后，再派一个子代理处理日志轮转。四份改动合在一起跑完整 gate，全部通过，总耗时只相当于挨个排查时的两轮左右。

## 结果回来之后

几个子代理同时干活，快是快了，可它们可能在同一个地方一起犯错，也可能汇报写着完成、实际却没改到位。因此结果回来后要做三件事：

1. 先对比各份 diff，看有没有两个子代理改到了同一处；有冲突要先处理好，别急着往下走。
2. 逐份读汇报，挑其中的关键改动去看实际 diff，确认汇报里说的和实际改的一致，不要只凭汇报下结论。
3. 把各份改动合到一起后，用 `run_command` 跑一遍完整的测试 gate；单独看都对、合起来却出错的情况，只有这一步能发现。

收尾的顺序不能颠倒：先有全绿的 gate 和对得上的抽查结果，然后才用 `task_progress` 更新进度、标记任务完成，或者直接写最终回复。如果进行不下去，就在这一轮回复里把证据摆出来，并说清卡在哪个决定上、需要谁来拍板。每个子代理处于什么状态，宿主会自己报给父级，你不用手工转达。
