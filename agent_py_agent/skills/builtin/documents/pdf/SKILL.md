# PDF 处理

PDF 是"所见即所得"的格式:文本流抽得对不代表版式没崩。**唯一可信的验收标准是把页面渲染成图片用眼睛看**,而不是相信生成代码跑通了、或抽取函数返回了文字。

**核心原则:版式正确以渲染图为准,不以代码无报错为准。**

## 三类任务,工具各有分工

| 任务 | 主力工具 | 注意 |
|------|----------|------|
| 生成新 PDF | `reportlab` | 排版可控、可编程,首选 |
| 抽取正文/快速核查 | `pdfplumber`(或 `pypdf`) | 只信文本,**不要拿它判断版式保真度** |
| 视觉核对最终效果 | Poppler 的 `pdftoppm` 渲页成 PNG | 唯一能证明"长得对"的手段 |

## 标准链路

1. **优先视觉核对**:把 PDF 各页渲染成 PNG 再看。
   - 有 `pdftoppm` 直接用。
   - 没有就装 Poppler;装不上则如实说明缺哪个依赖、并交付 PDF 让用户本地自行渲染核对。
2. 生成新文档用 `reportlab`,排版逻辑写成可重跑的脚本。
3. 抽取文本/快速核查用 `pdfplumber` 或 `pypdf`;**这一步只用来验证文字内容,版式保真度必须靠渲染图判断**。
4. **每次有意义的改动之后,重新渲染、再核对**对齐、间距、可读性——不要攒到最后才看。

## 依赖(缺了就装)

依赖管理优先用 `uv`。

Python 包:
```bash
uv pip install reportlab pdfplumber pypdf
```
没有 `uv` 时:
```bash
python3 -m pip install reportlab pdfplumber pypdf
```
渲染用的系统工具(Poppler):
```bash
# macOS(Homebrew)
brew install poppler

# Ubuntu/Debian
sudo apt-get install -y poppler-utils
```

当前环境装不上时,**别假装能渲染**:明确告诉用户缺哪个依赖、本地怎么装,把能交付的部分如实交付。

## 渲染命令

```bash
pdftoppm -png 输入.pdf 输出前缀
```

## 中间产物与输出约定

- 中间文件放统一临时目录(如 `tmp/pdfs/`),收尾时清理。
- 最终产物放固定的输出目录(如 `output/pdf/`),文件名稳定、可读、能看出内容。
- 不同任务的产物不要互相覆盖。

## 质量底线

- 排版整洁统一:字体、间距、页边距、章节层级一致。
- 杜绝渲染事故:文字被裁切、元素重叠、表格断裂、出现黑块、字形乱码或无法辨认。
- 图表、表格、图片必须清晰、对齐、标注明确。
- 连字符只用 ASCII 的 `-`;避免 U+2011(不换行连字符)及其他 Unicode 破折号——它们在某些字体下会渲染成豆腐块或消失。
- 引用与参考文献必须是人能读懂的文本,绝不残留工具占位符、token 串或半成品字符串。
- 中文 PDF 注意注册中文字体(macOS 自带 `/System/Library/Fonts/STHeiti Light.ttc`、`PingFang.ttc` 等),否则中文会渲染成空白/方块——这一类问题只有看渲染图才发现得了。

## 红旗清单——出现就停,回去渲染核对

- 只跑了生成脚本、没看过任何一页渲染图,就准备交付。
- 拿 `pdfplumber` 抽出的文字"看起来没问题"当作"版式没问题"。
- 改了排版(换字体/调间距/加图表)却没重新渲染。
- 出现"应该对了""大概没问题"这类没看图就下的结论。
- 还没看到零缺陷的渲染图,就准备声称完成 / 提交交付 / 标记任务完成。

## 交付前最终检查

- **看到最新一轮 PNG 核对结果为零视觉/排版缺陷之前,不交付。**
- 确认页眉页脚、页码、章节衔接都整洁到位。
- 图表、表格、图片清晰对齐、标注完整;中文/特殊字符正常显示无方块。
- 中间文件已整理或在最终确认后清除。

## 与任务系统的衔接

- PDF 生成/抽取/渲染的命令都通过 `run_command` 执行并查看真实输出,不靠推断。
- 多篇/大批量处理时,可派子代理分担(`create_subagents` / `dispatch_subagents` / `schedule_child_subagents`),但**子代理回报"做好了"不等于做好了**:收尾时自己抽查它产出的 PDF 渲染图,核实无缺陷再算数。
- 处理失败的篇目用 `task_progress` / `raise_event` 如实上报原因(缺依赖、字体未注册、源文件损坏等),绝不在清单里声称不存在或没核对过的产物。
- 准备声称完成、或在交付验收(`submit_for_acceptance`)/标记任务完成之前:必须有当下这一轮刚渲染出来的、零缺陷的页面图作为证据。

## 一句话总结

PDF 的"完成"由眼睛判定,不由代码退出码判定——**没看过干净的渲染图,就还没做完。**
