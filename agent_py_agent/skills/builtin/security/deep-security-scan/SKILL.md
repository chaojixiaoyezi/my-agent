# 深度安全扫描方法

普通安全扫描跑一遍发现阶段就交结论;深度安全扫描的价值在于:**发现阶段是整条链路里方差最大的一环,跑一次会漏。** 所以它把"发现"重复跑多轮、彼此独立、再语义合并,只让验证和出报告这种确定性强的环节跑一次。

适用对象:**整个检出的仓库**,或仓库内某个**用户指定的路径/包/目录/子模块**。不适用于改动 diff、单次提交、分支差异、工作区改动——那是另一种扫描,别用本方法硬套,也别把指定子路径偷偷扩大成整个仓库根。

## 三条铁律(不可协商)

这三条是方法的骨架,任何"协调者临场发挥"都不许动它们:

1. **每一轮跑固定数量的独立发现子代理**(本方法取 `6` 个/轮)。少一个都不算这一轮完成,不许为了赶进度把数量砍下来。
2. **每个子代理用同一份发现简报**,只允许机械替换(目标元信息、轮次号、子代理号、各自的产物落盘路径)。不许给某些子代理加"主题暗示""高危家族提示""上一轮没覆盖到的方向"这类协调者私货——那会让多个子代理趋同,失去独立性。
3. **不预设共享威胁模型**。每个发现子代理必须自己对同一目标独立生成自己的威胁模型,再据此发现。统一威胁模型只在发现循环跑到终态之后,由各子代理的威胁模型合成一份,供后续验证用。

目标不是"浅层并行",而是**同一简报、多次随机独立跑出来的发现多样性**。

## 整体编排

协调者(主代理)只负责编排,不亲自下场做面向目标代码的发现:

1. 把扫描目标解析定死一次(整仓 or 指定子路径),全程不再扩大或重解释。
2. 跑**多轮**独立发现子代理,每轮 `6` 个;每个子代理先自建威胁模型,再做漏洞候选发现。
3. 每轮结束后,把本轮产物和此前所有轮产物做**语义合并**,得到一份"权威候选清单"。
4. 当某一轮**完整跑完后没有新增任何新候选簇**,发现循环停止(终态 = `saturated`)。
5. 发现到终态后,把各子代理威胁模型合成一份权威验证威胁模型,再**一次性**跑验证、攻击路径分析、出最终报告。

## 派发发现子代理

用 my-agent 的子代理原语派发并行发现:`create_subagents` 创建一批、`dispatch_subagents` 派发执行、需要分批排队时用 `schedule_child_subagents`。每个子代理用宿主默认的 agent 类型/模型/推理档位,**不要继承协调者的对话历史**(各自独立,互不可见)。

如果当前环境根本派不出并行子代理,**不要谎称跑了深度安全扫描**——如实说明"本环境不支持并行子代理",并退回到"单遍普通安全扫描"作为兜底。

### 子代理隔离要求

每个发现子代理必须彼此独立:

- 同一份已解析的扫描目标
- 自己独立生成、写到自己专属路径的威胁模型(不读、不复用、不覆盖、不臆测别人的)
- 同一套发现规则、同一份发现简报(只机械替换目标元信息/轮次号/子代理号/产物路径)
- 同一份父代理预先生成的"覆盖范围清单"作为只读输入(见下)
- **看不到**其他子代理的发现结果和合并产物
- **不跑**顶层验证、**不跑**顶层攻击路径分析、**不做**最终产物定稿
- **不改**任何仓库文件

### 发现子代理简报(每个子代理照发)

下面这段是每个子代理的标准简报。**不要在前后加任何协调者旁白、技能路径模板、主题强调、候选家族暗示、上一轮新颖性暗示、协调者自创的"专长分工"。** 只替换已解析的目标细节、轮次号、子代理号、产物落盘路径。

```text
你是一个发现子代理,不是顶层扫描协调者。把下面这份自包含的专属任务当作你的全部任务来做。
如果做不完,向协调者报告问题,不要越权接管或终止整个扫描。

只跑两步:威胁建模 → 漏洞候选发现。

先用给定的、已解析好的扫描目标,自己独立生成一份威胁模型,只写到你专属的威胁模型产物路径。
不要读取、复用、覆盖或臆测任何共享的协调者威胁模型。
然后以你自己这份威胁模型为唯一事实来源,做漏洞候选发现。
不要重解释目标,不要跑顶层验证,不要跑顶层攻击路径分析,不要写最终产物,不要改仓库文件。

你的任务是:为这个范围尽可能穷尽地枚举"技术上站得住、彼此不同"的安全漏洞候选。

发现时严格遵守:
- 扎根于代码本身和你自己的威胁模型,不空想
- 保留不同的根因,不要把它们压成"表面变体"
- 各自独立可达的实例分开记,不要合并
- 保留具体的"来源 → 最近的防护 → 汇聚点(sink)→ 影响 → 受影响位置"证据链
- 把父代理给的覆盖范围清单当只读输入,逐项审,不重新生成、不重排、不覆盖
- 每个候选的机器可读"受影响位置"用统一结构:affected_locations 是对象数组,
  每个对象必须含 label / path / lines 三个字段(lines 始终是字符串,哪怕只有一行,如 "154"),
  detail 字段可选;不要用 "src/file.py:154" 这种纯字符串位置,也不要换别的字段名。

把你的威胁模型 + 完整的发现候选产物集返回给协调者,细节要足够支撑后续的语义合并和验证。
```

> 用 my-agent 任务系统跟踪进度:子代理可用 `task_progress` 汇报阶段进展;子代理遇到无法独自解决的阻塞时用 `raise_event` 上抛给父代理研判,而不是自行终止整个扫描。

## 共享前置:覆盖范围清单

第一轮发现开始**之前**,协调者必须先把"要覆盖的范围"固定下来,作为所有子代理的共享只读输入:

- 用确定性的方式把目标范围内的待审来源/文件列成一份**穷尽**的覆盖范围清单(整仓 = 仓库根;指定子路径 = 那个精确路径),落盘到一个标准的发现目录下。
- 把这份清单声明为"对所有子代理权威且穷尽"。每个子代理都消费**同一份**清单,不许各自重新生成、重排或覆盖它。
- 协调者**不**在此阶段生成任何共享威胁模型(威胁模型是每个子代理自己的事)。
- 给每个子代理分配**专属的产物落盘路径**,使各自的发现报告、台账、候选不会互相覆盖。

## 深度发现循环

按**同步轮次**跑发现:

- 每轮 `6` 个独立发现子代理
- 最多 `10` 轮
- 当第一轮"完整跑完且没新增任何新候选簇"时停止

至少跑一轮。

每轮结束后:

1. 收齐本轮所有发现子代理的产物
2. 确认本轮每个完成的子代理在产物和摘要收齐后都已空闲(不再运行)
3. 把本轮产物与此前所有轮的产物合并
4. 更新权威候选清单
5. 把新清单和上一轮的权威清单做新颖性对比
6. 如果没有任何新的候选簇被加入,**停止**

不要跨轮复用已完成的子代理。后续轮只消费**已落盘的产物**,不消费上一轮子代理的活动状态。开下一轮前,确认上一轮每个子代理都已完成并空闲;**不要去打断一个已经完成的子代理。**

> 这条停止规则只衡量"发现是否饱和",**不**代表"已验证漏洞"或"最终可上报漏洞"也饱和了——验证、JSON 定稿、报告投影都在发现循环结束后才各跑一次。

如果**第一轮就没发现任何站得住的候选**:写出对应的"无发现"产物,直接进入最终的"无发现"装配路径。

### 每轮收尾检查表(按顺序执行,不许跳步)

每一个完成的轮次都要按下面顺序走一遍:

1. 确认这一轮恰好有 6 个可用的、已完成的发现子代理
2. 确认本扫描类型需要的每份子代理产物都已在其专属路径下收齐
3. 确认这一轮 6 个完成的子代理都已空闲
4. 确认这一轮没有任何子代理还在运行
5. 把本轮已落盘产物与此前已落盘产物合并成标准的发现报告形态
6. 写出:合并记录、本轮候选清单、合并后的权威发现报告
7. 对照上一轮权威候选清单计算新颖性
8. **恰好二选一**:
   - **停**:仅当本轮没有新增任何新候选簇
   - **再开一轮 6 个**:仅当上面每一步都已完成

## 语义合并(每轮之后)

合并要在"底层可执行候选"的层面做,**不是**在"标题像不像"的层面做。

只有当一个细心的安全审查者会认为"这俩就是同一个底层问题",或者"一个是另一个更窄/更具体的复述、留着会重复计数"时,才把两个候选当成同一簇。

**不要**仅因为下列原因就合并:

- 提到了同一个子系统
- 共享一个宽泛的漏洞家族 / CWE 大类
- 涉及同一个路由族、文件族、辅助函数族
- 用了相似的攻击话术
- 利用路径有重叠但实质不同、被破坏的防护不同、受影响实例不同

### 合并的硬门槛:补救包含(remediation-subsumption)

这是判断"能不能合并"的唯一硬标准:

- **只有当"修好合并后的候选"能同时修好"被合并的每一个上游候选"时,合并才成立。**
- 只要任何一个上游的"来源/防护/汇聚点/影响"四元组在合并修复后仍会独立可被利用、独立可上报、或实质上没被解决,这次合并就**无效**。
- 相关但不同的发现可以晚点交叉引用或主题分组,但在补救闭包不一致时必须保持为各自独立的权威候选。
- **例**:一个"认证绕过"和一个"不安全路径拼接/文件影响"漏洞,如果修认证不能消掉文件影响、修文件影响也不能消掉认证绕过,就**保持分开**。

### 真要合并时(用"保留式合并",不是"有损摘要")

- 保留最强的标题,或合成一个更好的
- 保留每个成员里有实质价值、非冗余的细节(更窄的利用框架、受影响子路径、有意义的前置条件、不同的来源/防护/汇聚点细微差别、与补救相关的子情形)
- 保留属于同一证明四元组的不同受影响位置
- 保留让结论可读的"来源/防护/汇聚点"区分
- 把不确定性如实写明,不要为了合并而虚抬置信度
- 把上游证据**综合**成一个连贯候选,而不是把各子代理原文**拼接**起来
- 只删掉真正重复、被更精确表述取代、或在补救包含测试后已无关的细节
- 标题变宽时,不要因此降维丢失对验证/报告有用的上游框架

候选有重叠但实质不同时,**保持分开**。

## 权威发现产物(每轮合并后保留)

每次合并后保留:

- 一份合并记录(哪些子代理候选被归到一组)
- 当前的权威候选清单
- 合并后的权威发现报告(标准发现报告形态)
- 与上一轮权威清单的新颖性对比
- 每个候选的内部溯源:首次出现在第几轮、贡献的子代理与源候选 id、后续哪几轮重复出现、后续证据是"加强/收窄/反驳/仅重复"了该候选

**关键不变式:**

- 权威候选清单里每一个候选,都必须在合并后的权威发现报告里**实质性出现**——报告可以改措辞、综合互补证据、规范化格式,但**不许丢弃、压制或悄悄合并掉**任何一个权威候选。
- 一旦合并层判定某个候选被语义包含,这次合并必须已经体现在合并产物里,**不许**在最终装配发现报告时重新决定。

> 合并后的权威发现报告是**无损**的权威候选全集,形态和"普通发现阶段交给验证的那份"一致。它**不是**选择性晋级清单、不是三级摘要、不是再压一层的二次合并。验证及后续阶段必须消费这份权威发现报告,不许消费各子代理原始产物,也不许消费一份手工裁剪过的版本。

## 进入"集中收尾"前的终态门

只有当发现循环已记录下明确终态,才进入集中收尾:

- **saturated(饱和)**:某一轮完整跑完后,没新增任何新候选簇
- **capped(触顶)**:达到最大轮数上限时,新颖性还在出现

下面这些**都不是**进入验证/攻击路径分析/定稿的正当理由:

- 第一轮就跑出了一份看起来很强的候选集
- 协调者觉得当前合并清单"够好了"
- 已经顺手开始做了一些验证
- 就算没有终态,最终报告"也挺有用"

进入集中收尾前,确认发现产物里已具备能证明终态的证据:最后一轮的合并记录、最后一轮的候选清单、那之后的权威候选清单、与之一一对应的合并后权威发现报告,以及一条"本循环因 saturated 还是 capped 而结束"的明确内部记录。**缺这些就回去继续跑发现、补齐证据,不要因为发现没做完就草草定稿或判失败。**

### 集中收尾(各跑一次)

终态记录齐备后:

1. 拿权威候选清单和合并后权威发现报告,对照底层发现证据做一次理智检查:删掉误扩大的过度断言、修复把不同问题压到一起的错误合并、确保受影响位置和证明四元组仍然具体、确认没有任何权威候选在产出标准发现报告时消失。
2. 把各子代理的威胁模型合成**一份权威验证威胁模型**,写到标准的每扫描威胁模型路径。保留仍与权威候选相关的不同攻击者模型、信任边界、特权面、风险框架;矛盾保守归一,而不是抹掉有用的区分。**这份威胁模型是给验证用的下游上下文,不是回头过滤发现候选集的筛子。**
3. 对合并后的发现输入,**一次性**跑验证。
4. 对验证存活下来的发现及需要的闭合行,**一次性**跑攻击路径分析。
5. **一次性**填好完整的权威清单/发现/覆盖结果,生成最终报告;用 my-agent 的 `run_command` 跑出报告产物,并在回复里给出报告路径。

> 不要因为某个候选在多个子代理里反复出现就跳过验证。**复现是搜索证据,不是可上报证明。**

## 最终输出规则

- 最终结论要让用户感觉就是一份普通的安全扫描结果。
- **不要**对用户暴露:发现轮数、子代理个数、候选复现次数、语义簇 id、原始新颖性指标——除非用户主动问。
- 保留正常风格的优先级、严重度、置信度、受影响位置、验证推理、可达性、攻击路径、补救建议。
- 中间产物保留以备审计,但**不要**倒进给用户看的结果里。
- 如果集中流水线后没有任何发现存活,就出一份正常的"无发现"报告。

## 验收纪律(声称完成 / 标记任务完成前)

这条是 my-agent 的通用底线,套在本方法上:

- **未跑到终态、未一次性走完验证+攻击路径+报告生成之前,不许声称扫描已完成、也不许给出最终回复。** 复现多、候选多,都不等于扫完了。
- 发现没做完、产物有缺、轮次记账不全——这些是**可恢复**状态:记录已有进展,留着任务继续跑或交接,**不要**因为一轮没收尾、上下文用满、或还有活没干就把任务判失败。
- 报告产物必须**真的生成并落盘**,在回复里给出真实路径;不要在交付清单里声称一个不存在的报告文件。

## 红旗清单(踩到就停下纠正)

- 用了"少于 6 个可用子代理"的轮去做合并或新颖性判断 —— 这一轮不算完成
- 把"失败的派发 / 子代理崩溃 / 产物缺失"当成"候选空间已穷尽"的证据 —— 这是误判,该重试或补位,不是饱和
- 协调者在某一轮还没全部完成空闲时,就去读子代理产物的实质候选内容、从半截结果里推断"正在冒头的漏洞家族" —— 越权,只许查产物的存在性/完整性/可解析性/schema 合规
- 协调者自己下场做面向目标代码的发现、汇聚点狩猎、候选假设、基于目标代码的验证准备 —— 这是编排漂移,产物不算合法发现证据,不许影响新颖性/去重/验证输入
- 根据上一轮的发现、疑似盲点、早期新颖性观察,去**改后续子代理的简报** —— 禁止,所有轮同一份简报
- 把"指定子路径目标"在解析后偷偷扩大或重解释 —— 禁止
- 把不同的、各自独立可达的脆弱实例合并掉(普通规则本该保留它们) —— 禁止
- 让反复出现的"猜测性措辞"在没有集中验证的情况下变成一个可上报问题 —— 禁止
- 把各阶段(威胁建模/发现/验证/攻击路径/定稿)压到一起跑 —— 禁止,阶段边界要清

## 异常处理

- **依赖缺失**(派不出并行子代理等):尽早停下并解释,深度安全扫描依赖并行子代理工作流,不要静默降级成别的流程。
- **某个子代理失败**:有部分产物就保留,内部记一笔,只重试或替换**那一个**子代理,直到这一轮凑齐 6 个可用的完成项。不要为了往前走把轮次缩到 6 个以下,也不要在子代理只完成一部分时就去合并/做新颖性比较。
- **不完整的一轮**绝不能算作"无新颖性的一轮"。
- **产物缺失或不一致**(缺合并记录、缺候选清单、缺终态记账、清单与发现报告对不上、去重集与逐候选台账对不上)都是**可修复的记账/一致性缺陷**,不是终态扫描失败:在合并/验证/定稿前修好;本轮修不完就保留产物、留任务继续跑或交接。
- 子代理 `affected_locations` 输出格式错乱:这是必须在语义合并前修好的产物缺陷。只有 `line→lines`、`file→path` 这类无损机械等价才可直接归一;纯字符串位置、或无法无歧义映射的另类位置清单,算"不完整的子代理输出",不是合并输入。
- **达到 10 轮上限但仍有新候选簇在冒出**:带着当前最好的权威清单继续走集中验证流水线(终态记为 capped),**不要**谎称"新颖性已坍缩"。

## 护栏(始终生效)

- 扫描过程中**不改**仓库文件。
- **不**扩大或重解释已解析的指定子路径目标。
- **不**把各扫描阶段压到一起。
- **不**让发现子代理看见彼此的结果。
- **不**让反复出现的猜测性措辞在没有集中验证时变成可上报问题。
- **不**把普通规则本该保留的、各自独立可达的脆弱实例合并掉。
