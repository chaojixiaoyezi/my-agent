# 定义目标

一个目标写得好不好，要看做完那一刻能不能拿出东西证明它达成了。这个 skill 用来把用户笼统的意图改写成这样的目标：说清要达成的结果、用什么来验证、边界划在哪里。

它的产出到“目标说清楚”为止：计划的拆解、中间计划文件、台账、决策日志、续跑文件都不在这里产生，执行也不从这里开始。

## 先判断要不要走这一步

适用的信号有两种：用户点名要把目标、成功标准或验收条件讲清楚；或者你准备开工，却说不出“到什么程度就算完”。用户只是交代一个普通功能时，直接去做；正在进行、目标已经明确的事，也不必回头再定义。

## 一个合格的目标有三层

**结果。** 做完以后，哪一件可以核对的事会变成真的？它体现在用户看得见的行为、某个产物，还是某个模块、系统或运行环境上？

**证据。** 怎么知道它真的成了？最好是能直接给出“通过/不通过”的东西：一条验收条件、一道 gate、一条测试命令、一套评测或一项检查。连续指标要写阈值，例如耗时、内存、错误率、准确率或成本；靠人判断的写清评审标准；需要多次观察的写明数量，比如连续重跑成功几次、至少核对多少个用例、迁移完多少条记录。只选能说明“真的成了”的数字，不为显得严谨而堆砌指标。

**边界。** 写明范围内包含什么；容易误解的地方，把排除项也写出来；目标环境、允许的命令、能动的模块和文件、影响面上限、输出格式、交付时间，凡是会约束工作的都写上。再约定一个停下来的信号：碰到哪些情况就回头找用户商量，不一个人死磕。

## 把含糊的目标改硬

- 只描述动作、没有结果的说法，如“看看这个问题”“接着弄”“改进一下性能”“处理下 X”，磨成能验证的结果之前不要接下。
- 缺的信息会影响“要达成什么”或“怎么验收”时，用一句话问清楚。
- 信息够用、自己改写也不会跑偏时，直接改写成可度量的版本。

提问有成本：只在自己改写很可能带偏目标时才问，一次只问一件事，通常是缺了判定方式或范围边界。比如：

- “这次说的‘快’，指接口响应，还是页面加载完成？”
- “到什么程度算收工：测试全绿就够，还是要你亲自看过产物？”
- “在本机验收就行，还是要在预发环境复现？”

用户自己也说不出用什么衡量时，你来提议一个现在就能执行、结论只有“是/否”、也不容易自欺的检查方式，请用户点头。

## 不同类型任务的写法提示

- 调研：约定什么证据才算站得住、只查哪些来源或系统、结论要支撑哪个决定。
- 运维：写明什么情况下回滚或上报、失败阈值、要盯多久，以及正常状态是什么样。
- 性能：说清怎么测、测几次、看哪个指标、达到多少算数。
- 修 bug：先能复现，再谈修复；最好有一项修复前失败、修复后通过的检查。
- 测试类：写出要跑的命令，以及怎样的结果才算过。
- 质量改进：给一个旁人也能核对的完成标志，比如用户认可了产物、若干样例逐一复核过，或 lint、类型检查和测试都已通过。

## 不要把日常工作变成模式切换

闲聊、改代码、用户接连交代的几件小事，都照常在当前 conversation 里接着做。`get_goal` / `create_goal` / `update_goal` 这组特殊 overlay 专门服务于持续运行的 `/goal`，除非用户或系统明确这样要求，否则别去调用。

`task_progress` 只是可选的进度便签，复杂工作需要跨越 compact 记住走到哪一步时才读写。之前遗留的清单只用来查历史、帮助恢复：用户不需要先对它做任何处理（选中、完成、停止、关闭都不需要），你也不能拿它当拒绝新指令的理由。这一轮做什么，以用户最新的消息为准；接着做旧活还是开始新活，看对话本身的意思和文件的现状，始终只维护这一份聊天上下文。

## 定稿

对照三层逐一检查：结果是不是一个可以核对的事实？证据里有没有明确的数值门槛或是非判断？该写的边界和停止条件写了没有？都满足后，用一句话写出目标，把验证方法写进这句话，边界会约束工作时也一并写进去。为这个目标单独建任务，前提是用户明确要求按目标驱动的方式运行；多步骤的日常工作不需要。

合格的写法：

> 把搜索接口在一万条数据下的平均响应时间从约 900ms 降到 300ms 以内；只改查询层和索引，不改接口字段；用 `run_command` 连续跑 5 次现有压测脚本，5 次都达标才算完成。

> 修复导入带 BOM 的 CSV 时首列列名出错的问题：先补一个用带 BOM 样例复现失败的测试，修复后它转为通过，原有导入测试也全部通过；导出逻辑不动。

不合格的写法：“把搜索弄快点。”“再研究研究导入的问题。”

## 定下之后

- 目标里承诺的验证不是摆设。要说“完成”之前，无论是宣布完成、写最终回复，还是把任务标为完成，都先把那个判定真正执行一遍（用 `run_command`，或者跑测试 gate），拿到结果再说话，不拿“看起来没问题”充数。
- 需要子代理帮忙时，用 `create_subagents` 创建，任务说明里原样放上定稿的目标和验证方法。子代理创建即由宿主启动，它在做什么、卡在哪里、最后结果如何，也由宿主自动告诉它的直接父级；你要防的是目标在一层层转交中被改写或缩水。
