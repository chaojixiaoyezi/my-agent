# 来源与迁移范围

参考来源：[eternityspring/shuohao-skills](https://github.com/eternityspring/shuohao-skills)，固定 commit `7ebef4f2f53159ee1eaaec2793271a114a8be8cc`。本轮依据已下载公开副本，不声称是远端最新版。

已读：五个 `skills/novel-*/SKILL.md` 的元数据、`skills/novel-script/references/schema.md`、分镜脚本的接口和 README 的报告组装说明。
本包按这些方法重新编写少量资料指导与 Python 标准库检查器，使用新的聚合 JSON 格式和新编故事，没有复制上游 .mjs 脚本、安装器、报告样式、图片或示例小说。

| 上游范围 | 本包映射 | 当前覆盖与缺项 |
| --- | --- | --- |
| novel-outline | 分集目标与 hook/ending 提示 | 方法简化；原有完整改编五件套和全部质量规则未迁移 |
| novel-characters / novel-art | 角色、地点、道具与参考计划 | ID 对账；真实设定图、造型变体与全部美术规则未迁移 |
| novel-script | 场次和动作/对白节拍 | 说话人、场次关系；原语速估时及全部内容质量门未迁移 |
| novel-storyboard | 节拍到镜头、参考图计划 | 引用、正时长和本包新增的逐集目标对账；H3 导出和真实图片一致性未验 |
| report.mjs | 安全转义的静态 HTML 核对页 | 无原多面板交互、图像布局、导出按钮或原报告样式 |
| 安装与生成能力 | 无 | 不软链到全局 Skill；不调用原 Codex imagegen，不安装 Node 依赖 |

本包新编内容按主仓库 Apache-2.0（`LICENSE`）；上游相应 `LICENSE` 与 `NOTICE` 分别保留于 `licenses/shuohao-skills-LICENSE`、`licenses/shuohao-skills-NOTICE`。NOTICE 中的原样例声明被保留不代表本包复制了该样例。
当前为可构建/组件验证的文本切片，不是原项目完整迁移；真实 TUI、自然召回、媒体和视觉验收均另列。

## 本包 0.1.1 修订

本仓库独立补充按 `shots.scene_id → scenes.episode_id` 汇总镜头秒数并与显式 `episodes.target_seconds` 对账；这不是上游脚本的完整迁移。缺目标保留未验证警告，非法目标、溢出和时长差异分别报告，数值容差只处理浮点舍入。原有角色、道具、节拍、参考条目等外键检查保持。

完整制作交付的说明同时明确：通过原资源引用物化同版本检查器，沿现有工具实际运行后才报告结构验证；未执行可如实交付未验证资料，不给宿主增加领域硬门。跨包转换复用显式字段和转换清单逐项核对，来源 ID 与参考条目 ID 分开，无参考条目与 planned 参考计划分开。

开发验证只使用本包公开合成资料及数值/断链反例；不把真实用户任务的措辞、题材或固定时长写成判定分支。本检查器仍只读指定 project、向 stdout 输出，不新增执行器，不自动读取原文或子任务文件。来源事实、主子资料转换的语义一致性、创作节奏和真实媒体仍需另行审阅。

## 本包 0.1.2 修订

本仓库补齐 `templates/project.json` 的既有字段占位，包括场次关系、动作/对白节拍及镜头引用。填写的仍是原 `drama_workflow_project.v1`；原检查器、公开合成例子及其判定语义不变，未填写模板不能作为制作交付。

新增 `templates/handoff.json` 供记录制作阶段文件、真实字节 SHA、对象转换、省略、新增及未决差异。这是本仓库新编的普通制作资料模板，不是上游完整工作流迁移，也不是宿主任务/权限账。当前检查器不验证其摘要或跨文件映射，填写模板不构成实际执行证明。

入口补充当前宿主 `create_subagents.items[].allowed_skills` 的包级引用示例，精确版本仍由宿主从父级授权快照继承；未放宽默认授权或新增调度器。组件验证仅使用公开合成资料和隔离的既有派工接口，不代表模型实际采用、真实任务质量或媒体验收通过。

## 本包 0.1.3 修订

本仓库独立实现有界交接结构校验，不是上游脚本移植。`templates/handoff.json` 显式升为 `drama_workflow_handoff.v2`：使用阶段 ID、明确文件 ID 与 JSON Pointer 地址，旧 v1 字段别名不自动兼容。可选 `--handoff` 只读取重复 `--input-file FILE_ID=PATH` 明确授权的文件；JSON 正文路径不授予读取权，同次原字节用于摘要和解析。核对字段、唯一 ID、实际 SHA、阶段范围与对象地址，未决差异单列警告，不推断剧情或实际执行事实。

原 `check_project()`、项目 v1 关系与时长规则保持。CLI 报告明确升为 `drama_workflow_check.v2`，用 `checks.project/handoff` 区分已检与未请求交接，保留单一错误/警告及计量入口。脚本仍是可单独物化运行的一份标准库 Python 文件，无新执行器、辅助模型、网络请求、宿主验收门或状态账。

独立复核发现词法路径缓存可能误合并不同实际文件；本版本已分开声明比较与快照身份，仅相同绑定路径复用本次读取，补验缺目录、中间链接及实际字节摘要的反例。

新增验证只使用公开合成输入与字段、授权、摘要、地址、容量和 I/O 反例；没有把真实任务正文或固定故事事实写入规则。结构通过仍不证明来源忠实、全部应有映射已被列出、持物连续、媒体验收或用户接受；旧版本和旧真实失败记录不改。历史 0.1.2 的“尚不验证交接”说明描述的是当时版本，本节才是 0.1.3 新增范围。
