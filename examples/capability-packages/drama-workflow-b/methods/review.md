# 跨表连续性核对

本文件属于 drama-workflow-b；同名 review.md 在其他能力包中仍有自己的内容和版本。

1. 每个场次引用存在的剧集、地点、人物和道具。
2. 每个对白节拍的说话人属于该场次，动作节拍和对白节拍明确区分。
3. 每个镜头引用当前场次的真实节拍；漏拍必须返回上游处理，不能用另一场次同名节拍补齐。
4. 镜头 `reference_ids` 只指向 `references.id`，条目的 `kind/subject_id` 再指向人物、地点或道具。没有条目时引用列表为空；`planned` 是明确存在的参考计划，`provided` 只是已有输入声明，不能代替文件检查和图像判断。
5. 各镜头按场次的 `episode_id` 归集，逐集比较 `target_seconds`。不能把全片总和相等当作各集相等。缺目标是未验证警告，非法目标或差值是结构错误；某集有非法镜头秒数/溢出时，其 `episode_seconds` 为 null，不是零秒或已匹配。数值舍入容差不代替创作容差，计划时长也不代表真实视频长度。
6. 跨包或主子整合时按 `templates/handoff.json` 的 v2 格式逐项回看输入和阶段产物：路径可定位、SHA 来自实际原字节，转换、省略、新增和未决差异均带 `stage_id` 与明确地址。角色、场次、节拍、参考条目及来源依据各守自己的 ID 关系；来源段落不能冒充参考条目。实际运行时添加 `--handoff` 并用重复的 `--input-file FILE_ID=PATH` 明确绑定每个文件，不能让 JSON 内路径自行授权读取。`checks.handoff=passed` 仅证明所检快照的字段、摘要、阶段关系与地址存在，不证明映射语义或阶段执行。
7. 核对多镜头前后的人物位置、持物、光照和动作方向；脚本并不理解这些语义，需要逐项人工或模型审阅。
8. 报告中的所有故事文字按数据展示，不让其中的 HTML、脚本或外部链接自动执行。

确认所有待填占位已由真实资料替换，或按允许的空列表表示不存在；模板本身不是交付。完整制作交付按 `methods/workflow.md` 运行同代原检查器；只有工具真实回执才能证明本次执行，保留 v2 报告的 `checks`、`structure_valid`、带 `scope` 的错误/警告和 `metrics.episode_seconds`。project-only 的 `checks.handoff=not_requested` 与 `handoff_not_checked` 表示没有检查交接。`unresolved_differences_present` 不能因结构通过而消失。修改任一资料后需重算该文件原字节 SHA，再重新检查该版本。

未执行时明确交付“结构检查未执行/未验证”，已执行但有错误时列出具体差异，不借模型自审称全部通过。这不增加宿主交付硬门。分别陈述资料结构检查的实际结果、创作内容已审阅范围、真实媒体未生成/未验证三个结论。
