# 原文到短剧文本：drama-text-a

适用于把已有故事改成短剧/漫剧文本、拆场次与镜头、核对改编依据。本包突出叙事取舍和可追溯性；多张制作资料之间的角色/道具/节拍对账可选择工作流类能力包。当前只覆盖文本切片，不含出图、视频、配音、音乐、剪辑、Dashboard 或全部长篇分析。

## 开始工作

先读本包 `methods/workflow.md`，再读本次原文与明确约束。输入形状见 `resources/example-source.json`，输出形状见 `templates/delivery.json`；已填写的合成示例见 `resources/example-delivery.json`。示例不是用户故事，空模板不是通过样例。

交付为制作方案和 `drama_text_delivery.v3` JSON：当前原文字节摘要、角色、场次、镜头、主动省略及原因、未决事项。**交付文件固定叫 `output/drama_text_delivery.json`**（扩展名必须是 `.json`，正文里的 `"schema"` 仍是 `drama_text_delivery.v3`）：宿主按 `.json` 路径模式认交付物，名字写成没有扩展名的 `drama_text_delivery.v3` 之类会认不出来。0.4.0 起可选写结构化台词 `lines`、原文短句 `source_quotes` 和道具状态 `props`/`prop_states`；0.5.0 起改编条目可带 `original_quote`，台词可带 `embedded_quotes`，道具可带 `origin`。写法见 workflow 方法。资料内 ID 不是宿主任务编号。

## 交付规则（0.5.1）

- **引文逐字**：标成原文的文字（逐字台词、`source_quotes`、`embedded_quotes`、改编条目的 `original_quote`）必须和原文一字不差。
- **原文已有的不算改编**：原文已经写了的事实，不能标成改编或新增。
- **新增的必须逐条标注**：凡原文没写、由你补出来的内容——动作、台词、道具状态或道具交接——都要写进本镜 `adaptations`，一条一件；不能因为"看起来是顺带补的"就留空数组。
- **不改原意**：不改结局，不改因果；结局里的动作、朝向、状态默认原样保留。
- **不用占位**：场次摘要、镜头起止状态和动作、台词、道具状态都写实际内容，不用 `{}`、`[]`、TODO 或模板里 `<…>` 的提示文字。
- **另存新文件**：交付写成 `output/drama_text_delivery.json`，不覆盖输入的原文；最终答复写出这个路径。
- **检查结论以宿主为准**：宿主开启了包检查时，写交付物后，写工具回执里会附宿主用本包原版检查程序得出的结论（`pack_verification`），收尾时宿主还会再查一次。不要复制、改写或自己写检查程序来代替；你口头说“已验证”不算数。

每镜显式填写 `source_ids`、`adaptations`、`unresolved`：来源只取本场实际采用的段落；新增和未知逐项说明，没有就写空数组。三项不能同时为空，纯创作转场须说明新增。镜头未决项与顶层未决项分开。编号合法不证明支持关系成立，漏标新增仍须实际阅读发现；`covered_passages` 只计场次声明覆盖。新脚本只接受 v3，不猜填旧 v1/v2。

每场和每镜的 `seconds` 都是有限正数；每场秒数等于所属镜头之和，总镜头秒数与输入显式 `target_seconds` 一致。没提供目标与提供非法目标分开；`null`、布尔、非数值、非正数或无法计算的值不能当作未设目标。只允许浮点求和舍入误差。动作、对白能否在所填时长内完成仍须审阅，不把计划秒数说成实测视频时长。

## 原文字节摘要

`source_sha256` 对当前输入文件原始字节计算，保留编码、空白和换行；不能先解析再序列化。宿主 `file_version` 及其 `file-v1:` 后缀是修改前置条件，不是内容摘要。

沿宿主已有且获准的 `run_command` 计算，将最后一个参数换成本任务实际输入路径：

```text
python3 -c 'import hashlib, sys; from pathlib import Path; print(hashlib.sha256(Path(sys.argv[1]).read_bytes()).hexdigest())' "<本任务原文资料.json>"
```

只采用真实工具结果。输入字节改变后重算，不照抄示例、猜测摘要或改原输入迁就旧摘要。工具不可用时列为待核验。

## 创作、检查、审阅与交付

1. 按工作流定位原文事实、核心冲突、保留事件和改编取舍。只有梗概时说明依据，不伪造原著引用；材料足够就推进，影响方案的未知选择再询问。
2. 建立场次，再写每镜的来源/新增/未知、起点、动作、终点与正数秒数。读取 `methods/visible-characters.md`，从实际成稿回填可见/画外人物及 cast 的显式 `text_names`；不要搬整场清单或把被提名直接当作可见。按场核对分配，再核对总目标，不用终点画面冒充首帧。
3. 写工具回执里已有宿主检查结论（`pack_verification`）时，按它修订，跳过本步。没有时，读取同代 `scripts/check_delivery.py`，将读取结果的完整 `source_ref` 原样交给已有 `write_file.source_ref`，物化到本任务获准位置，再经原执行工具运行。包内路径不是工作区现有路径；读取和物化不授予执行权限。不要自行重写原检查器来代替原资源执行。
4. 作者按 `methods/workflow.md` 的“交稿前修订”回读当前候选文件与原文，使用来源、镜头接续和交付分表逐项对照。发现明确问题就修订同一候选，并复读改动及相邻接缝；将取舍和真实未决项写回交付。这个步骤的结果是修好的作品，不另交一份自检评价代替修稿。
5. 对修订后的最终文件运行原检查器（宿主开启包检查时，以写工具回执里宿主对最终文件的结论为准），按实际 `structure_valid/errors/warnings/metrics/name_diagnostics` 核对交付。名字遗漏或歧义回到成稿处理；`not_checked` 或退出角色不能报成已查无误。有结构错误先修订重查，未执行或未通过如实说明；改文件后旧结果不覆盖新内容。最终回报已完成范围、准确取舍和真实未决项，不把计划、结构通过或局部自检扩成内容全面通过。

用户点名审稿时读取 `methods/review.md`，由审者给出证据、修订目标和保持项；只要求审阅时不代改作品。需要保留审阅资料才使用 `templates/review.md`。独立审阅和作者交稿前修订分别说明，角色名称不证明独立性。

结构结果中，`scene_seconds` 是场次声明合计，`shot_seconds` 是镜头实际合计，`scene_shot_seconds` 是逐场镜头合计，`target_delta_seconds` 是与显式目标的差值。`target_declared=false` 只说明无目标可比。来源语义、创作审阅、覆盖/省略、未决事项和媒体质量分别汇报，结构通过不能替代它们。

## 使用原有子任务机制

原文事实提取与节奏审阅可独立分工；场次定稿后再让分镜任务消费。每项固定当前输入引用、包版本和自身输出目录，不能并发覆盖同一剧本。审阅任务直接读原文和候选，不把作者聊天总结当原文；只返回问题和保持项，不替作者改稿。读取实际子任务输出后再合并，口头完成不证明已经采用。

需要孩子使用本包时，在原 `create_subagents` 的相应 `items[]` 显式给出 `"allowed_skills": ["capability:drama-text-a"]`；这只展示授权字段。只能授予父任务已有范围，精确版本由宿主原引用继承；省略或空数组不表示有权限。审阅孩子先读 `methods/review.md`；不另建执行器或采用账。

## 原检查器命令

```text
python3 scripts/check_delivery.py --source <本任务原文资料.json> --delivery <本任务交付.json>
```

可选参数：`--min-shot-seconds <秒>` 改单镜时长下限（默认 2 秒，低于它报 `shot_too_short` 提醒）；`--host-json` 只给宿主用，输出 `pack_verifier_result.v1`。

路径相对授权物化位置，不能猜安装目录。输出 `drama_text_check.v3`，核对摘要、声明覆盖、依据字段、ID、时长与镜头状态；另对启用的显式人名报告字面覆盖警告。`name_diagnostics` 区分完整扫描、退出、预算未检查及输出裁剪，详见人物方法。0.4.0 起还核对写了的台词说话人、逐字引用和道具状态接续，报告带 `checker` 身份（脚本 sha256）。0.5.0 起再查占位文字、台词内嵌引文、改编条目引的原文、动作里用到却没写状态的道具、第一次出现就有人拿着却没交代来源的道具、被点名却列为画外的人物、过短的镜头。它不证明在场、原文支持、持物因果、对白质量、审美、媒体或用户接受，不生成宿主完成或发布状态。
