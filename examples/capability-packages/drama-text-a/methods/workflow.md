# 以原文依据为中心的创作链

本方法由 drama-skills 的创作分段和分镜依据思想改写，范围和许可见 `PROVENANCE.md`。它是领域指导，不改变宿主权限或任务状态。

| 阶段 | 消费输入 | 形成输出 | 交接检查 |
| --- | --- | --- | --- |
| 原文定位 | 带编号的段落与当前文件字节 | 原始字节的 source_sha256、事件、人物关系、不可擅改事实 | 摘要由实际工具计算，不用 file_version；引用确实存在于本次材料 |
| 改编取舍 | 用户目标和事件 | premise、取舍说明、主动省略 | 省略写原因，未知内容不编成原文事实 |
| 场次设计 | 采用的事件、角色 | scenes：id/source_ids/character_ids/seconds/summary | seconds 为有限正数；每个场次有原文依据，新增桥段明确标注为创作 |
| 镜头设计 | 当前场次与视觉事实 | shots：id/scene_id/source_ids/adaptations/unresolved/seconds/start_state/action/end_state | 来源限定本场，新增与未知逐项说明；每镜须正数 seconds，起点与终点可见，不用终点描述冒充首帧 |
| 人物依据回填 | 实际镜头成稿及 cast | 每镜 visible_character_ids/offscreen_character_ids，cast 的 text_names 或显式退出理由 | 按 `methods/visible-characters.md` 从成稿核对，整镜任一时刻可见者不列画外；字面告警不推断人物存在 |
| 作者修订 | 已写出的候选文件、原文及实际结构错误 | 修订同一份场次/镜头/取舍说明，保住已有有效内容 | 回到成稿逐项反查来源和状态，明确问题直接修，真实创作分叉才交用户选择 |
| 最终检查与交付 | 修订后的实际文件 | 当前原检查结果、已完成范围、取舍和真实未决项 | 只汇报当前字节支持的结论；结构检查与语义判断分开 |

先让每个场次承担一个明确变化，再决定镜头数量。场次和镜头的 `seconds` 都不能缺省、用布尔值、零或负数代替；模板中的 `null` 必须填写。脚本按 `scene_id` 累加镜头秒数，比较每场声明，再比较总镜头秒数与原输入显式 `target_seconds`；浮点求和只用 `1e-12` 相对误差，不设置会掩盖极小数差异的绝对秒数下限。没有目标字段就如实报告未声明，非法目标不跳过。人工另行核对各场动作、对白和转场能否在所填时长内完成，不能把数值相等当作节奏已经合适。估计的秒数只服务节奏计划，不能报告成实测视频时长。

原文摘要按入口“原文摘要”步骤对文件原始字节计算。相同 JSON 内容采用不同空白或换行仍会产生不同摘要；`file_version` 只帮助原文件工具避免过期修改，不能填入 `source_sha256`。
资料里提到的角色、场景和道具一致性只是设计要求。没有真实参考图输入与生成回执时，不声称画面一致性已实现。

v3 的每镜 `source_ids`、`adaptations`、`unresolved` 必须显式存在。列表为空表示当前没有该类声明，三项合计至少一项；只取当前场次已声明的段落，不借其它场次的有效编号掩盖错配。改编新增与未知写具体事项，脚本只检查形状并提示审阅，不解析“没有问题”等句子判真。镜头未决项与顶层交付未决项分开；原 `covered_passages` 仍是场次覆盖，不称镜头语义覆盖。

v3 同时要求每镜明确可见/画外列表、每个角色明确 `text_names`。必读 `methods/visible-characters.md` 的回填次序、代称/退出、歧义与预算边界，再处理原检查器给出的具体位置。名字诊断完整扫描只覆盖声明的写法；退出或 `not_checked` 不等于没有漏项。无论诊断结果如何，持物因果与未点名人物仍按下面的来源和接续步骤阅读。

## 台词、逐字引用和道具状态（0.4.0，可选字段）

这些字段都可以不写；写了，原检查器就逐项核对。用户要求对白或可排演文本时，应当写出来，不能只在 `action` 里转述"某人说明了……"。

- **台词 `lines[]`**：
  - 每条是 `{"speaker_id": 角色ID或null, "text": "台词"}`。`null` 表示旁白或字幕。
  - 说话人必须在本镜的可见或画外列表里。
  - 检查器只数条数、核对说话人，不评价台词好坏。
  - 一个镜头都没写 `lines` 时，报告 `dialogue_not_structured`；写了但全稿 0 条时，报告 `no_dialogue_lines`。
- **逐字标记**：
  - 只有台词和原文**一字不差**时，才在那条台词上加 `"verbatim_source_id": "本镜引用的段落ID"`。改了一个字就不要标，改写的部分写进 `adaptations`。
  - 检查器按原文连续子串比较，不做标点、空白或全半角的归一化。不符时报 `quote_not_verbatim`，并列出这句其实出现在哪些段落。
- **原文短句依据 `source_quotes[]`**：
  - 每条是 `{"source_id": 段落ID, "text": "原文里的一小段"}`，用来给镜头标出原文依据，同样必须逐字。
  - 散文里加了引号的文字不会被当作原文引用，也不会被检查。所以要声明"这是原文"，就写进这里。
- **道具状态**：
  - 顶层写 `props[]`，每条是 `{"id", "name"}`。
  - 每镜写 `prop_states: {"start": [...], "end": [...]}`，每条是 `{"prop_id", "holder_id": 角色ID或null, "state": "短标签"}`。
  - 同一状态始终用同一个标签，例如一直写"压扁"，不要一会儿写"扁了"。
  - `shots[]` 的数组顺序就是叙事顺序。上一镜 `end` 和下一镜 `start` 的同一道具，持有人或标签对不上时，报 `prop_state_discontinuity` 提醒；有意跳接就在下一镜写一句 `continuity_break`。
  - 持有人不在本镜声明里报错；持有人在画外只提醒。
- **原检查器身份**：报告的 `checker.script_sha256` 应等于本包 `scripts/check_delivery.py` 资源的摘要。自写或改过的脚本给出的结果，不能说成"原检查器通过"。

## 0.5.0 新增写法和检查

- **改编条目**：`adaptations[]` 每条可以写成 `{"text": "新增或改写了什么", "original_quote": "被改写的原文逐字片段"}`。纯新增的 `original_quote` 写空字符串；旧的纯文字条目仍然有效。写了 `original_quote`，它就必须是原文某一段里一字不差的片段，否则报 `adaptation_original_not_in_source`。原文已经写了的事实不是改编，不要写进这里。
- **台词里的原文片段**：一句台词只有一部分是原文时，在这条台词加 `"embedded_quotes": [{"source_id": "本镜段落ID", "text": "原文片段"}]`。片段必须出现在这句台词里（否则 `embedded_quote_not_in_line`），并且和所引段落一字不差（否则 `embedded_quote_not_verbatim`）。整句都是原文时仍用 `verbatim_source_id`。
- **道具来源**：`props[]` 每条可以写 `origin`，说明第一次出现时从哪来、谁交给谁。道具第一次出现在 `prop_states` 时已经有人拿着、却没写 `origin`，报 `prop_origin_unstated` 提醒。第一次出现时无人持有（比如放在门口），可以不写。
- **动作里用到的道具要写状态**：已登记道具的名字出现在某镜 `action` 里，这一镜的 `prop_states` 就要写这个道具，否则报 `prop_states_missing` 提醒。
- **被点名的人物**：起止状态或动作里点了某个人物的名字，这个人物通常就在画面里；列成画外会报 `named_character_offscreen` 提醒。背影、手部入画都算可见。
- **镜头时长**：单镜秒数低于下限（默认 2 秒）报 `shot_too_short` 提醒。一镜里动作多，就给足时间或拆镜。
- **不用占位**：摘要、起止状态、动作、台词、道具状态写 `{}`、`[]`、TODO、纯标点，或者照抄模板里 `<…>` 的提示，都报 `placeholder_text` 错误。
- **不改原意**：改编不改结局和因果。这一条检查器查不出来，要靠作者自己回读原文核对。

## 0.5.1 新增写法（交付命名、新增标注、结局保留、人名声明）

### 交付文件命名

交付物写成本任务工作区下的 `output/drama_text_delivery.json`：**扩展名必须是 `.json`**。`"schema"` 字段里的 `drama_text_delivery.v3` 是正文里的格式版本号，**不是**文件名——把交付文件命名成 `drama_text_delivery.v3`（没有扩展名）会被宿主当成没写交付物。
宿主按声明的 `**/*.json` 路径模式认交付物：名字不符合的模式的文件不会被当成这次交付，也不会进入检查，返工提示会说没找到符合模式的交付物。写完之后自己回看一遍路径，最终答复里照实写出这个路径。

### 新增创作逐条标注（adaptations）

凡原文没有、由你补出来的内容——新动作、新台词/字幕、新的道具来源或道具交接、新的时间地点交代——都要在**对应镜头**的 `adaptations[]` 里逐条列出来，一条一件事，并写清它是新增还是改写（改写就填 `original_quote`，纯新增填空字符串）。

正例（该镜补了原文没有的"蹲下拾灯"动作和一句台词，两条都写了）：

```json
"adaptations": [
  {"text": "补写拾灯、翻看灯面的动作，让发现过程可见。", "original_quote": ""},
  {"text": "新增台词：'这灯……谁放在这儿的？'原文无对白。", "original_quote": ""}
]
```

反例（同一镜补了上述动作和台词，却写成空数组——检查程序只看形状，不会替你发现漏标，评审会按"新增创作未标识"判不合格）：

```json
"adaptations": []
```

原文已经写了的事实不是新增，不要写进这里；确实没有新增时，才写空数组并确认这一镜真的没有补任何东西。整段省略要写进顶层 `omitted_passages` 并给原因，不能靠不写代替。

### 结局关键事实原样保留

原文结局里的**动作、朝向、状态**默认原样保留。改编只能改**表达方式**（把叙述写成台词、把一句动作展开成几个镜头），不能改事实本身。原文写"推开窗"，就只能拍成推窗；换成"关上窗""钉死窗"都算改了结局的关键动作，即使理由看起来更利于画面。

确实需要删掉或改动的，必须同时做两件事：

1. 写进顶层 `omitted_passages`（省略整段时）或对应镜头的 `adaptations`（改动细节时），并给出理由；
2. 不碰结局的关键事实——结局里的关键动作、朝向、状态和因果都不能被删改。只能省"怎么到达"的中间过程，不能省或改"最后是什么样"。

### cast 的 text_names 声明

`cast[]` 每条要写 `text_names`（正文里逐字用到的名字写法）：要么是**非空**的名字数组，要么是**空数组 + 非空 `text_match_skip_reason`**。两者只能选一种——同时给非空 `text_names` 和非空 `text_match_skip_reason` 会报 `conflicting_text_match_declaration`，交付无效。

不冲突的例子（同一份 cast 里两种合法写法并存）：

```json
"cast": [
  {"id": "C01", "name": "店员", "text_names": ["店员"], "text_match_skip_reason": ""},
  {"id": "C02", "name": "旁白", "text_names": [], "text_match_skip_reason": "正文只用'旁白'标注，不作为人物名参与字面匹配。"}
]
```

冲突的例子（同一条同时给了非空数组和退出理由，会报错）：

```json
{"id": "C03", "name": "姐姐", "text_names": ["姐姐"], "text_match_skip_reason": "姐姐全程不出场。"}
```

正确做法：姐姐若在正文里被逐字提到"姐姐"，就写 `text_names: ["姐姐"]`、`text_match_skip_reason` 留空，再把她列进对应镜头的 `offscreen_character_ids`；确实不想参与字面匹配，就把 `text_names` 留空并只写退出理由。

只复制自己实际阅读到的依据。对子任务传递当前原文/场次引用与本包身份，不把聊天总结当作原文，也不以模型口头完成替代宿主结果。

合并并行阶段结果时，按当前 `source_ids`、`scene_id` 和角色 ID 复查来源与去向。跨包或跨格式转换须在本次交付说明里逐项列出原字段/ID、目标字段/ID、保留或省略理由及新增内容；不能把同名编号当作同一个对象。转换清单帮助内容复核，不产生新的宿主任务身份、权限或完成记录。

## 交稿前修订

这是普通创作的作者步骤，沿原任务继续完成。参考固定上游写作和分镜 owner 的交稿前反查/原文档修订；具体来源见 `PROVENANCE.md`。使用现有三个分表作为阅读方法，结果写回作品，不另建事实库、覆盖表或审查回合。

1. **打开当前候选**：完成结构错误修正后，重新读取实际交付文件与需要对照的原文。以文件中的动作、场次和镜头为对象；计划、记忆中的写作意图和上一版检查不代替当前成稿。长文件沿宿主原分页继续读取本次范围。
2. **反查取舍**：使用 `methods/review-source.md`，从各段原文的事件、关系和状态检查实际落到哪里，再从镜头的陈述回查依据。段落被部分采用时，仍须准确说明其中省掉或改写了什么；把取舍写回现有 brief/场次/镜头说明。需要修正的是实际表达，不是让一段有效编号替整段内容作证。
3. **逐镜接续**：使用 `methods/review-continuity.md`，沿现有叙事顺序核对每镜起点—动作—终点，再核上一终点—已有过渡—下一起点，场次边界也包括在内。直接对照实际字段，不用一段总括的状态链代替中间连接。作品已有的有意省略保持；缺少依据时不替作品编造镜外解释。
4. **修订成稿**：明确的来源、取舍或接续问题直接修改对应场次/镜头/说明，并重新读取受影响镜头及前后接缝。保留无关有效段落，不因自检给故事添加额外机关；没有发现问题就保留成稿，不制造一次写入充当检查证明。只有现有依据不能决定、会显著改变作品方向的选择，才如实留作未决；不能用“建议以后修改”代替本任务已授权的明确修订。
5. **按最终事实交付**：使用 `methods/review-delivery.md` 对照实际合并、数量、时长及拟陈述；对最终字节运行原检查器。最终只说明做了什么、为什么取舍、仍缺什么。没完成的阅读或无法确认的内容保留范围，不把“结构通过”或局部自检写成全面无遗漏。

用户点名审稿时，沿 `methods/review.md` 交还带证据的问题、修订目标和保持项；只读审者不替作者改稿。用户同时要求修订时，作者在原授权内改同一作品并复查。需要保留反馈才使用 `templates/review.md`，不以额外报告是否存在判断创作完成，也不把审阅文字变成宿主状态。
