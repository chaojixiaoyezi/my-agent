# 带证据的文本审阅

本方法由固定上游 `short-drama-review` 的当前 Markdown 流程改写，来源见 `PROVENANCE.md`。本文件及其分表属于 drama-text-a；其他包同名方法没有继承关系。审阅只产生内容意见，不决定宿主完成、授权或发布状态。

本入口服务于用户点名的审稿。普通创作的交稿前检查与明确修订由作者沿 `methods/workflow.md` 完成，也可以直接读取三个分表；不会因为使用分表就另开审稿回合或将作者工作缩成一份评价。只要求审阅时交还问题；同时要求修改时由原任务中负责作品的作者修订。

## 先界定本次审什么

写明当前原文、交付文件、段落/场次/镜头范围，以及用户明确的约束。直接读取这些文件；材料缺失只使依赖它的判断待核验，其他部分继续。只读了部分内容就列出范围，不把抽样表述成完整审阅。

优先由未参与这版创作的审者执行。只能自检时如实说明，不把角色名称当作独立审阅证明。作者与审者保持写入职责分开；已有任务授权的修订由作者完成。

## 按顺序完成三个工作单元

1. **机械核对**：按入口物化同代 `scripts/check_delivery.py`，用当前输入和交付运行。来源摘要必须取当前输入原始字节，不能采用宿主文件版本。保留实际返回的错误、警告和计量。未运行、失败和通过分别陈述；结构错误先交作者处理，仍可记录不依赖该错误的内容问题。
2. **定向阅读**：按下表读取适用分表并对照真实材料。不是读完清单就算审过；每个问题须写出支持它的两个事实或缺失位置。
3. **交付核对**：作者合并或修订后，用 `methods/review-delivery.md` 复查变动位置、前后连接、跨文件交接和拟对外陈述。原检查后文件发生变化，要重新运行原检查器；旧结果不能证明新字节。

| 本次对象 | 本包私有方法 | 实际需要形成的反馈 |
| --- | --- | --- |
| 原文事实、人物关系、动作依据和改编新增 | `methods/review-source.md` | 原文事实与下游陈述成对对照，指出漏标新增和仍未知的内容 |
| 场内镜头、相邻镜头及跨场转场 | `methods/review-continuity.md` | 上一终点、过渡动作、下一起点的具体连接；保留刻意省略或蒙太奇 |
| 并行合并、跨格式资料与最终汇报 | `methods/review-delivery.md` | 计划/实际、来源/去向及拟陈述/真实证据的差异 |

完整短剧交付通常涉及三行；专门审一处问题时只消费所需分表，不预加载其他项目或媒体资料。

## 问题必须可交还作者处理

每项按 `templates/review.md` 的问题形状给出：当前位置、原文或上游事实、冲突的下游事实、影响、应恢复的结果、须保留的内容、负责修改的文档/作者及严重程度。引用文件名、现有段落/场次/镜头 ID、行号或必要短引文，不发明新来源编号。

分清四种依据：客观结构错误、带证据的语义冲突、可覆盖的创作默认和个人偏好。只有明确事实或用户约束遭到破坏，才提出必须修订；不能为了展示审阅规则增加新人物、新事件或强制镜头数量。对白、节奏与人物动机指出具体问题，不给没有依据的总分。

相同原因造成的问题可以归组，但保留每个受影响位置。修订要求描述要恢复的结果及保持项，不直接替作者写另一版故事。改动到的来源、动作、物件或转场须复查相邻处；不递归推翻所有无关交付。

## 输出和采用边界

需要保留审阅资料时，将问题写入当前任务的 Markdown；可使用 `templates/review.md`，不要求固定文件名。用户只要口头结论时直接按同样形状回复，无问题也写清检查范围、方法与未验证项，不为凑数编造发现。

审阅说明由模型或人阅读，宿主不解析其中的“通过/返工”等文字，不新增 JSON 裁决表、接受状态或另一份原文真源。模板不是检查结果。原文忠实、镜头连续与创作质量仍需实际阅读；媒体没看过就不声称媒体质量通过。
