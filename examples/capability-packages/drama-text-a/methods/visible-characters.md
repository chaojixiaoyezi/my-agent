# 从成稿回填人物依据

先完成当前镜头的起点、动作、终点，再回到实际文字填写人物声明。这个步骤改写自固定 drama-skills 的 storyboard 成稿反查和 SHT-22 人物具名覆盖；来源与许可见 `PROVENANCE.md`。它不识别人物是否真的在场，不代替来源、持物因果和相邻镜接续审阅。

## 作者的工作顺序

1. 读实际成稿，列出该镜任一时刻需要可见的人，写入 `visible_character_ids`。不要搬整场人物名单；先画外发声、后来入画的人仍只列可见。
2. 姓名可能只是被提及、出现在屏幕或属于离场的物主。若全镜都不需此人可见，写入 `offscreen_character_ids`；不要为消除告警把真实出场的人改成画外。
3. 在 `cast[].text_names` 明确列出实际正文使用的姓名或称呼。检查器不会自动加入展示用 `name`，也不处理代词。修改称呼后同步声明；不要为检查虚造正文从未使用的别名。
4. 运行同代原检查器，回到告警指向的当前镜头字段与位置。漏声明就据成稿补声明；正文与创作意图冲突就修正文，再复查受影响接缝。歧义由作者根据实际对象解决，不能把所有候选都自动补为可见。
5. 对最终文件再检查，分别说明字面检查范围和实际内容判断。没有名字告警不代表没有未点名人物、虚假画外声明或接续问题。

## v3 声明

`cast[].name` 是非空展示名。必填 `text_names` 是逐字写法的数组，每项至少两个 Unicode 字符；不能重复，不能有首尾空白、ASCII 控制字符或 DEL。内部普通空格保留。不同人物允许同名，命中时报告歧义。大小写、空白和 Unicode 不归一化，需要的不同写法须显式分别列出。

如果名字与常用词撞名，或只有单字名且没有实际使用的更具体称呼，可以写 `text_names: []`，同时提供非空 `text_match_skip_reason`。这是明确退出该人物的字面诊断，会列入警告；理由只供阅读，不解析为机器状态。启用名称匹配时不能同时保留非空退出理由；不能靠退出代替如实填写可见人物。

两种写法只能选一种：非空 `text_names` 配空退出理由，**或者**空 `text_names` 配非空退出理由。同时给非空数组和非空理由会报 `conflicting_text_match_declaration`（结构错误，交付无效）。人物在正文里被逐字提到、但这一镜不出场时，用前一种写法，再把他列进该镜 `offscreen_character_ids`，不要用退出理由回避。

每镜必须提供 `visible_character_ids` 和 `offscreen_character_ids`，即使为空。两表各自不重复、互不重叠。可见角色仍限本场 `character_ids`；画外角色可引用整个 cast。画外以整镜为范围，不是“此刻暂未入画”。这些声明的真假仍需作者/审者判断。

新版只接受 `drama_text_source.v1` + `drama_text_delivery.v3`，返回 `drama_text_check.v3`。旧 v1/v2 不自动升级。作者若迁移旧作品，应对实际成稿明确填写新字段；旧检查器与旧结果仍属于原版本。

## 字面诊断能说明什么

只独立扫描每镜 `start_state`、`action`、`end_state`，不拼接字段，不扫描场次摘要、改编说明或整个原文段落。`source_ids` 指向整段，不能证明段中所有人物都应出现在本镜；SHT-26 的镜头来源短引文检查尚未迁入。

- 精确名字命中后，唯一对应人物未列在可见或画外中，产生 `named_character_unaccounted` 警告。
- 同一写法对应多人，产生 `ambiguous_character_name`，保留全部候选及已声明候选；不任取第一人、不要求所有人可见。
- ASCII 名称首尾及相邻字符若同属 `A-Za-z0-9_-`，粘连的部分不算独立名字，例如 `Tom_1` 不命中 `Tom`。这不是中文分词或完整 Unicode 词边界。
- 边界有效的长名字才抑制其完全包含的短名字；相交但不包含的名字各自保留。同长度不按遍历顺序吞掉。无效长名不得隐藏有效短名。
- 引号、否定句或“某人的包”仍是字面出现；不根据措辞判在场。仅列出人物却未在正文具名，也不能据此判定多列。

警告位置是当前原字段的 Unicode 字符下标：从 0 开始，`end` 不含末端；不是 JSON 文件字节偏移。`text_name_preview` 最多 80 字符，完整长度另记。名称扫描不改变 `structure_valid`、退出码或宿主任务状态；新字段的缺失、类型、引用或互斥错误仍是资料结构错误。

## 预算与回执

原每份 JSON 输入的 4 MiB 上限保持。名字诊断先估算「去重名称总字符数 × 三个镜头字段的总字符数」，上限 2,000,000。使用长度分组和区间前缀最大值，避免逐命中与全部历史区间互比；估算是包内资源预算，不是性能或语义完整性的保证。

`name_diagnostics.status=complete` 只表示对本次启用的显式名称完整扫描。`match_count` 按保留的“镜头、字段、名称、出现区间”计数；`warning_count` 按其中未覆盖或有歧义的出现区间计数。最多输出 100 条名字警告，但继续完整扫描并给出准确 `emitted_warning_count`、`omitted_warning_count` 和 `warnings_truncated`。退出、预算与其他原检查警告不计入名字命中警告总数。

结构无效、无可匹配名称或超预算时，该诊断为 `not_checked` 并附原因；匹配和警告计数为 `null`，不能填零伪装没有漏项。退出角色 ID 单独列出。超预算不更改原摘要、来源、时长检查的真实结果，也不据此判作品失败；可在保持任务范围的前提下分章节/集次交付，不能静默截断正文或名称再声称全部查完。
