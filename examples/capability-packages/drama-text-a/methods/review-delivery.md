# 并行合并与最终交付核对

先读本包 `methods/review.md`。本分表把上游跨文档审阅和修订后复读方法映射到本包；输出是供模型/人使用的反馈，不成为宿主完成条件。

## 合并后回到实际文件

逐项打开子任务实际输出，核对合入目标中的对应位置。计划、阶段结果、合并产物是不同材料：子任务已完成不能证明其全部内容已合入，集数计划也不能改变最终镜头的秒数之和。

对每个采用的上游对象，在现有交接说明中列出来源文件/字段/ID、目标文件/字段/ID、保留/合并/省略/新增及理由。使用原文件的现有编号，不因名称相同就自动当成同一对象。转换后来源集合、角色、道具和动作仍须回读验证；转换说明写得正确也不能替代目标内容。

与其他能力包组合时，保持其独立输入和检查流程，不将本包 JSON 当作对方格式。对照对应场次的对象清单与实际节拍：清单引用有效不证明动作所使用的对象都列全；解释文字、实际字段和原文依据须指向同一转换。

## 对最终内容运行实际检查

按入口通过同代资源引用原样物化并运行 `scripts/check_delivery.py`。若只有自己重写的脚本、手算或部分检查，分别说明其范围，不能称为原包检查已执行。检查返回错误时交作者修订；若暂时无法修好，交付中保留实际缺项。

最终文件改动后旧检查结果不再覆盖当前内容。重新检查只读实际文件，不修改原输入目标来迁就输出；必要内容缺失时补齐实际交付，不能靠重写汇报达到目标数字。

## 拟对外陈述与实际事实逐项对照

交付前按下表从真实结果取值；只需要本次相关行。模板里的占位或计划中的目标不能当作已经实现：

| 拟汇报内容 | 核对来源 | 不一致时如何反馈 |
| --- | --- | --- |
| 交付了哪些文件、镜头和场次 | 当前实际文件；原检查 `metrics.shots/scenes` | 列出实际数量及缺项，不能照抄计划或子任务总结 |
| 总时长及逐场时长 | `shot_seconds`、`scene_seconds`、`scene_shot_seconds` | 列明实际值，不用集数或分组说明改变加总结果 |
| 是否达到目标 | `target_declared/target_seconds/target_delta_seconds` | 目标缺省、目标非法、实际不符分开；差异不为零就保留差异 |
| 来源覆盖 | `covered_passages/omitted_passages` 与已读镜头/原文 | 场次声明覆盖只能这样称呼，不能升级为语义无遗漏 |
| 检查是否通过 | 本次实际 `structure_valid/errors/warnings` | 未执行、错误未解、结构通过分别汇报 |
| 创作审阅及剩余问题 | 本次实际审阅的位置、问题和复核记录 | 自检/独立审阅、抽样/完整、未读/已读如实区分 |

最后回读准备发出的数量、时长、文件清单和“通过”结论；每一项都应能指回表中的实际证据。发现冲突时优先修订实际内容，无法完成则准确报告差异，不把失败隐藏成完成。

## 收回修订结果

审者把问题、应恢复结果和保持项交还作者。作者完成原任务已授权的修改后，审者重新读取受影响文件及相邻接缝，关闭已解决问题或保留仍存在的问题；需要额外未授权素材或选择时再交给用户决定。

可在同一 Markdown 更新本轮复核说明，不建立新的安装/任务/接受账本，不把审阅文字当作自动继续或停止的控制信号。用户只要求审阅时交还问题即可，不擅自编辑目标文件。
